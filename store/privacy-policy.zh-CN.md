## 聚合邮件翻译 for Thunderbird：隐私政策

聚合邮件翻译 for Thunderbird 翻译你在 Thunderbird 中阅读的邮件。它没有自己的服务器：开发者不会从扩展收到任何数据；扩展不收集统计数据、使用数据或崩溃报告，也没有账号。

### 发送什么、发给谁

只有在你翻译邮件，或更改会改变译文的设置（显示方式、语言、服务）时，扩展才发送邮件文字：使用弹出面板中的按钮、快捷键 Alt+A、Alt+S 和 Alt+R，或者你开启的自动翻译。这时扩展把邮件各段落的文字发送给你所选翻译层级的服务：

| 服务 | 文字发往 |
| --- | --- |
| 谷歌翻译 | translate.googleapis.com |
| 微软翻译 | edge.microsoft.com；使用自己的 Azure Translator 密钥时，发往你的 Azure 资源的接口地址（默认 api.cognitive.microsofttranslator.com） |
| DeepLX | 你填写的 DeepLX 服务器地址 |
| DeepL API | api.deepl.com；DeepL 免费计划的密钥发往 api-free.deepl.com；或你填写的地址 |
| 百度翻译 | fanyi-api.baidu.com |
| 有道智云 | openapi.youdao.com |
| 彩云小译 | api.interpreter.caiyunai.com |
| AI 服务（OpenAI、Anthropic、Google Gemini、DeepSeek 等预设） | 设置页显示的该服务接口地址，或你填写的地址 |

开启精翻时，AI 服务还会收到整封邮件的文字（最多 20,000 个字符）作为上下文；邮件较长时，另有一个请求让 AI 服务分析整封邮件（摘要、人名与术语表、语气）。

你请求邮件的摘要与待办时（使用弹出面板的“摘要与待办”按钮、你自己设置的快捷键，或在你开启后出现在已翻译邮件上方的“摘要”按钮），或者“自动摘要”自行打开摘要时（默认关闭，可选“翻译邮件时”或“每封打开的邮件”），摘要所用的 AI 服务会收到整封邮件的文字（最多 20,000 个字符）以及发件人、日期和标题，以便写出谁要做什么，并把“下周三”换算成具体日期。开启精翻时，请求还会附上前文所述分析中的术语表。长邮件需要这项分析、且摘要与第 3 层使用同一个 AI 服务和模型时，一次请求同时完成分析和摘要，邮件连同发件人、日期和标题只发给该服务一次。你不请求摘要、也没有开启“自动摘要”，扩展就不为摘要发送任何内容。

### 图片

邮件中的图片只在你开启精翻之后才会发送，并且只在以下两种情况下发送：

- 图片翻译为“图片下询问”（默认）时，你点击某张图片下方的“翻译图片文字”：只发送这一张；
- 图片翻译为“开启”时，翻译邮件时自动发送：按邮件中的顺序，发送通过下文过滤的前几张图片。

每封邮件最多发送 5 张图片（默认值），按当前显示的这封邮件计数，扩展重新绘制图片区域不会重新计数；用“重新翻译”再次翻译这封邮件时重新计数。

发送的是图片本身：缩小到长边不超过 1568 像素（默认值），并重新编码为 JPEG，文件名和 EXIF 等元数据随之丢弃；同时发送提示词和一行文字，写明它在邮件中的序号和目标语言。开启“使用邮件上下文”时，还附上精翻为这封邮件生成的人名与术语表，但只发给第 3 层的服务，或你同时允许接收邮件文字的服务；此时确认面板会写明这一点。每封邮件发送的图片合计不超过 6 MB（默认值）。图片发往视觉服务：第 3 层的 AI 服务，或你为图片另选的 AI 服务，地址即上表所列的接口地址。

从不发送：Thunderbird 没有显示的远程图片（这封邮件的远程内容被阻止，或图片加载失败）、跟踪像素、超过 4000 万像素的图片、低于设置中尺寸下限的图片（默认短边 100 像素、面积 40,000 像素、文件 4 KB）、动图（除非你选择发送其第一帧），以及不是图片的附件。签名里的图片默认不发送，这项过滤可以在设置中关闭。

远程图片指 Thunderbird 从互联网加载的图片。它只在 Thunderbird 已经显示它时参与翻译，即你允许了这封邮件或其发件人的远程内容。读取它的字节需要“读取远程图片”的权限。你在弹出窗口或设置页点击“允许读取远程图片”时，Thunderbird 以“访问所有网站的数据”的形式询问你；扩展不会自行请求。获得权限后，扩展按邮件中写明的地址再向图片服务器请求一次这张图片，不带 Cookie，不带来源页（Referer）。因此服务器会再收到一次来自你 IP 地址的请求，和 Thunderbird 显示图片时的那次请求相同。在“开启”模式下，这次请求在开始翻译邮件时发出；在“图片下询问”模式下，只在你点击图片下方的“翻译图片文字”时发出。扩展只读取当前显示邮件中图片所写的 http 和 https 地址，每张不超过 15 MB，并且只读取公共互联网上的主机：本机和局域网中的地址（localhost、私有或链路本地 IP 地址、printer.local 这类名称）一律不请求。图片服务器返回重定向时，扩展会跟随；重定向的终点在本机或局域网时，扩展丢弃这次响应，不读取其内容，因此其中任何内容都不会发出。你所在网络的 DNS 把某个域名解析到私有地址时，扩展无法识别，因为扩展不解析域名。同一项权限也覆盖你为某个服务填写的地址，这些地址因此不再单独询问；扩展不把它用于其他用途，设置页会列出撤销这项权限后一并失去访问权限的服务。在设置页或附加组件管理器中撤销这项权限后，扩展不再读取远程图片。

随文字一起发送的还有源语言和目标语言，以及属于该服务的请求设置：对 AI 服务而言是模型、提示词、温度和思考模式开关；对百度和有道而言是你的应用 ID 和用密钥算出的签名，密钥本身不发送；对 DeepL 而言是正式程度和英语、葡萄牙语的变体。你保存的 API 密钥只发给它所属的服务。邮件的收件人和附件从不发送；发件人、日期和标题只随摘要发送，见上文。各服务按照自己的隐私政策处理收到的文字。

### 扩展在 Thunderbird 中读取的内容

为了翻译图片，扩展用 `messages.getAttachmentFile()` 读取当前显示邮件的图片部件：正文中的图片和图片附件里通过上述过滤的那些，不读取其他附件。翻译邮件开始时，扩展在你的电脑上读取它们，用来查找已有的结果和执行过滤，并且只读取翻译开始时显示的那封邮件、只在它仍然显示时读取；图片只按上文所述离开你的电脑。对远程图片，扩展还在你的电脑上用 `messages.getFull()` 读取当前显示邮件的 HTML，确认图片地址确实出自这封邮件。生成摘要时，扩展读取当前显示邮件的发件人、日期和标题（权限“读取你的电子邮件”，`messagesRead`，读取上述图片部件和邮件 HTML 也用这项权限）。扩展不读取账户设置，也不保存上述内容；离开你电脑的只有生成摘要的邮件的发件人、日期和标题，见上文。

### 你的同意

邮件文字第一次发送给某个在线服务之前，邮件上方的面板会写明服务名称、请求发往的地址以及发送的内容。点击“允许并翻译”之前，扩展不向这个服务发送任何内容。摘要沿用同一项同意：摘要所用的 AI 服务第一次收到邮件之前，会出现同样的面板；“自动摘要”自行打开的摘要也是如此。每个服务及其地址只询问一次，你的选择连同这个地址记录在扩展的设置中；你更改服务的地址后会再次询问。设置页列出你已允许的服务及其地址，“撤销”收回同意：该服务仍在队列中等待的请求不再发送，之后面板会再次询问。

图片另有单独的同意，与文字分开：第一张图片发给某个服务之前，图片下方的面板写明服务名称和地址，说明图片会缩小并重新编码、不含文件名和元数据；对 Anthropic、Google Gemini 和 OpenAI，还写明该服务对数据用途的说明。点击“允许并翻译图片”之前不发送任何内容；你撤销同意、关闭图片翻译或离开这封邮件后，仍在队列中等待的图片不再发送。开启“每封邮件确认一次”时，每封邮件都会询问，选择不记录。设置页用单独一栏列出已允许接收图片的服务，每个都可以“撤销”。

设置页或设置向导把 Google 翻译（免费）或 Microsoft Translator（免费）显示为已添加的服务时，会向它发送“测试连接”所用的固定测试句，每个页面一次，用来告诉你当前网络能否连接这个服务（例如 Google 翻译在中国大陆不可用）。这次请求不含任何邮件文字；和任何请求一样，服务能看到你的 IP 地址。

扩展连接的地址有三类：清单（manifest）中列出的地址；你设置的服务的地址；你允许读取远程图片之后，Thunderbird 所显示远程图片的服务器，见上文“图片”一节。清单在安装时直接授予的只有 Google 和 Microsoft 的免费线路，以及下文离线数据的下载地址。需要你的密钥的服务（使用 Azure 密钥的 Microsoft、DeepL、百度、有道、彩云和各 AI 服务）的地址，以及你自己填写的地址（例如本机的 Ollama 服务器或你的 DeepLX 服务器），都需要经过 Thunderbird 自己的授权提示。扩展只在你为该服务点击“授权访问”或“测试连接”，或在设置向导中设置好它之后点击“下一步”时显示这个提示。从 3.0 或更早版本更新时，这些服务已有的访问权限保持不变。

### 不发送什么

离线词典和离线 Bergamot 模型在你的电脑上翻译，不发送任何内容。只使用这两项时，邮件文字不会离开 Thunderbird，扩展也不会显示同意面板。

### 不含你数据的下载

有两份列表和离线数据来自网络，其中不含任何邮件文字：

- 词典包列表和词典包本身，来自本项目的 GitHub Releases（github.com，下载会重定向到 release-assets.githubusercontent.com）；
- Bergamot 翻译模型列表和模型文件，来自 Mozilla（firefox.settings.services.mozilla.com 和 firefox-settings-attachments.cdn.mozilla.net）。

设置页或新手引导显示这两份列表时，扩展会读取它们；某个层级选用了词典或 Bergamot 时，Thunderbird 启动、设置改变和弹出面板打开时也会读取。词典包和模型只在你点击下载按钮时下载。与任何下载一样，这些请求会让服务器看到你的 IP 地址和所请求的文件。

### 在你电脑上保存什么

- 设置，包括 API 密钥，保存在 Thunderbird 配置文件的扩展存储（storage.local）中。与其他附加组件的数据一样，这些内容没有加密。
- 翻译、摘要与图片文字的缓存，保存在同一存储中，默认最多 5,000 条。缓存保存译文、摘要和图片的回答，原文和原图只以哈希值保存。设置页可以关闭和清空缓存。
- 你下载的词典包和 Bergamot 模型，保存在扩展的 IndexedDB 存储中。

卸载扩展会删除以上全部内容。
