# Thunderbird Translate

[English](../README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Español](README.es.md) | [Português (Brasil)](README.pt-BR.md) | Русский | [Türkçe](README.tr.md) | [Tiếng Việt](README.vi.md)

Thunderbird Translate — расширение для Thunderbird, которое переводит текст открытого письма прямо в области просмотра сообщения. Перевод выводится под каждым абзацем оригинала (двуязычный режим) или заменяет его (режим «Только перевод»). После отключения перевода письмо возвращается в точности к исходному виду. По умолчанию используется бесплатный Google Translate, который работает сразу после установки. Кроме него можно подключить 22 ИИ-провайдера, в том числе OpenAI, Claude, Gemini, DeepSeek и Qwen.

Этот документ рассчитан на читателей, которые раньше не пользовались расширениями Thunderbird. Порядок изложения: установка, использование, настройка, устройство.

## Возможности

- Перевод текста письма: расширение находит в теле письма содержимое уровня абзаца — абзацы, элементы списков, ячейки таблиц, заголовки, цитаты, блоки div только с текстом, а в письмах в простом текстовом формате — абзацы, разделённые пустыми строками. Код, абзацы, уже написанные на языке перевода, числа, голые ссылки и пробельные символы пропускаются.
- Два режима отображения: двуязычный режим вставляет под оригиналом блок перевода со светлой линией слева, который хорошо читается и в тёмных темах. Режим «Только перевод» заменяет оригинал переводом; оригинал хранится в памяти и возвращается на место при отключении перевода.
- Обновление на лету: если во время показа перевода сменить режим отображения или язык перевода, страница перерисовывается без повторного открытия письма. Смена режима отображения перерисовывает страницу из уже полученных переводов и не отправляет новых запросов.
- Точки входа: кнопка «Перевести сообщение» на панели инструментов заголовка сообщения со всплывающим окном и сочетания клавиш Alt+A (перевести / показать оригинал) и Alt+S (переключить двуязычный режим / только перевод).
- Необязательный автоматический перевод: письма, написанные не на языке перевода, переводятся сразу при открытии.
- Пакетная обработка запросов: фоновый скрипт собирает абзацы в течение 50 мс и объединяет их в один запрос; есть ограничение числа параллельных запросов, повторные попытки с экспоненциальной задержкой и локальный кэш.
- Службы: 3 бесплатные или размещаемые самостоятельно службы перевода и 22 готовые конфигурации ИИ-провайдеров, одна из которых — «Свой OpenAI-совместимый API». В списках служб показываются только те службы, которые вы добавили.
- Параллельный перевод (службы ИИ): бесплатный переводчик отвечает первым, и его результат показывается как черновик перевода, пока его не заменит перевод ИИ.
- Точный перевод (службы ИИ): весь текст письма служит контекстом каждого запроса, поэтому имена, термины и формы обращения остаются единообразными во всех абзацах.
- Переключатель режима рассуждений для каждого ИИ-провайдера, по умолчанию выключенный.
- Интерфейс на 12 языках. По умолчанию язык интерфейса совпадает с языком Thunderbird; его можно выбрать на странице настроек.

## Установка

### Из раздела Releases

1. Скачайте последний файл `thunderbird-translate-<version>.xpi` со страницы Releases этого репозитория.
2. В Thunderbird откройте Инструменты → Дополнения и темы (этот пункт есть и в меню ≡ в правом верхнем углу).
3. Нажмите на значок шестерёнки над списком расширений, выберите «Установить дополнение из файла…», укажите скачанный файл xpi и подтвердите установку.

Требуется Thunderbird 128 или новее.

### Сборка из исходного кода

Требуется Node.js 22 или новее (разработка ведётся на Node 24 и npm 11).

```bash
npm ci
npm test
npm run build
```

`npm run build` собирает с помощью esbuild фоновый скрипт, скрипт содержимого, всплывающее окно и страницу настроек в каталог `dist/`, генерирует `dist/_locales/<language>/messages.json` из файлов в `locales/` и упаковывает `dist/` в `web-ext-artifacts/thunderbird-translate-<version>.xpi`. Упаковка выполняется библиотекой fflate на чистом JavaScript, системная команда zip не нужна.

Во время разработки расширение можно загрузить без упаковки: в Thunderbird откройте Инструменты → Инструменты разработчика → Отладка дополнений, нажмите «Загрузить временное дополнение…» и выберите `dist/manifest.json`.

## Использование

Откройте письмо. На панели инструментов заголовка сообщения появится кнопка «Перевести сообщение». Нажатие на неё открывает всплывающее окно со следующими элементами:

- «Перевести это сообщение»: запускает перевод. Пока перевод выполняется или показан, кнопка называется «Показать оригинал» и по нажатию возвращает оригинал.
- «Отображение»: переключает двуязычный режим и режим «Только перевод»; изменение сразу применяется к текущему письму.
- «Язык перевода»: после смены языка переводимое письмо переводится заново на новый язык.
- «Служба перевода»: выбирает используемую службу. В списке только добавленные службы. Пункт «+ Добавить службу перевода» под списком открывает страницу настроек на разделе служб перевода.
- «Параллельный перевод» и «Точный перевод»: показываются, пока текущая служба — служба ИИ; включают и выключают два режима перевода ИИ.
- «Автоматически переводить сообщения, написанные не на языке перевода»: если флажок установлен, письмо, текст которого написан не на языке перевода, переводится сразу при открытии.

Всплывающее окно показывает ход перевода, например «Переведено 8 из 12». При параллельном переводе абзацы, у которых пока показан быстрый черновой перевод, считаются отдельно, например «Переведено 7 из 9 (черновых: 2)». Если абзац перевести не удалось, после него появляется красная надпись «Ошибка перевода, нажмите для повтора»; при наведении указателя видна ошибка, а нажатие повторяет перевод этого абзаца.

Alt+A переводит текущее письмо или возвращает оригинал; Alt+S переключает двуязычный режим и режим «Только перевод». Оба сочетания можно изменить в пункте «Управление горячими клавишами расширений» меню шестерёнки в «Управлении дополнениями».

В режиме «Только перевод» при наведении указателя на перевод во всплывающей подсказке показывается исходный текст.

## Настройки

Страница настроек открывается кнопкой «Настройки» этого расширения в «Управлении дополнениями». Настройки сохраняются автоматически; после записи в правом верхнем углу появляется надпись «Сохранено».

| Раздел | Содержимое |
| --- | --- |
| Общие | Язык интерфейса, язык перевода, режим отображения по умолчанию, текущая служба, автоматический перевод |
| Службы перевода | Службы в двух группах, «Добавленные» и «Можно добавить»; конечная точка, ключ API, модель, температура и режим рассуждений для каждой службы; кнопки «Проверить соединение», «Добавить», «Использовать эту службу» и «Удалить» |
| Режимы перевода ИИ | Параллельный перевод с выбором быстрой службы; точный перевод |
| Системный промпт | Собственный системный промпт для служб ИИ; `{{to}}` заменяется названием языка перевода; пустое поле означает встроенный промпт |
| Пакетная обработка запросов | Окно сбора, максимальное число символов и абзацев в запросе, число параллельных запросов, повторные попытки, объединение запросов к ИИ |
| Стиль перевода | Линия слева, пунктирная линия слева, выделение фоном или без оформления; акцентный цвет, непрозрачность текста, относительный размер шрифта; предварительный просмотр |
| Кэш | Включение и отключение кэша, максимальное число абзацев в кэше, текущее число записей, очистка кэша |

«Проверить соединение» отправляет одно тестовое предложение с теми значениями, которые сейчас введены в поля. При успехе показывается перевод, при неудаче — ошибка, которую вернула служба, например о недействительном ключе или неизвестном имени модели.

## Добавление и удаление служб

Боковой список раздела служб перевода состоит из двух групп. В группе «Добавленные» находятся службы, которые показываются в списках служб всплывающего окна и страницы настроек; в группе «Можно добавить» — все остальные. При выборе службы показываются её настройки и кнопки:

- У службы, которая не добавлена, есть кнопка «Добавить». Служба добавляется и при вводе ключа API (для DeepLX — конечной точки).
- У добавленной службы есть кнопки «Использовать эту службу» и «Удалить». Удаление убирает службу из списков, но сохраняет её настройки, поэтому при повторном добавлении ключ и модель восстанавливаются.
- Текущую службу удалить нельзя; нельзя удалить и быструю службу параллельного перевода, пока этот режим включён. Кнопка «Удалить» тогда неактивна, а строка под ней объясняет причину.

Новая установка начинается с добавленных Google Translate и Microsoft Translator. При загрузке настроек версии 1.1 и ранее служба считается добавленной в таких случаях:

| Служба | Считается добавленной, если |
| --- | --- |
| Google Translate, Microsoft Translator | всегда |
| DeepLX | заполнена конечная точка |
| Службы ИИ, которым нужен ключ | сохранён ключ API |
| Ollama, LM Studio, свой OpenAI-совместимый API | изменены конечная точка, модель или температура |
| текущая служба | всегда |

## Режимы перевода ИИ

Оба режима действуют, только пока текущая служба — служба ИИ. Их можно включить в разделе «Режимы перевода ИИ» страницы настроек или во всплывающем окне.

### Параллельный перевод

Каждый абзац уходит и службе ИИ, и быстрой службе (по умолчанию Google Translate; среди добавленных служб можно выбрать Microsoft Translator или DeepLX). Оба запроса проходят через обычную пакетную обработку и кэш. Результат зависит от того, какой ответ придёт первым:

| Случай | Что показывает письмо |
| --- | --- |
| Первой отвечает быстрая служба | её перевод курсивом с пометкой «Черновик»; при наведении указателя подсказка сообщает, что ИИ готовит перевод. Когда приходит перевод ИИ, он заменяет черновик. |
| Первой отвечает служба ИИ | перевод ИИ; результат быстрой службы отбрасывается |
| Запрос к ИИ завершился ошибкой | остаётся быстрый перевод с пометкой «Ошибка перевода ИИ»; при наведении указателя видна причина, а нажатие повторяет перевод абзаца |
| Перевод ИИ уже есть в кэше | перевод ИИ из кэша; к быстрой службе запрос не отправляется |

Смена режима отображения сохраняет пометки черновика и ошибки, а «Показать оригинал» убирает их вместе с переводами. Параллельный перевод не расходует дополнительных токенов ИИ, но вдвое увеличивает число запросов к быстрой службе.

### Точный перевод

Точный перевод передаёт письмо как контекст в каждом запросе к ИИ. При запуске перевода скрипт содержимого склеивает найденные абзацы в простой текст письма (он обрезается после 20 000 символов с пометкой о том, что текст продолжается) и один раз регистрирует его в фоновом скрипте. Письмо определяется по хешу его полного текста; обрезка относится только к тексту, отправляемому как контекст.

Порядок работы зависит от объёма абзацев, которые нужно перевести:

1. Если они помещаются в один запрос (в пределах «Макс. символов в запросе» и «Макс. абзацев в запросе»), все абзацы переводит один запрос; он сам несёт письмо целиком.
2. Иначе сначала один дополнительный запрос анализирует письмо целиком и возвращает краткое содержание из двух-трёх предложений, глоссарий имён, названий продуктов и других имён собственных с переводом, который нужно использовать, а также тон и форму обращения. Если этот ответ не удаётся разобрать, перевод продолжается без него.
3. Затем каждый запрос начинается с одного и того же префикса: системный промпт, анализ и, для писем примерно до 8000 символов, полный текст. После префикса идут абзацы пакета, каждый с предыдущим и следующим абзацем в качестве справки, которая не переводится.

Префикс совпадает символ в символ во всех запросах одного письма, поэтому провайдеры, которые кэшируют повторяющиеся префиксы промптов, могут отдавать его из своего кэша. Для Anthropic префикс помечается `cacheControl: { type: "ephemeral" }`. Анализ кэшируется так же, как переводы; ключ состоит из провайдера, модели, языка перевода и хеша текста письма, а пакеты одного письма ждут один и тот же запрос анализа.

Переводы в точном режиме кэшируются по ключу, в который входит хеш письма, и пакеты никогда не смешивают абзацы разных писем. Поэтому то же предложение в другом письме переводится заново, уже с тем письмом в качестве контекста. Запрос анализа и более длинные промпты делают точный перевод дороже обычного.

## Язык интерфейса

Параметр «Язык интерфейса» в разделе «Общие» принимает значения двух видов:

- «Как в Thunderbird» (по умолчанию): расширение использует поддерживаемый язык, ближайший к языку интерфейса самого Thunderbird. В названии варианта указан выбранный сейчас язык, например «Как в Thunderbird (Deutsch)».
- Один из 12 поддерживаемых языков: расширение использует этот язык независимо от языка Thunderbird.

Выбор действует на всплывающее окно, страницу настроек, надписи внутри писем («Перевод…», «Ошибка перевода, нажмите для повтора»), сообщения об ошибках, результат проверки соединения и подсказку кнопки на панели инструментов. Открытая страница настроек или всплывающее окно сразу меняют язык текста. Надписи внутри уже переведённого письма меняются при следующей отрисовке.

Несколько текстов Thunderbird считывает сам из манифеста расширения, и они всегда следуют языку интерфейса Thunderbird: название и описание расширения в «Управлении дополнениями» и описания сочетаний клавиш в разделе «Управление горячими клавишами расширений». Страница настроек сообщает об этом под параметром.

Вариант «Как в Thunderbird» сопоставляет язык Thunderbird так:

| Язык Thunderbird | Используемый язык интерфейса |
| --- | --- |
| `zh-TW`, `zh-HK`, `zh-MO`, `zh-Hant` | Китайский традиционный |
| остальные `zh-*` | Китайский упрощённый |
| `pt-*` | Португальский (Бразилия) |
| `en-*`, `ja`, `ko`, `fr-*`, `de-*`, `es-*`, `ru`, `tr`, `vi` | язык с тем же основным подтегом |
| любой другой язык | Английский |

В списке языков перевода у каждого языка сначала указано название на языке интерфейса, затем самоназвание языка, например «японский (日本語)». В промптах для служб ИИ всегда используется английское название языка, потому что модели надёжнее всего выполняют инструкции на английском.

При первой установке язык перевода задаётся по языку интерфейса: в японском Thunderbird исходный язык перевода — японский, в английском — английский. Уже заданный язык перевода никогда не перезаписывается.

## Настройка провайдеров

### Бесплатные и самостоятельно размещаемые службы

| Служба | Настройка | Примечания |
| --- | --- | --- |
| Google Translate (бесплатно, по умолчанию) | Не требуется | Обращается к конечной точке `client=gtx` на `translate.googleapis.com`; один POST-запрос несёт несколько параметров `q`, поэтому несколько абзацев идут одним запросом |
| Microsoft Translator (бесплатно) | Не требуется | Сначала пытается получить токен у `edge.microsoft.com/translate/auth` и обратиться к `api-edge.cognitive.microsofttranslator.com`; если Microsoft отключила конечную точку выдачи токенов, переключается на `edge.microsoft.com/translate/translatetext`. ### Режим рассуждений

У каждого ИИ-провайдера есть переключатель «Режим рассуждений», по умолчанию выключенный. Для перевода модели не нужно сначала рассуждать, а рассуждения замедляют запросы и делают их дороже. ## Как устроена пакетная обработка

В письме обычно от десяти до нескольких десятков абзацев. Если отправлять по одному запросу на абзац, каждый абзац несёт свою копию системного промпта и инструкций и расходует один запрос из лимита частоты запросов. Пакетная обработка объединяет абзацы, поступившие с небольшим интервалом, в один запрос, поэтому обе эти затраты приходятся на пакет, а не на абзац.

### Порядок работы

1. Скрипт содержимого передаёт фоновому скрипту каждый абзац, который нужно перевести.
2. Фоновый скрипт сначала ищет перевод в кэше и при попадании сразу возвращает ответ. Ключ кэша состоит из провайдера, модели, языка перевода, сигнатуры системного промпта, в точном режиме — хеша письма, и хеша текста абзаца. Если тот же текст уже переводится, последующие запросы получают тот же результат.
3. Абзацы, которых нет в кэше, попадают в очередь пакетов и группируются по сочетанию провайдер + модель + конечная точка + язык перевода, для служб ИИ ещё и по системному промпту, для Microsoft Translator ещё и по режиму (бесплатный или со своим ключом), а в точном режиме ещё и по письму. Абзацы одной группы накапливаются в течение 50 мс. Группа отправляется, когда окно сбора истекает, когда достигнут лимит абзацев или когда следующий абзац превысил бы лимит символов. Отдельный абзац длиннее лимита символов образует собственный пакет.
4. Очередь запросов выполняет каждый пакет. Она ограничивает число параллельных запросов и повторяет запросы при ошибках 408, 429, 5xx и сетевых ошибках с экспоненциальной задержкой; если сервер прислал `Retry-After`, она ждёт указанное время, но не дольше 30 секунд. Ошибки вроде 401 и 400 сообщаются без повторных попыток.
5. Результаты попадают в кэш в памяти и через 1 секунду записываются в `storage.local` одной операцией записи. Кэш вытесняет записи, которые дольше всего не использовались (LRU).

### Как каждая служба объединяет абзацы

- Google: один POST-запрос с несколькими параметрами `q`; возвращаемый массив поэлементно соответствует входным данным.
- Microsoft: тело запроса само является массивом.
- DeepLX: конечная точка принимает один абзац на запрос, поэтому абзацы пакета запрашиваются параллельно.
- ИИ-провайдеры: абзацы нумеруются и помещаются в одно сообщение, а модель просят вернуть JSON-массив той же длины. Парсер пробует по порядку: JSON-массив (возможно, внутри блока кода или в окружении пояснений; неэкранированные переводы строк внутри строк и завершающие запятые исправляются), пронумерованные блоки `<seg>`, пронумерованные строки и разделитель `%%`. Если ни один способ не сработал или число элементов не совпало, этот пакет отправляется заново по одному абзацу на запрос, и пользователь видит тот же результат. Ошибки, не связанные с разбором ответа, например ошибки аутентификации, не запускают этот запасной путь, поэтому одна и та же ошибка не повторяется N раз.

### Оценка затрат

Пусть системный промпт и инструкции занимают $s$ токенов, каждый абзац в среднем $t$ токенов, всего $N$ абзацев, размер пакета $B$, а нумерация и кавычки JSON добавляют $c$ токенов на абзац.

При одном запросе на абзац общее число входных токенов равно

$$
I_{\text{по одному}} = N(s + t).
$$

При пакетной обработке запросов $\lceil N/B \rceil$, и общее число входных токенов равно

$$
I_{\text{пакет}} = \left\lceil \frac{N}{B} \right\rceil s + N(t + c).
$$

Разность равна

$$
I_{\text{по одному}} - I_{\text{пакет}} = \left(N - \left\lceil \frac{N}{B} \right\rceil\right) s - Nc.
$$

Пока $s$ заметно больше $c$, более крупные пакеты дают большую экономию. При $s = 150$, $t = 60$, $c = 10$, $N = 20$ и $B = 30$:

$$
I_{\text{по одному}} = 20 \times 210 = 4200, \qquad I_{\text{пакет}} = 150 + 20 \times 70 = 1550.
$$

Число входных токенов снижается примерно на 63 %, а число запросов — с 20 до 1. Число выходных токенов в обоих случаях примерно одинаково, поскольку длина перевода не меняется. Сокращение числа запросов важно и для бесплатных конечных точек: Google и Microsoft ограничивают свои бесплатные конечные точки по частоте запросов, а письмо из 20 абзацев обходится одним запросом.

## Конфиденциальность

- Ключи API хранятся только в `storage.local` текущего профиля Thunderbird и отправляются только в запросах к конечной точке соответствующего провайдера.
- Скрипт содержимого работает внутри страницы сообщения; настройки, которые он получает от фонового скрипта, никогда не содержат ключей.
- Текст письма отправляется только текущей службе перевода и, пока включён параллельный перевод, выбранной быстрой службе. Расширение не собирает статистику и не обращается ни к каким сетевым адресам, кроме этих служб.
- Кэш переводов хранится локально; его можно отключить или очистить на странице настроек.
- Текст письма покидает ваш компьютер и уходит выбранной службе перевода. Для конфиденциальной переписки локальные модели, например Ollama или LM Studio, оставляют все запросы на вашем собственном компьютере.

## Известные ограничения

- Перевод — это простой текст. Ссылки, полужирный шрифт и другое встроенное форматирование оригинала в переводе не сохраняются. В двуязычном режиме оригинал остаётся полностью доступным; в режиме «Только перевод» можно навести указатель, чтобы увидеть оригинал, или вернуться в двуязычный режим.
- Бесплатные конечные точки Google и Microsoft не документированы и могут измениться или ограничить частоту запросов. Microsoft отключила конечную точку выдачи токенов `edge.microsoft.com/translate/auth` в июле 2026 года (она возвращает 404). Расширение по-прежнему пробует эту конечную точку при первом запросе, после неудачи переходит на прямую конечную точку и в течение часа больше не обращается к конечной точке выдачи токенов.
- Чтобы определить, написан ли абзац уже на языке перевода, китайский, японский, корейский и языки с похожей письменностью распознаются по классу символов, а для языков на латинице и кириллице сначала используется `i18n.detectLanguage` из API расширений. Если этот API недоступен или его результат ненадёжен, надёжно распознаётся только английский; абзацы на других языках с латиницей отправляются на перевод как обычно.
- Скрипт содержимого регистрируется через `messageDisplayScripts` и действует только в письмах, открытых после регистрации. При запуске расширение пытается внедрить его в уже открытые письма; если это не удалось, достаточно выбрать письмо заново.
- Сообщения об ошибках, которые формирует само расширение, переведены. Тексты ошибок, которые возвращает служба перевода или AI SDK (например, тело ответа HTTP 401), показываются в полученном виде, обычно на английском.
- Название расширения, его описание в «Управлении дополнениями» и описания сочетаний клавиш следуют языку интерфейса Thunderbird, а не параметру «Язык интерфейса».
- Точный перевод определяет письмо по хешу текста его тела, потому что скрипт содержимого не имеет доступа к ID письма. Две копии одного текста используют общие переводы и общий анализ.
- Кэширование промптов зависит от провайдера. Anthropic кэширует только префиксы длиннее минимальной длины, которая зависит от модели; более короткие префиксы отправляются и оплачиваются как обычно.
- Переключатель рассуждений работает по совпадению имён моделей. Новая модель, имя которой не подходит ни под один шаблон, не получает параметра рассуждений, пока не будет расширена таблица в `src/background/providers/thinking.ts`.
- Параллельный перевод вдвое увеличивает число запросов к быстрой службе, а они учитываются в лимитах частоты бесплатных конечных точек Google и Microsoft.

`npm run build:debug` создаёт отладочный xpi, который начинает перевод сразу при открытии письма и пишет ход работы в консоль; он нужен для проверки всего процесса в настоящем Thunderbird.

## Перевод интерфейса

Тексты интерфейса находятся в `locales/<language>.json`: для каждого языка один плоский объект «ключ → текст». Эталоном служит `locales/en.json`: во всех остальных файлах ровно те же ключи. `$1`–`$9` — подстановки; в каждом переводе они должны присутствовать с теми же номерами, что и в английском тексте. `{{apiKey}}` и `{{to}}` — буквальные токены, они остаются без изменений. Названия продуктов, такие как Google Translate, OpenAI или DeepLX, не переводятся.

`npm run build` преобразует эти файлы в `dist/_locales/<language>/messages.json` — формат, который читает Thunderbird. Собственная среда i18n расширения загружает те же файлы во время работы, поэтому язык интерфейса меняется без перезапуска Thunderbird. Для отсутствующих ключей используется английский текст.

Чтобы добавить язык, создайте `locales/<code>.json` со всеми ключами, добавьте код вместе с самоназванием языка в `SUPPORTED_LOCALES` в `src/shared/locales.ts` и запустите `npm run locales:check` и `npm test`.
