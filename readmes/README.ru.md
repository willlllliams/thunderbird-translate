# Thunderbird Translate

[English](../README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Español](README.es.md) | [Português (Brasil)](README.pt-BR.md) | Русский | [Türkçe](README.tr.md) | [Tiếng Việt](README.vi.md)

Thunderbird Translate — расширение для Thunderbird, которое переводит текст открытого письма прямо в области просмотра сообщения. Перевод выводится под каждым абзацем оригинала (двуязычный режим) или заменяет его (режим «Только перевод»). После отключения перевода письмо возвращается в точности к исходному виду. Перевод выполняется одновременно на трёх уровнях: офлайн-словарь, машинный переводчик (Google Translate, Microsoft Translator, DeepLX или офлайн-модели Bergamot) и служба ИИ (22 провайдера, в том числе OpenAI, Claude, Gemini, DeepSeek и Qwen). Самый быстрый результат появляется первым, а результат самого высокого уровня затем заменяет его. По умолчанию используется бесплатный Google Translate, который работает сразу после установки.

Этот документ рассчитан на читателей, которые раньше не пользовались расширениями Thunderbird. Порядок изложения: установка, использование, настройка, устройство.

## Возможности

- Перевод текста письма: расширение находит в теле письма содержимое уровня абзаца — абзацы, элементы списков, ячейки таблиц, заголовки, цитаты, блоки div только с текстом, а в письмах в простом текстовом формате — абзацы, разделённые пустыми строками. Код, абзацы, уже написанные на языке перевода, числа, голые ссылки и пробельные символы пропускаются.
- Два режима отображения: двуязычный режим вставляет под оригиналом блок перевода со светлой линией слева, который хорошо читается и в тёмных темах. Режим «Только перевод» заменяет оригинал переводом; оригинал хранится в памяти и возвращается на место при отключении перевода.
- Обновление на лету: если во время показа перевода сменить режим отображения или язык перевода, страница перерисовывается без повторного открытия письма. Смена режима отображения перерисовывает уже полученные переводы словаря и машинного перевода; уровню ИИ запрос отправляется снова, с промптом нового режима, а кэш отвечает, если такой перевод у него уже есть.
- Точки входа: кнопка «Перевести сообщение» на панели инструментов заголовка сообщения со всплывающим окном и сочетания клавиш Alt+A (перевести / показать оригинал) и Alt+S (переключить двуязычный режим / только перевод).
- Перевод при открытии письма (по желанию): письмо, написанное не на языке перевода, переводится сразу, без нажатия кнопки.
- Пакетная обработка запросов: фоновый скрипт собирает абзацы в течение 50 мс и объединяет их в один запрос; есть ограничение числа параллельных запросов, повторные попытки с экспоненциальной задержкой и локальный кэш.
- Три уровня перевода: словарь, машинный перевод и ИИ. Для каждого уровня выбирается своя служба или «Не используется»; каждый абзац отправляется сразу на все используемые уровни. Перевод нижнего уровня показывается как предварительный, пока его не заменит самый высокий уровень, и остаётся на месте, если самый высокий уровень завершился ошибкой.
- Службы: офлайн-словарь, 4 машинных переводчика (Google Translate, Microsoft Translator, DeepLX, офлайн-модели Bergamot) и 22 готовые конфигурации ИИ-провайдеров, одна из которых — «Свой OpenAI-совместимый API». В списках уровней показываются только те службы, которые вы добавили.
- Исходный язык: автоматическое определение или заданный язык; он передаётся каждой службе.
- Три промпта для уровня ИИ: для двуязычного отображения, для отображения только перевода и для точного перевода.
- Шаблоны промптов: готовые правила для регионального варианта языка перевода, для трудных слов с оригиналом в скобках, для коротких пояснений к трудным словам и для четырёх стилей. Шаблон добавляется в любой из трёх промптов.
- Мастер настройки: открывается после установки и по шагам настраивает языки, режим отображения, уровни перевода, офлайн-загрузки, службы и промпты. В конце он выполняет пробный перевод примера письма.
- Точный перевод (уровень ИИ): весь текст письма служит контекстом каждого запроса, поэтому имена, термины и формы обращения остаются единообразными во всех абзацах.
- Переключатель режима рассуждений для каждого ИИ-провайдера, по умолчанию выключенный.
- Интерфейс на 12 языках. По умолчанию язык интерфейса совпадает с языком Thunderbird; его можно выбрать на странице настроек.

## Установка

### Из раздела Releases

1. Скачайте последний файл `thunderbird-translate-<version>.xpi` со страницы Releases этого репозитория.
2. В Thunderbird откройте Инструменты → Дополнения и темы (этот пункт есть и в меню ≡ в правом верхнем углу).
3. Нажмите на значок шестерёнки над списком расширений, выберите «Установить дополнение из файла…», укажите скачанный файл xpi и подтвердите установку.

Требуется Thunderbird 128 или новее.

### Сборка из исходного кода

Требуется Node.js 22 или новее (разработка ведётся на Node 24 и npm 11).

```bash
npm ci
npm test
npm run build
```

`npm run build` собирает с помощью esbuild фоновый скрипт, скрипт содержимого, всплывающее окно, страницу настроек, мастер настройки и воркер Bergamot в каталог `dist/`, генерирует `dist/_locales/<language>/messages.json` из файлов в `locales/` и упаковывает `dist/` в `web-ext-artifacts/thunderbird-translate-<version>.xpi`. Упаковка выполняется библиотекой fflate на чистом JavaScript, системная команда zip не нужна. Фоновый скрипт — ES-модуль: AI SDK вынесен в отдельный чанк в `dist/chunks/`, который загружается, когда начинает использоваться уровень ИИ, поэтому Thunderbird запускает расширение без него. Первая сборка скачивает с сервера Mozilla зафиксированную версию движка Bergamot (wasm) в `.cache/`, см. [docs/bergamot.md](../docs/bergamot.md).

Во время разработки расширение можно загрузить без упаковки: в Thunderbird откройте Инструменты → Инструменты разработчика → Отладка дополнений, нажмите «Загрузить временное дополнение…» и выберите `dist/manifest.json`.

## Мастер настройки

После новой установки Thunderbird открывает мастер настройки во вкладке. Обновления расширения или Thunderbird его не открывают. Позже мастер открывается ссылкой «Мастер настройки» во всплывающем окне и кнопкой «Мастер настройки» вверху страницы настроек.

Каждый шаг предлагает одно решение и сразу сохраняет выбор. Кнопки «Назад», «Далее» и «Пропустить шаг» переходят между шагами. Нумерованный список под индикатором хода позволяет перейти к любому шагу. Кнопка «Выйти из мастера» в любой момент закрывает вкладку. При следующем открытии мастер продолжает с того шага, на котором его оставили; после нажатия «Завершить» он начинается с первого шага.

| Шаг | Содержимое | Когда показывается |
| --- | --- | --- |
| 1 Языки | язык интерфейса, исходный язык (по умолчанию «Определять автоматически»), язык перевода | всегда |
| 2 Отображение | двуязычный режим или «Только перевод», с предпросмотром примера письма в текущем стиле перевода | всегда |
| 3 Уровни перевода | скорость, качество, конфиденциальность и стоимость уровней словаря, машинного перевода и ИИ; служба каждого уровня или «Не используется»; хотя бы у одного уровня должна быть служба | всегда |
| 4 Офлайн-перевод | пакеты словарей и направления Bergamot, которые нужны языкам из шага 1, с размером, лицензией и указанием авторства; отмеченные пункты скачиваются кнопкой «Загрузить выбранное» с отображением хода загрузки | уровень словаря используется или уровень машинного перевода использует Bergamot |
| 5 Онлайн-машинный перевод | поля машинного переводчика: для Google заполнять ничего не нужно; для Microsoft есть варианты «Стандартный интерфейс (бесплатно)» и «Использовать мой ключ (Azure Translator)»; для DeepLX нужны конечная точка и токен; кнопка «Проверить соединение» | уровень машинного перевода использует Google, Microsoft или DeepLX |
| 6 Перевод ИИ | провайдер ИИ, его ключ API, модель, температура и режим рассуждений, кнопка «Проверить соединение» и переключатель «Точный перевод»; примечание о том, что режим рассуждений и точный перевод делают перевод медленнее и дороже | уровень ИИ используется |
| 7 Промпты | три промпта и библиотека шаблонов (см. «Шаблоны промптов») | уровень ИИ используется |
| 8 Готово | способы перевода (кнопка на панели инструментов, Alt+A, Alt+S), переключатель «Автоматически переводить сообщения, написанные не на языке перевода» и кнопка «Перевести пример сообщения» | всегда |

Шаг, который не нужен при сделанном ранее выборе, остаётся в списке зачёркнутым, и навигация его пропускает. Например, если на шаге 3 выбрать службу ИИ, шаги 6 и 7 снова становятся доступными.

Если исходный язык — японский, а язык перевода — китайский упрощённый, шаг 4 предлагает следующее:

- словарь: пакет японский → китайский, если он есть в выпуске, а иначе два пакета, японский → английский и английский → китайский;
- Bergamot: направления ja → en и en → zh-Hans, потому что у каждой модели Bergamot с одной стороны английский.

При варианте «Определять автоматически» шаг 4 предлагает пакеты и направления с английского языка. Примечание под списком просит установить направление на английский для каждого другого языка, на котором приходят письма.

Кнопка «Перевести пример сообщения» на шаге 8 выводит на странице короткое письмо (на исходном языке, если это английский или немецкий, иначе на английском, а на немецком, если язык перевода английский) и переводит его с текущими настройками. Страница использует определение абзацев и отрисовку из скрипта содержимого и отправляет запросы фоновому скрипту по тому же соединению, что и открытое письмо. Поэтому результат показывает, как будет выглядеть настоящее письмо, включая работу используемых уровней.

Мастер использует те же компоненты, что и страница настроек: поля служб и проверку соединения, списки словарей и моделей Bergamot, редактор промптов с шаблонами.

## Использование

Откройте письмо. На панели инструментов заголовка сообщения появится кнопка «Перевести сообщение». Нажатие на неё открывает всплывающее окно со следующими элементами:

- «Перевести это сообщение»: запускает перевод. Пока перевод выполняется или показан, кнопка называется «Показать оригинал» и по нажатию возвращает оригинал.
- «Отображение»: переключает двуязычный режим и режим «Только перевод»; изменение сразу применяется к текущему письму.
- «Исходный язык» и «Язык перевода»: исходный язык по умолчанию — «Определять автоматически». После смены любого из них переводимое письмо переводится заново. Если оба языка совпадают, появляется предупреждение.
- «Уровни перевода»: по одному списку на уровень («Уровень 1: Словарь», «Уровень 2: Машинный перевод», «Уровень 3: Перевод ИИ»), в каждом — «Не используется» и добавленные службы этого уровня. Хотя бы одному уровню нужна служба; если выбрать «Не используется» для последнего используемого уровня, выбор отменяется и появляется предупреждение. Пункт «+ Добавить службу перевода» под списками открывает страницу настроек на разделе служб перевода.
- «Точный перевод»: показывается, пока у уровня ИИ есть служба.
- «Автоматически переводить сообщения, написанные не на языке перевода»: если флажок установлен, письмо, текст которого написан не на языке перевода, переводится сразу при открытии.
- «Мастер настройки»: открывает мастер настройки в новой вкладке.

Всплывающее окно показывает ход перевода, например «Переведено 8 из 12». Абзацы, у которых пока показан предварительный перевод нижнего уровня, считаются отдельно, например «Переведено 7 из 9 (черновых: 2)». Если для абзаца ошибкой завершились все уровни, после него появляется красная надпись «Ошибка перевода, нажмите для повтора»; при наведении указателя видна ошибка, а нажатие повторяет перевод этого абзаца.

Alt+A переводит текущее письмо или возвращает оригинал; Alt+S переключает двуязычный режим и режим «Только перевод». Оба сочетания можно изменить в пункте «Управление горячими клавишами расширений» меню шестерёнки в «Управлении дополнениями».

В режиме «Только перевод» при наведении указателя на перевод во всплывающей подсказке показывается исходный текст.

## Настройки

Страница настроек открывается кнопкой «Настройки» этого расширения в «Управлении дополнениями». Настройки сохраняются автоматически; после записи в правом верхнем углу появляется надпись «Сохранено». Кнопка «Мастер настройки» рядом с ней открывает мастер настройки.

| Раздел | Содержимое |
| --- | --- |
| Общие | Язык интерфейса, исходный язык, язык перевода, режим отображения по умолчанию, переключатель «Автоматически переводить сообщения, написанные не на языке перевода» |
| Уровни перевода | Служба каждого уровня или «Не используется»; точный перевод |
| Службы перевода | Службы в двух группах, «Добавленные» и «Можно добавить»; конечная точка, ключ API, модель, температура и режим рассуждений для каждой службы; кнопки «Проверить соединение», «Добавить», «Использовать эту службу» и «Удалить» |
| Словари | Языковые пары уровня «Словарь» с размером, лицензией и указанием авторства; скачивание и удаление; тег выпуска пакетов (для опытных) |
| Модели офлайн-перевода (Bergamot) | Направления моделей Bergamot с размером и версией; фильтр по языку; скачивание, обновление, отмена и удаление; направления, которые нужны текущим языкам |
| Промпты (уровень ИИ) | Библиотека шаблонов; промпты для двуязычного отображения, отображения только перевода и точного перевода, у каждого кнопка «Восстановить встроенный промпт» |
| Пакетная обработка запросов | Окно сбора, максимальное число символов и абзацев в запросе, число параллельных запросов, повторные попытки, объединение запросов к ИИ |
| Стиль перевода | Линия слева, пунктирная линия слева, выделение фоном или без оформления; акцентный цвет, непрозрачность текста, относительный размер шрифта; предварительный просмотр |
| Кэш | Включение и отключение кэша, максимальное число абзацев в кэше, текущее число записей, очистка кэша |

«Проверить соединение» отправляет одно тестовое предложение с теми значениями, которые сейчас введены в поля. При успехе показывается перевод, при неудаче — ошибка, которую вернула служба, например о недействительном ключе или неизвестном имени модели.

## Добавление и удаление служб

Боковой список раздела служб перевода состоит из двух групп. В группе «Добавленные» находятся службы, которые показываются в списках служб всплывающего окна и страницы настроек; в группе «Можно добавить» — все остальные. При выборе службы показываются её настройки и кнопки:

- У службы, которая не добавлена, есть кнопка «Добавить». Служба добавляется и при вводе ключа API (для DeepLX — конечной точки).
- У добавленной службы есть кнопки «Использовать эту службу», которая назначает службу её уровню, и «Удалить». Удаление убирает службу из списков, но сохраняет её настройки, поэтому при повторном добавлении ключ и модель восстанавливаются.
- Службу, которую использует какой-либо уровень, удалить нельзя. Кнопка «Удалить» тогда неактивна, а строка под ней называет этот уровень. Используемые службы отмечены в боковом списке меткой «Используется».

Новая установка начинается с добавленных Google Translate и Microsoft Translator. Словарю и Bergamot нужны данные, которые вы скачиваете сами, поэтому эти службы добавляются вручную. При загрузке настроек версии 1.1 и ранее служба считается добавленной в таких случаях:

| Служба | Считается добавленной, если |
| --- | --- |
| Google Translate, Microsoft Translator | всегда |
| DeepLX | заполнена конечная точка |
| Службы ИИ, которым нужен ключ | сохранён ключ API |
| Ollama, LM Studio, свой OpenAI-совместимый API | изменены конечная точка, модель или температура |
| службы уровней | всегда |

| Уровень | Службы | Что даёт |
| --- | --- | --- |
| 1 Словарь | Словарь (офлайн) | пословный подстрочник по установленным пакетам словарей, сразу и без сети |
| 2 Машинный перевод | Google Translate, Microsoft Translator, DeepLX, Bergamot (офлайн) | полный перевод за одну-две секунды |
| 3 Перевод ИИ | 22 ИИ-провайдера | лучший перевод, выполненный по промпту текущего режима отображения |

У каждого уровня одна служба или «Не используется», и хотя бы у одного уровня есть служба. По умолчанию используется только Google Translate на уровне 2.

Каждый абзац отправляется сразу на все используемые уровни. Каждый уровень проходит через обычную пакетную обработку и кэш. Что показывает письмо, определяет одно правило: побеждает самый высокий уровень из тех, что уже ответили.

| Случай | Что показывает письмо |
| --- | --- |
| Первым отвечает нижний уровень | его перевод курсивом с меткой его уровня («Словарь», «Машинный перевод»); при наведении указателя подсказка называет уровень, который ещё работает. Когда приходит перевод более высокого уровня, он заменяет предварительный. |
| Отвечает самый высокий используемый уровень | его перевод без метки — это окончательный перевод. Ответы нижних уровней, пришедшие позже, игнорируются. |
| Самый высокий уровень завершился ошибкой | остаётся лучший перевод нижнего уровня с пометкой «Ошибка: Перевод ИИ» (или с названием другого самого высокого уровня); при наведении указателя видна причина, а нажатие повторяет только уровни, завершившиеся ошибкой |
| Все уровни завершились ошибкой | красная надпись «Ошибка перевода, нажмите для повтора» |
| Перевод самого высокого уровня уже есть в кэше | этот перевод сразу; к нижним уровням запросы не отправляются |

При смене режима отображения словарный и машинный переводы перерисовываются без изменений. У уровня ИИ свой промпт для каждого режима отображения, поэтому ему отправляется новый запрос с промптом нового режима; перевод, уже сохранённый в кэше для этого промпта, возвращается без запроса. Всплывающее окно считает окончательные переводы переведёнными, а переводы нижних уровней — черновыми.

Настройки, сохранённые версией 1.3 и ранее, преобразуются один раз:

- Служба ИИ, которая была текущей службой, становится уровнем 3; если был включён параллельный перевод, его быстрая служба становится уровнем 2.
- Любая другая текущая служба становится уровнем 2.
- Уровень словаря сначала не используется.

## Исходный язык

Исходный язык по умолчанию — «Определять автоматически»; можно также выбрать один из 20 языков списка языков перевода. Исходный язык передаётся каждой службе:

| Служба | Автоматическое определение | Заданный язык |
| --- | --- | --- |
| Google Translate | `sl=auto` | `sl=<code>` |
| Microsoft Translator, бесплатно и с ключом | без параметра `from` | `from=<code>` |
| DeepLX | `source_lang: "auto"` | `source_lang: "<code>"` (варианты китайского передаются как `ZH`) |
| Службы ИИ | «Detect the source language of … and translate it into …» | «Translate … from <language> into …» |
| Словарь | определяется для каждого абзаца | заданный язык |
| Bergamot | `"auto"`, а запасным вариантом служит язык, найденный по системе письма и английским стоп-словам | заданный язык |

Абзацы, которые определены как написанные на языке перевода, по-прежнему пропускаются. При заданном исходном языке абзацы, язык которых нельзя надёжно определить, считаются написанными на этом языке. Исходный язык входит в ключи кэша и в признаки пакетов, поэтому после его смены переводы, сделанные при прежней настройке, не возвращаются.

## Промпты

У уровня ИИ три системных промпта. Каждый можно изменить на странице настроек и вернуть кнопкой «Восстановить встроенный промпт»; пустое поле тоже означает встроенный промпт. `{{to}}` заменяется английским названием языка перевода. Исходный язык и формат пакета расширение само добавляет в каждый запрос.

| Промпт | Где используется | Чего требует встроенный промпт |
| --- | --- | --- |
| Двуязычное отображение | уровень ИИ в двуязычном режиме | перевода, близкого к оригиналу: предложение за предложением в том же порядке, без добавлений и пропусков, поскольку читатель сравнивает его с оригиналом |
| Отображение только перевода | уровень ИИ в режиме «Только перевод» | связного текста, который читается как письмо, написанное на языке перевода; части предложений можно переставлять, а предложения разбивать или объединять при полном сохранении смысла |
| Точный перевод | уровень ИИ, пока включён точный перевод, в обоих режимах отображения | единых терминов, имён и форм обращения во всём письме с опорой на глоссарий, краткое содержание и соседние абзацы |

Ключи кэша и пакетов содержат вид промпта и хеш его текста. Поэтому после изменения промпта переводы, сделанные с прежним текстом, не возвращаются. Собственный системный промпт, сохранённый версией 1.3 или ранее, становится промптом обоих режимов отображения; промпт точного перевода начинается со встроенного текста.

### Шаблоны промптов

Библиотека шаблонов находится над тремя промптами на странице настроек и на шаге 7 мастера настройки. Шаблон применяется так:

1. Выберите шаблон в списке «Шаблон». Если у шаблона есть варианты, выберите вариант в списке «Вариант».
2. В списке «Добавить в промпт» выберите промпт.
3. Нажмите «Применить шаблон».

Строка «Пример:» показывает исходное предложение и ожидаемый результат выбранного шаблона.

| Шаблон | Варианты | Правило, которое добавляется в промпт |
| --- | --- | --- |
| Диалект или региональный вариант | зависят от языка перевода: кантонский (Гонконг) и сычуаньский для китайского упрощённого; кантонский (Гонконг) и тайваньский вариант для китайского традиционного; британский и американский английский; бразильский и европейский португальский; мексиканский испанский и испанский (Испания); канадский французский (Квебек); швейцарский литературный немецкий | писать на этом варианте языка, с его орфографией, лексикой и формами обращения |
| Трудные слова с оригиналом | нет | переводить как обычно и после каждого трудного слова или термина указывать в скобках оригинал, один раз на абзац, например «комплексная проверка (due diligence)» |
| Пояснения к трудным словам | нет | перевести абзац, а затем пояснить его трудные слова на языке перевода в конце того же абзаца, в одной скобке: 〔Примечание: термин: пояснение; …〕 |
| Стиль | официально-деловой, разговорный, простой язык для изучающих, литературный | использовать этот регистр и полностью сохранять смысл |

Список вариантов зависит от языка перевода. Для языка перевода без региональных вариантов, например японского, шаблон «Диалект или региональный вариант» не предлагается.

Шаблон добавляет в конец промпта блок правил на английском языке, отделённый пустой строкой. Блок начинается с заголовка, например `Style (this rule takes precedence over the rules above):`. Поэтому блок имеет приоритет над общими правилами встроенного промпта, такими как «Do not add explanations». Повторное применение того же шаблона заменяет его блок, а блоки разных шаблонов складываются. Поле промпта показывает объединённый текст и остаётся доступным для правки. Кнопка «Восстановить встроенный промпт» удаляет все добавления.

Шаблоны сохраняют правило «один перевод на абзац». Пояснения к трудным словам остаются внутри перевода своего абзаца, а блок запрещает возвращать их отдельным абзацем или отдельным элементом массива. Поэтому пакет по-прежнему возвращается как JSON-массив (или пронумерованные сегменты) ровно с одной записью на абзац. Тесты применяют все четыре шаблона к одному промпту и разбирают ответ подменённой модели в обоих форматах.

## Точный перевод

Точный перевод относится к уровню ИИ и передаёт письмо как контекст в каждом запросе к ИИ. Он включается во всплывающем окне или в разделе «Уровни перевода» страницы настроек. При запуске перевода скрипт содержимого склеивает найденные абзацы в простой текст письма (он обрезается после 20 000 символов с пометкой о том, что текст продолжается) и один раз регистрирует его в фоновом скрипте. Письмо определяется по хешу его полного текста; обрезка относится только к тексту, отправляемому как контекст.

Порядок работы зависит от объёма абзацев, которые нужно перевести:

1. Если они помещаются в один запрос (в пределах «Макс. символов в запросе» и «Макс. абзацев в запросе»), все абзацы переводит один запрос; он сам несёт письмо целиком.
2. Иначе сначала один дополнительный запрос анализирует письмо целиком и возвращает краткое содержание из двух-трёх предложений, глоссарий имён, названий продуктов и других имён собственных с переводом, который нужно использовать, а также тон и форму обращения. Если этот ответ не удаётся разобрать, перевод продолжается без него.
3. Затем каждый запрос начинается с одного и того же префикса: системный промпт, анализ и, для писем примерно до 8000 символов, полный текст. После префикса идут абзацы пакета, каждый с предыдущим и следующим абзацем в качестве справки, которая не переводится.

Префикс совпадает символ в символ во всех запросах одного письма, поэтому провайдеры, которые кэшируют повторяющиеся префиксы промптов, могут отдавать его из своего кэша. Для Anthropic префикс помечается `cacheControl: { type: "ephemeral" }`. Анализ кэшируется так же, как переводы; ключ состоит из провайдера, модели, языка перевода и хеша текста письма, а пакеты одного письма ждут один и тот же запрос анализа.

Переводы в точном режиме кэшируются по ключу, в который входит хеш письма, и пакеты никогда не смешивают абзацы разных писем. Поэтому то же предложение в другом письме переводится заново, уже с тем письмом в качестве контекста. Запрос анализа и более длинные промпты делают точный перевод дороже обычного.

## Словарный перевод

Служба «Словарь» переводит слово за словом по пакетам словарей, которые хранятся в профиле Thunderbird. После установки пакета сеть ей не нужна, а отвечает она за миллисекунды, поэтому заполняет время, пока не ответят уровни машинного перевода и ИИ. Результат — пословный подстрочник: слова идут в порядке оригинала, без грамматики.

### Пакеты

Пакеты публикуются как файлы GitHub-выпуска этого репозитория, по умолчанию выпуска `dicts-v1`. Тег выпуска можно изменить в поле «Тег выпуска пакетов словарей (для опытных)» раздела «Словари». Каждое направление — один файл `dict-<src>-<tgt>.tsv.gz`, сжатый gzip текстовый файл в UTF-8:

```text
#dict	<src>	<tgt>	<packVersion>	<sourceName>	<license>
w	<key>	<translation>
f	<key>	<lemmaKey>
```

Первая строка описывает пакет. Строки, начинающиеся с `w`, — статьи; строки, начинающиеся с `f`, сопоставляют словоформе ключ её леммы, например `went` — `go`. Ключ нормализуется в NFC, приводится к нижнему регистру по правилам исходного языка и очищается от пробелов по краям; ключом может быть и фраза из нескольких слов. Индекс `dict-index.json` перечисляет все пакеты с размером, числом статей и словоформ, контрольной суммой SHA-256, источником, лицензией и указанием авторства. Пакеты охватывают английский, китайский упрощённый и традиционный, японский, корейский, французский, немецкий, испанский, португальский, русский, турецкий и вьетнамский. Сборка пакетов описана в [docs/dictionary-packs.md](../docs/dictionary-packs.md).

Раздел «Словари» читает индекс и показывает каждый пакет с размером, лицензией и указанием авторства. Кнопка «Скачать» загружает файл с отображением хода загрузки, проверяет контрольную сумму SHA-256 и заголовок и сохраняет файл в базе данных IndexedDB `tt-dictionary` расширения; кнопка «Удалить» удаляет его. Если индекс загрузить не удалось, раздел сообщает причину, а установленные пакеты по-прежнему можно удалить.

### Перевод

1. Исходный язык — заданный в настройках, а при автоматическом определении — язык абзаца (по системе письма, встроенному детектору браузера и английским стоп-словам).
2. `Intl.Segmenter` разбивает абзац на слова. На каждом слове сначала выбирается самая длинная фраза длиной до трёх слов, для которой есть статья, затем отдельное слово. Слово без статьи ищется через его лемму; если и это не удаётся, слово остаётся как есть. Знаки препинания и числа остаются без изменений.
3. Для китайского и японского языков перевода слова соединяются без пробелов, для остальных — через пробел.
4. Между двумя языками, ни один из которых не английский, перевод идёт через английский: для перевода с французского на немецкий используются пакеты французский → английский и английский → немецкий.
5. Если нужного пакета нет, сообщение об ошибке называет языковую пару и отсылает к разделу «Словари».

Фоновый скрипт читает пакет из IndexedDB при первом использовании и держит его в памяти; после пяти минут без словарных переводов память освобождается.

Пакеты собраны из двух источников:

## Офлайн-перевод (Bergamot)

Служба Bergamot переводит на вашем компьютере с помощью движка и моделей Firefox Translations, которые Mozilla публикует под лицензией MPL-2.0. Движок входит в состав расширения; модель каждого направления перевода скачивается с сервера Mozilla один раз (от 13 до 48 МБ) и хранится в IndexedDB расширения. Загруженное направление занимает около 200 МБ памяти и выгружается после пяти минут без использования. У каждой модели с одной стороны английский, поэтому для перевода с японского на китайский используются направления японский → английский и английский → китайский.

Раздел «Модели офлайн-перевода (Bergamot)» страницы настроек перечисляет 114 пар направлений между 58 языками с размером и версией и фильтрует их по языку. Он называет направления, которые нужны текущим исходному языку и языку перевода, и показывает их первыми. Скачивание отображает ход загрузки и может быть отменено; у установленной пары, для которой Mozilla предлагает более новую версию, появляется кнопка «Обновить». Удаление пары, которая нужна текущим языкам, требует подтверждения. Установка, перевод и удаление выполняются в фоновом скрипте, где работает движок. Выбор моделей, их проверка, хранение и устройство движка описаны в [docs/bergamot.md](../docs/bergamot.md).

## Язык интерфейса

Параметр «Язык интерфейса» в разделе «Общие» принимает значения двух видов:

- «Как в Thunderbird» (по умолчанию): расширение использует поддерживаемый язык, ближайший к языку интерфейса самого Thunderbird. В названии варианта указан выбранный сейчас язык, например «Как в Thunderbird (Deutsch)».
- Один из 12 поддерживаемых языков: расширение использует этот язык независимо от языка Thunderbird.

Выбор действует на всплывающее окно, страницу настроек, надписи внутри писем («Перевод…», «Ошибка перевода, нажмите для повтора»), сообщения об ошибках, результат проверки соединения и подсказку кнопки на панели инструментов. Открытая страница настроек или всплывающее окно сразу меняют язык текста. Надписи внутри уже переведённого письма меняются при следующей отрисовке.

Несколько текстов Thunderbird считывает сам из манифеста расширения, и они всегда следуют языку интерфейса Thunderbird: название и описание расширения в «Управлении дополнениями» и описания сочетаний клавиш в разделе «Управление горячими клавишами расширений». Страница настроек сообщает об этом под параметром.

Вариант «Как в Thunderbird» сопоставляет язык Thunderbird так:

| Язык Thunderbird | Используемый язык интерфейса |
| --- | --- |
| `zh-TW`, `zh-HK`, `zh-MO`, `zh-Hant` | Китайский традиционный |
| остальные `zh-*` | Китайский упрощённый |
| `pt-*` | Португальский (Бразилия) |
| `en-*`, `ja`, `ko`, `fr-*`, `de-*`, `es-*`, `ru`, `tr`, `vi` | язык с тем же основным подтегом |
| любой другой язык | Английский |

## Как устроена пакетная обработка

В письме обычно от десяти до нескольких десятков абзацев. Если отправлять по одному запросу на абзац, каждый абзац несёт свою копию системного промпта и инструкций и расходует один запрос из лимита частоты запросов. Пакетная обработка объединяет абзацы, поступившие с небольшим интервалом, в один запрос, поэтому обе эти затраты приходятся на пакет, а не на абзац.

### Порядок работы

1. Скрипт содержимого передаёт фоновому скрипту каждый абзац, который нужно перевести, один раз для всех используемых уровней.
2. Для каждого уровня фоновый скрипт сначала ищет перевод в кэше и при попадании сразу возвращает ответ. Ключ кэша состоит из провайдера, модели, исходного языка и языка перевода, для служб ИИ — вида промпта и хеша его текста, в точном режиме — хеша письма, и хеша текста абзаца. Если тот же текст уже переводится, последующие запросы получают тот же результат.
3. Абзацы, которых нет в кэше, попадают в очередь пакетов и группируются по сочетанию провайдер + модель + конечная точка + исходный язык + язык перевода, для служб ИИ ещё и по промпту, для Microsoft Translator ещё и по режиму (бесплатный или со своим ключом), а в точном режиме ещё и по письму. Абзацы одной группы накапливаются в течение 50 мс. Группа отправляется, когда окно сбора истекает, когда достигнут лимит абзацев или когда следующий абзац превысил бы лимит символов. Отдельный абзац длиннее лимита символов образует собственный пакет.
4. Очередь запросов выполняет каждый пакет. Она ограничивает число параллельных запросов и повторяет запросы при ошибках 408, 429, 5xx и сетевых ошибках с экспоненциальной задержкой; если сервер прислал `Retry-After`, она ждёт указанное время, но не дольше 30 секунд. Ошибки вроде 401 и 400 сообщаются без повторных попыток.
5. Результаты попадают в кэш в памяти и через 1 секунду записываются в `storage.local` одной операцией записи. Кэш вытесняет записи, которые дольше всего не использовались (LRU).

### Как каждая служба объединяет абзацы

- Словарь и Bergamot: весь пакет переводится одним локальным вызовом.
- Google: один POST-запрос с несколькими параметрами `q`; возвращаемый массив поэлементно соответствует входным данным.
- Microsoft: тело запроса само является массивом.
- DeepLX: конечная точка принимает один абзац на запрос, поэтому абзацы пакета запрашиваются параллельно.
- ИИ-провайдеры: абзацы нумеруются и помещаются в одно сообщение, а модель просят вернуть JSON-массив той же длины. Парсер пробует по порядку: JSON-массив (возможно, внутри блока кода или в окружении пояснений; неэкранированные переводы строк внутри строк и завершающие запятые исправляются), пронумерованные блоки `<seg>`, пронумерованные строки и разделитель `%%`. Если ни один способ не сработал или число элементов не совпало, этот пакет отправляется заново по одному абзацу на запрос, и пользователь видит тот же результат. Ошибки, не связанные с разбором ответа, например ошибки аутентификации, не запускают этот запасной путь, поэтому одна и та же ошибка не повторяется N раз.

### Оценка затрат

Пусть системный промпт и инструкции занимают $s$ токенов, каждый абзац в среднем $t$ токенов, всего $N$ абзацев, размер пакета $B$, а нумерация и кавычки JSON добавляют $c$ токенов на абзац.

При одном запросе на абзац общее число входных токенов равно

$$
I_{\text{по одному}} = N(s + t).
$$

При пакетной обработке запросов $\lceil N/B \rceil$, и общее число входных токенов равно

$$
I_{\text{пакет}} = \left\lceil \frac{N}{B} \right\rceil s + N(t + c).
$$

Разность равна

$$
I_{\text{по одному}} - I_{\text{пакет}} = \left(N - \left\lceil \frac{N}{B} \right\rceil\right) s - Nc.
$$

Пока $s$ заметно больше $c$, более крупные пакеты дают большую экономию. При $s = 150$, $t = 60$, $c = 10$, $N = 20$ и $B = 30$:

$$
I_{\text{по одному}} = 20 \times 210 = 4200, \qquad I_{\text{пакет}} = 150 + 20 \times 70 = 1550.
$$

Число входных токенов снижается примерно на 63 %, а число запросов — с 20 до 1. Число выходных токенов в обоих случаях примерно одинаково, поскольку длина перевода не меняется. Сокращение числа запросов важно и для бесплатных конечных точек: Google и Microsoft ограничивают свои бесплатные конечные точки по частоте запросов, а письмо из 20 абзацев обходится одним запросом.

## Конфиденциальность

- Ключи API хранятся только в `storage.local` текущего профиля Thunderbird и отправляются только в запросах к конечной точке соответствующего провайдера.
- Скрипт содержимого работает внутри страницы сообщения; настройки, которые он получает от фонового скрипта, никогда не содержат ключей.
- Текст письма отправляется только службам используемых уровней. Словарь и Bergamot переводят на вашем компьютере и никуда не отправляют текст. Страница настроек и мастер настройки читают список пакетов словарей из GitHub-выпусков этого репозитория, а список моделей Bergamot — с сервера Mozilla; сами пакеты и модели скачиваются только после нажатия кнопки «Скачать». Ни один из этих запросов не содержит текста писем. Расширение не собирает статистику и не обращается ни к каким другим сетевым адресам.
- Кэш переводов хранится локально; его можно отключить или очистить на странице настроек.
- При использовании Google, Microsoft, DeepLX или онлайн-службы ИИ текст письма покидает ваш компьютер. Для конфиденциальной переписки используйте только словарь, Bergamot и локальные модели ИИ, например Ollama или LM Studio: они оставляют все запросы на вашем собственном компьютере.

## Известные ограничения

- Перевод — это простой текст. Ссылки, полужирный шрифт и другое встроенное форматирование оригинала в переводе не сохраняются. В двуязычном режиме оригинал остаётся полностью доступным; в режиме «Только перевод» можно навести указатель, чтобы увидеть оригинал, или вернуться в двуязычный режим.
- Бесплатные конечные точки Google и Microsoft не документированы и могут измениться или ограничить частоту запросов. Microsoft отключила конечную точку выдачи токенов `edge.microsoft.com/translate/auth` в июле 2026 года; расширение использует только прямую конечную точку.
- Чтобы определить, написан ли абзац уже на языке перевода, китайский, японский, корейский и языки с похожей письменностью распознаются по классу символов, а для языков на латинице и кириллице сначала используется `i18n.detectLanguage` из API расширений. Если этот API недоступен или его результат ненадёжен, надёжно распознаётся только английский; абзацы на других языках с латиницей отправляются на перевод как обычно.
- Скрипт содержимого регистрируется через `messageDisplayScripts` и действует только в письмах, открытых после регистрации. При запуске расширение пытается внедрить его в уже открытые письма; если это не удалось, достаточно выбрать письмо заново.
- Сообщения об ошибках, которые формирует само расширение, переведены. Тексты ошибок, которые возвращает служба перевода или AI SDK (например, тело ответа HTTP 401), показываются в полученном виде, обычно на английском.
- Название расширения, его описание в «Управлении дополнениями» и описания сочетаний клавиш следуют языку интерфейса Thunderbird, а не параметру «Язык интерфейса».
- Точный перевод определяет письмо по хешу текста его тела, потому что скрипт содержимого не имеет доступа к ID письма. Две копии одного текста используют общие переводы и общий анализ.
- Кэширование промптов зависит от провайдера. Anthropic кэширует только префиксы длиннее минимальной длины, которая зависит от модели; более короткие префиксы отправляются и оплачиваются как обычно.
- Переключатель рассуждений работает по совпадению имён моделей. Новая модель, имя которой не подходит ни под один шаблон, не получает параметра рассуждений, пока не будет расширена таблица в `src/background/providers/thinking.ts`.
- Каждый используемый уровень отправляет собственные запросы. Если используются и уровень ИИ, и уровень машинного перевода, каждое письмо также стоит запросов к машинному переводчику, а они учитываются в лимитах частоты бесплатных конечных точек Google и Microsoft.
- Словарный перевод — пословный подстрочник: он сохраняет порядок слов оригинала и не изменяет формы слов. Слова, которых нет в пакетах, остаются непереведёнными.
- Пример письма в мастере настройки написан на английском, а если язык перевода английский, то на немецком. Если задан исходный язык, отличный от этих двух, пробный перевод всё равно отправляет английский текст с указанием этого исходного языка.
- Если вкладка мастера настройки активна, Alt+A переводит пример письма или возвращает его оригинал. Надпись на кнопке пробного перевода при этом не меняется.
- Шаблоны — это инструкции для модели. Насколько точно соблюдаются диалект или стиль, зависит от модели; маленькие модели чаще смешивают региональные варианты.
- Bergamot и словарь переводят пакет с одним исходным языком. При автоматическом определении Bergamot определяет язык всего пакета, поэтому пакет со смесью языков переводится как написанный на преобладающем языке.

## Перевод интерфейса

Тексты интерфейса находятся в `locales/<language>.json`: для каждого языка один плоский объект «ключ → текст». Эталоном служит `locales/en.json`: во всех остальных файлах ровно те же ключи. `$1`–`$9` — подстановки; в каждом переводе они должны присутствовать с теми же номерами, что и в английском тексте. `{{apiKey}}` и `{{to}}` — буквальные токены, они остаются без изменений. Названия продуктов, такие как Google Translate, OpenAI или DeepLX, не переводятся.

`npm run build` преобразует эти файлы в `dist/_locales/<language>/messages.json` — формат, который читает Thunderbird. Собственная среда i18n расширения загружает те же файлы во время работы, поэтому язык интерфейса меняется без перезапуска Thunderbird. Для отсутствующих ключей используется английский текст.

Чтобы добавить язык, создайте `locales/<code>.json` со всеми ключами, добавьте код вместе с самоназванием языка в `SUPPORTED_LOCALES` в `src/shared/locales.ts` и запустите `npm run locales:check` и `npm test`.
