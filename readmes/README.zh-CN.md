# Thunderbird 邮件翻译

[English](../README.md) | 简体中文 | [繁體中文](README.zh-TW.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Español](README.es.md) | [Português (Brasil)](README.pt-BR.md) | [Русский](README.ru.md) | [Türkçe](README.tr.md) | [Tiếng Việt](README.vi.md)

Thunderbird 邮件翻译（Thunderbird Translate）是一个 Thunderbird 扩展，在阅读窗格里直接翻译邮件正文。译文可以放在每段原文下方（双语对照），也可以替换原文（仅译文），取消翻译后邮件恢复成原样。翻译分三个层级同时进行：离线词典、机器翻译（谷歌翻译、微软翻译、DeepLX 或离线的 Bergamot 模型）和 AI 服务（OpenAI、Claude、Gemini、DeepSeek、通义千问等 22 个服务商）。先到的结果先显示，最高层级的结果到达后替换它。默认使用免费的谷歌翻译，装好即可使用。

本文写给第一次接触 Thunderbird 扩展的读者，按“装上、用起来、按需配置、了解原理”的顺序展开。

![演示：翻译邮件、切换双语与仅译文、更换目标语言](../docs/demo.gif)

## 功能

- 翻译正文：识别邮件正文中的段落级内容，包括段落、列表项、表格单元格、标题、引用块、只含文字的 div，以及纯文本邮件中以空行分隔的段落。代码、已是目标语言的段落、纯数字、纯链接和空白内容会被跳过。
- 两种显示方式：双语对照在原文下方插入带淡色左边框的译文块，深色主题下同样可读；仅译文用译文替换原文，原文保存在内存中，取消翻译时原样放回。
- 翻译过程中切换显示方式或目标语言，页面会自动重新渲染，不需要重新打开邮件。切换显示方式会用已收到的词典和机器翻译译文重绘；AI 层级会按新显示方式的提示词重新请求，缓存里已有该译文时由缓存直接返回。
- 入口：邮件头部工具栏的“翻译邮件”按钮和弹出面板，快捷键 Alt+A（翻译 / 显示原文）和 Alt+S（切换双语 / 仅译文）。
- 打开即翻译（可选）：打开非目标语言的邮件时自动开始翻译。
- 请求批处理：后台在 50 毫秒窗口内收集段落，合并成一次请求；每个服务各自限制并发，附带失败重试、指数退避、请求超时和本地缓存。超过单次请求上限的长段落按整行切成若干片；只有单行超过单次请求上限时，才在句子之间切开。
- 三个翻译层级：词典、机器翻译、AI 翻译。每个层级选一个服务或“不使用”，每个段落同时发给所有在用的层级。低层级的结果作为临时译文显示，最高层级的结果到达后替换它；最高层级失败时，低层级的结果保留。
- 服务：1 个离线词典，4 个机器翻译服务（谷歌翻译、微软翻译、DeepLX、离线 Bergamot 模型），22 个 AI 服务商预设，其中一个是“自定义 OpenAI 兼容”。各层级的下拉框只列出已添加的服务。
- 源语言：自动检测或指定一种语言，传给每个服务。
- AI 层级有三套提示词：双语对照一套，仅译文一套，精翻一套。
- 提示词预设：方言或地区用语、难词保留原文、难词解释、四种语言风格，可以追加到三套提示词中的任意一套。
- 新手引导：安装后自动打开，分步设置语言、显示方式、翻译层级、离线下载、服务和提示词，最后用一封示例邮件试译。
- 精翻（AI 层级）：每次请求都以整封邮件为上下文，人名、术语和称谓在各段之间保持一致。
- 每个 AI 服务商各有一个思考模式开关，默认关闭。
- 界面支持 12 种语言。界面语言默认跟随 Thunderbird，也可以在设置页指定。

## 安装

### 从 Releases 安装

1. 在本仓库的 Releases 页面下载最新的 `thunderbird-translate-<版本号>.xpi`。
2. 打开 Thunderbird，进入“工具 → 附加组件和主题”（也可以从右上角 ≡ 菜单进入）。
3. 点击扩展列表上方的齿轮图标，选择“从文件安装附加组件”，选中下载的 xpi 文件，确认安装。

扩展要求 Thunderbird 128 或更新版本。

### 从源码构建

需要 Node.js 22 或更新版本（开发时使用 Node 24、npm 11）。

```bash
npm ci
npm test
npm run build
```

`npm run build` 用 esbuild 把后台脚本、内容脚本、弹出面板、设置页、新手引导页和 Bergamot Worker 分别打包到 `dist/`，由 `locales/` 中的文件生成 `dist/_locales/<语言>/messages.json`，再把 `dist/` 压缩成 `web-ext-artifacts/thunderbird-translate-<版本号>.xpi`。压缩用的是纯 JavaScript 的 fflate 库，不依赖系统里的 zip 命令。后台脚本是 ES 模块，AI SDK 单独成块，放在 `dist/chunks/` 下，用到 AI 层级时才加载，所以 Thunderbird 启动扩展时不需要它。首次构建会从 Mozilla 下载固定版本的 Bergamot 引擎（wasm）到 `.cache/`，详见 [docs/bergamot.md](../docs/bergamot.md)。

开发调试时可以不打包安装：在 Thunderbird 中打开“工具 → 开发者工具 → 调试附加组件”，点击“临时载入附加组件”，选择 `dist/manifest.json`。

## 新手引导

首次安装后，Thunderbird 会在新标签页中打开新手引导。扩展更新或 Thunderbird 更新时不会打开。之后可以从弹出面板的“新手引导”链接或设置页顶部的“新手引导”按钮再次打开。

每一步只做一个决定，选择后立即保存。“上一步”“下一步”“跳过此步”在步骤之间移动，进度条下方的步骤列表可以直接跳到任意一步，“退出引导”随时关闭标签页。下次打开时从上次离开的那一步继续；点过“完成”之后，从第一步重新开始。

| 步骤 | 内容 | 何时显示 |
| --- | --- | --- |
| 1 语言 | 界面语言、源语言（默认“自动检测”）、目标语言 | 总是显示 |
| 2 显示方式 | 双语对照或仅译文，附一段示例邮件按当前译文样式渲染的预览 | 总是显示 |
| 3 翻译层级 | 词典、机器翻译、AI 三个层级的速度、质量、隐私和费用对比；为每个层级选择服务或“不使用”，至少一个层级使用服务 | 总是显示 |
| 4 离线翻译 | 第 1 步所选语言需要的词典包和 Bergamot 方向，附大小、许可证和署名；勾选后点“下载所选项”，显示下载进度 | 词典层级在用，或机器翻译层级使用 Bergamot |
| 5 在线机器翻译 | 机器翻译服务的配置：谷歌无需填写，微软可选免费模式或 Azure 密钥模式，DeepLX 填写接口地址和令牌；“测试连接” | 机器翻译层级使用谷歌、微软或 DeepLX |
| 6 AI 翻译 | AI 服务商、API 密钥、模型、温度、思考模式、“测试连接”和精翻开关；说明思考模式和精翻会让翻译更慢、费用更高 | AI 层级在用 |
| 7 提示词 | 三套提示词和预设库（见“提示词预设”） | AI 层级在用 |
| 8 完成 | 使用方法（工具栏按钮、Alt+A、Alt+S）、“自动翻译非目标语言的邮件”开关、“翻译示例邮件” | 总是显示 |

前面的选择用不到的步骤仍留在步骤列表中，以删除线显示，导航时直接越过。例如在第 3 步为 AI 层级选择服务后，第 6、7 步重新出现。

源语言为日语、目标语言为简体中文时，第 4 步推荐的内容如下：

- 词典：发布中有日语 → 中文词典包时推荐这一个，否则推荐日语 → 英语和英语 → 中文两个包；
- Bergamot：推荐 ja → en 和 en → zh-Hans 两个方向，因为每个 Bergamot 模型都有一侧是英语。

源语言为“自动检测”时，按英语推荐词典包和方向，并提示为收到的其他每种语言安装其到英语的方向。

第 8 步的“翻译示例邮件”在页面中渲染一封简短的邮件（源语言是英语或德语时用源语言，否则用英语；目标语言是英语时用德语），并用当前设置翻译。引导页使用内容脚本的段落识别和渲染模块，经由与真实邮件相同的连接把请求发给后台脚本，因此结果与真实邮件一致，各层级的临时译文和最终译文都会出现。

引导页与设置页使用同一套组件：服务配置字段与测试连接、词典列表、Bergamot 模型列表、带预设的提示词编辑器。

## 使用

打开一封邮件，邮件头部工具栏会出现“翻译邮件”按钮。点击它会弹出面板，面板中有以下控件：

- “翻译此邮件”按钮：开始翻译；翻译进行中或完成后，按钮变为“显示原文”，点击即恢复原文。
- 显示方式：在双语对照和仅译文之间切换，对当前邮件立即生效。
- 源语言和目标语言：源语言默认为“自动检测”。改动任何一项后，正在翻译的邮件会重新翻译。两者相同时，下方出现提示。
- 翻译层级：每个层级一个下拉框（层级 1 词典、层级 2 机器翻译、层级 3 AI 翻译），选项为“不使用”和该层级中已添加的服务。至少要有一个层级设置了服务；把最后一个在用的层级改成“不使用”时，下拉框恢复原值并显示提示。下方的“+ 添加翻译服务”打开设置页并定位到“翻译服务”分组。
- 精翻：AI 层级设置了服务时显示。
- 自动翻译非目标语言的邮件：勾选后，打开邮件时如果正文不是目标语言，会自动开始翻译。
- 新手引导：在新标签页中打开新手引导。

面板下方显示翻译进度，例如“已翻译 8 / 12”。仍显示低层级临时译文的段落单独计数，例如“已翻译 7 / 9（2 段为临时译文）”。某段在所有层级都失败时，原文后会出现红色的“翻译失败，点击重试”，鼠标悬停可以看到错误原因，点击即重试这一段。

快捷键 Alt+A 翻译当前邮件或恢复原文，Alt+S 在双语和仅译文之间切换。快捷键可以在附加组件管理器的齿轮菜单“管理扩展快捷键”中修改。

在仅译文模式下，把鼠标停在译文上，提示框会显示对应的原文。

## 设置

在附加组件管理器中点击本扩展的“选项”打开设置页。设置自动保存，右上角出现“已保存”即表示已写入。保存失败时，错误信息显示在同一位置，这次改动随下一次保存一起写入。新手引导在离开或完成时无法保存设置的，会保持打开并显示错误。旁边的“新手引导”按钮打开新手引导。

| 分组 | 内容 |
| --- | --- |
| 常规 | 界面语言、源语言、目标语言、默认显示方式、“自动翻译非目标语言的邮件”开关 |
| 翻译层级 | 每个层级的服务或“不使用”；精翻 |
| 翻译服务 | 服务分“已添加”和“可添加”两组；每个服务商的接口地址、API 密钥、模型、温度、思考模式；“测试连接”“添加”“使用此服务”“移除”按钮 |
| 词典 | 词典层级的语言对，附大小、许可证和署名；下载、删除；词典包的发布标签（高级） |
| 离线翻译模型（Bergamot） | Bergamot 模型的各个方向，附大小和版本；按语言筛选；下载、更新、取消、删除；当前语言需要的方向 |
| 提示词（AI 层级） | 提示词预设库；双语对照、仅译文、精翻三套提示词，各带“恢复内置提示词”按钮 |
| 请求批处理 | 收集窗口、每次请求最大字符数和段落数、并发数、重试次数、请求超时（默认 60 秒；Ollama、LM Studio 和思考模式为三倍）、是否合并 AI 请求 |
| 译文样式 | 左侧竖线、左侧虚线、底色高亮或无装饰；强调色、文字不透明度、字号比例；附带实时预览 |
| 缓存 | 是否缓存、最多缓存段落数、当前缓存条数、清除缓存 |

“测试连接”用输入框中的当前值发送一句测试文本，成功时显示译文，失败时显示服务商返回的错误，例如密钥无效或模型名称不存在。

## 添加与移除服务

“翻译服务”分组左侧的列表分为两组。“已添加”组里的服务出现在弹出面板和设置页的服务列表中，其余服务在“可添加”组里。选中一个服务后，右侧显示它的配置和按钮：

- 未添加的服务有“添加”按钮。填入 API 密钥（DeepLX 为接口地址）也会自动添加该服务。
- 已添加的服务有“使用此服务”和“移除”按钮。“使用此服务”把它设为所属层级的服务。移除只把服务移出列表，已填的配置保留，再次添加时密钥和模型仍在。
- 某个层级正在使用的服务不能移除。此时“移除”按钮不可点，按钮下方写明是哪个层级在用。左侧列表中，在用的服务带“使用中”标签。

新安装时，谷歌翻译和微软翻译处于已添加状态。词典和 Bergamot 需要先下载数据，因此要手动添加。读取 1.1 及更早版本保存的设置时，按下表判断一个服务是否已添加：

| 服务 | 视为已添加的条件 |
| --- | --- |
| 谷歌翻译、微软翻译 | 始终 |
| DeepLX | 已填写接口地址 |
| 需要密钥的 AI 服务 | 已保存 API 密钥 |
| Ollama、LM Studio、自定义 OpenAI 兼容 | 接口地址、模型或温度被改过 |
| 各层级正在使用的服务 | 始终 |

## 翻译层级

| 层级 | 可选服务 | 给出的结果 |
| --- | --- | --- |
| 1 词典 | 词典（离线） | 用已安装的词典包逐词对照，立即可用，不需要网络 |
| 2 机器翻译 | 谷歌翻译、微软翻译、DeepLX、Bergamot（离线） | 完整译文，通常一两秒内返回 |
| 3 AI 翻译 | 22 个 AI 服务商 | 质量最高的译文，按当前显示方式的提示词翻译 |

每个层级选一个服务或“不使用”，至少一个层级设置了服务。默认只有层级 2 使用谷歌翻译。

每个段落同时发给所有在用的层级，各层级分别走原有的批处理和缓存。邮件中显示的内容遵循一条规则：显示已返回结果的最高层级。

| 情况 | 邮件中显示的内容 |
| --- | --- |
| 低层级先返回 | 该层级的译文，斜体，带注明层级的标签（“词典”“机器翻译”）；悬停提示仍在等待的层级。更高层级的结果到达后替换它 |
| 在用的最高层级返回 | 最高层级的译文，不带标签，即最终译文；之后到达的低层级结果被忽略 |
| 最高层级失败 | 保留已有的最好的低层级译文，标记“AI 翻译失败”（或最高层级的名称）；悬停显示原因，点击只重试失败的层级 |
| 所有层级都失败 | 红色的“翻译失败，点击重试” |
| 最高层级的译文已在缓存中 | 直接显示该译文，不请求低层级 |

切换显示方式时，词典和机器翻译的结果直接重新渲染。AI 层级的每种显示方式各有一套提示词，因此切换后按新提示词重新请求；该提示词下已有缓存时不发请求。弹出面板把最终译文计为已翻译，把低层级译文计为临时译文。

读取 1.3 及更早版本保存的设置时，转换规则如下：

- 当前服务是 AI 服务时，它成为层级 3；当时开启了竞速翻译的，竞速的快速服务成为层级 2。
- 当前服务是其他服务时，它成为层级 2。
- 词典层级为“不使用”。

## 源语言

源语言默认为“自动检测”，也可以指定目标语言列表中 20 种语言的任意一种。各服务按下表接收源语言：

| 服务 | 自动检测 | 指定语言 |
| --- | --- | --- |
| 谷歌翻译 | `sl=auto` | `sl=<代码>` |
| 微软翻译（免费与密钥模式） | 不带 `from` 参数 | `from=<代码>` |
| DeepLX | `source_lang: "auto"` | `source_lang: "<代码>"`（中文变体统一为 `ZH`） |
| AI 服务 | 提示“Detect the source language of … and translate it into …” | 提示“Translate … from <语言> into …” |
| 词典 | 逐段检测 | 直接使用指定语言 |
| Bergamot | 逐段检测，同一语言的段落合在一起翻译 | 直接使用指定语言 |

跳过段落的规则不变：检测为目标语言的段落不翻译。目标语言是中文时，段落还要与目标使用同一种书写体系：目标为繁体中文时，简体段落照常翻译，反过来也一样。判断依据是只在一种书写体系中出现的字，例如们/們、这/這、说/說；段落里没有这类字时，简繁读者都能直接阅读，按已是目标语言处理。指定了源语言时，检测结果不可靠的段落按指定的源语言处理。缓存键和批次键都包含源语言，改动源语言后不会命中按旧设置得到的译文。

词典和 Bergamot 不做简体中文与繁体中文之间的翻译。两者都要经英语中转，得到的是按中文词序排列的英语释义，例如把“我们明天开会”译成“我們明天持有一個會議”。因此，另一种书写体系的中文段落在这两个层级中失败，错误信息为“此服务不支持简体中文与繁体中文之间的翻译。”，也不显示来自这两个层级的临时译文；这类段落由机器翻译层级和 AI 层级翻译。新手引导不为这一语言对推荐词典包。

## 提示词

AI 层级有三套系统提示词，都可以在设置页编辑，并用“恢复内置提示词”还原。设置里只保存改动过的提示词：没有改动的提示词存为空串，代表内置提示词，编辑框中显示内置文本。这样扩展升级后，没有改过提示词的用户自动用上新版的内置提示词。点击“恢复内置提示词”，或把编辑框的内容改回与内置文本相同，保存的都是空串。旧版本存入的内置提示词副本会在读取设置时识别出来，改为空串，设置随即以这种形式写回；用户自己写的提示词原样保留。`{{to}}` 会替换为目标语言的英文名称。源语言和批处理格式由扩展自动加入每次请求。

| 提示词 | 使用场合 | 内置提示词的要求 |
| --- | --- | --- |
| 双语对照 | 双语对照模式下的 AI 层级 | 读者会对照原文阅读，因此贴近原文，逐句对应，顺序不变，不增不删 |
| 仅译文 | 仅译文模式下的 AI 层级 | 读者只看译文，因此要求通顺、可独立阅读、符合目标语言的邮件习惯，可以调整语序、拆分或合并句子，完整保留原意 |
| 精翻 | 开启精翻时的 AI 层级，两种显示方式都用它 | 利用术语表、摘要和相邻段落，使术语、人名和称谓在整封邮件中保持一致 |

缓存键和批次键包含提示词的种类和内容哈希，修改提示词后不会命中旧译文。1.3 及更早版本保存的自定义系统提示词会同时成为双语对照和仅译文两套提示词，精翻提示词使用内置内容。

### 提示词预设

预设库位于设置页三套提示词的上方，新手引导第 7 步中也有同一个预设库。使用步骤：

1. 选择预设；预设带变体时，再选择变体。
2. 在“追加到”中选择一套提示词。
3. 点击“应用预设”。

“示例”一行给出一句原文和应用该预设后的预期译文。

| 预设 | 变体 | 追加到提示词的规则 |
| --- | --- | --- |
| 方言 / 地区用语 | 按目标语言列出：简体中文为粤语（香港）、四川话；繁体中文为粤语（香港）、台湾用语；英语为英式、美式；葡萄牙语为巴西、欧洲；西班牙语为墨西哥、西班牙本土；法语为加拿大法语（魁北克）；德语为瑞士标准德语 | 用该变体书写，采用它的拼写、词汇和称呼方式 |
| 难词保留原文 | 无 | 正常翻译，在难词和专业术语的译文后用括号保留原文，每段只标注一次，例如“尽职调查（due diligence）” |
| 难词解释 | 无 | 翻译段落后，在同一段末尾用一个括号以目标语言解释该段的难词：〔注：术语：解释；……〕 |
| 语言风格 | 正式商务、口语随意、简明易懂（面向语言学习者）、文学化 | 采用该语体，完整保留原意 |

变体列表随目标语言变化。目标语言没有地区变体时（例如日语），预设列表中不出现“方言 / 地区用语”。

预设以英文规则块的形式追加在提示词末尾，与前文隔一个空行。规则块以标题行开头，例如 `Style (this rule takes precedence over the rules above):`，表示它优先于内置提示词中的通用规则，比如“不要添加解释”。再次应用同一个预设会替换它原来的规则块，不同预设的规则块叠加。提示词编辑框显示组合后的文本，可以继续手动修改；“恢复内置提示词”会去掉所有追加内容。

预设不改变“每段一个译文”的约定。难词解释留在所属段落的译文之内，规则块明确禁止把解释输出为单独的段落或数组元素，因此批量请求的回答仍是每段恰好一项的 JSON 数组（或编号分段）。测试把四个预设同时追加到一套提示词上，用模拟模型分别返回 JSON 数组和编号分段，两种格式都能正确解析。

## 精翻

精翻只作用于 AI 层级，让每次 AI 请求都带上整封邮件作为上下文，可以在弹出面板或设置页的“翻译层级”分组中开关。开始翻译时，内容脚本按顺序拼接已识别的段落，得到邮件正文的纯文本（超过 20000 字符时截断，并注明后文未列出），向后台登记一次。邮件以完整正文的哈希值标识，截断只作用于作为上下文发送的文本。

翻译流程取决于待翻译段落的总量：

1. 待翻译段落能放进一次请求（不超过“每次请求最大字符数”和“每次请求最大段落数”）时，一次请求翻译全部段落，这次请求本身就包含了整封邮件。
2. 放不下时，先多发一次请求分析全文，要求返回三项内容：2 到 3 句话的摘要；人名、产品名等专有名词及其统一译法组成的术语表；语气和称谓建议。返回内容无法解析时，不使用分析结果，翻译照常进行，这封邮件也不再重新分析。请求失败（网络错误、超时、HTTP 错误）时，同样不使用分析结果，翻译照常进行；下次翻译这封邮件时重新请求分析。
3. 之后每次请求都以同一段前缀开头：系统提示词、分析结果，以及全文（全文不超过约 8000 字符时）。前缀之后是本批段落，每段前后各附一个相邻段落作为参考，并注明参考段落不翻译。

同一封邮件的所有请求，前缀逐字相同，支持前缀缓存的服务商可以直接命中缓存。Anthropic 需要显式标记，扩展为前缀加上 `cacheControl: { type: "ephemeral" }`。分析结果与译文存放在同一个缓存中，缓存键由服务商、模型、源语言与目标语言、请求配置（接口地址、提示词、思考开关、温度）的哈希和全文哈希组成；同一封邮件的多个批次共用一次分析请求。

精翻得到的译文，缓存键中包含邮件哈希；批处理也按邮件分组，不同邮件的段落不会进入同一次请求。因此同一句话出现在另一封邮件里时，会结合那封邮件重新翻译。分析请求和更长的提示词让精翻的费用高于普通翻译。

## 词典翻译

词典服务用保存在 Thunderbird 配置文件中的词典包逐词翻译。词典包装好后不需要网络，几毫秒内就能返回，用来填补机器翻译和 AI 翻译返回之前的空档。得到的是逐词对照：词序与原文相同，不做语法变换。

### 词典包

词典包作为本仓库 GitHub Release 的附件发布，默认使用 `dicts-v1` 这个发布。设置页“词典”分组中的“词典包的发布标签（高级）”可以改用其他发布。每个翻译方向一个文件 `dict-<源>-<目标>.tsv.gz`，内容是 gzip 压缩的 UTF-8 文本：

```text
#dict	<src>	<tgt>	<packVersion>	<sourceName>	<license>
w	<key>	<translation>
f	<key>	<lemmaKey>
```

各行的含义如下：

- 第一行说明词典包本身：源语言、目标语言、版本、数据来源、许可证。
- 以 `w` 开头的行是词条。
- 以 `f` 开头的行把屈折形式对应到原形的键，例如把 `went` 对应到 `go`。

键经过 NFC 规范化，按源语言的规则转为小写，并去掉首尾空白；键可以是含空格的多词短语。索引文件 `dict-index.json` 列出每个词典包的大小、词条数、变形数、SHA-256 校验值、来源、许可证和署名。词典包覆盖英语、简体中文、繁体中文、日语、韩语、法语、德语、西班牙语、葡萄牙语、俄语、土耳其语和越南语。构建方法见 [docs/dictionary-packs.md](../docs/dictionary-packs.md)。

设置页的“词典”分组读取索引，列出每个词典包的大小、许可证和署名。“下载”按钮下载文件，显示进度和“取消”按钮，校验 SHA-256 和文件头，然后存入扩展的 IndexedDB 数据库 `tt-dictionary`；“删除”按钮删除它。索引无法加载时，分组中写明原因，已安装的词典包仍可删除。索引 30 秒内没有响应时加载失败。下载 30 秒内没有收到数据时停止并报错；下载较慢但持续收到数据时，不限时间。

### 翻译过程

1. 确定源语言：使用指定的源语言；自动检测时，按段落检测（文字类别、浏览器的语言检测、英文常用词）。
2. 用 `Intl.Segmenter` 把段落切分成词。在每个词的位置，先找最长的、有词条的短语（最多 3 个词），再找单词。单词查不到时，经变形表找到原形再查；仍查不到则保留原词。标点和数字原样保留。
3. 目标语言为中文或日语时，词与词之间不加空格，其他语言用空格分隔。
4. 两种语言都不是英语时，经英语中转：法语到德语使用“法语 → 英语”和“英语 → 德语”两个词典包。
5. 缺少需要的词典包时，错误信息写明缺少的语言对，并提示到“词典”分组下载。

后台第一次用到某个词典包时从 IndexedDB 读入内存；连续 5 分钟没有词典翻译后释放内存。

### 数据来源

词典包的数据有两个来源：

- Wiktionary，由 wiktextract 提取、kaikki.org 发布，许可证为 CC BY-SA 4.0，版权归 Wiktionary 贡献者。
- skywind3000 的 ECDICT，许可证为 MIT。

每个词典包在索引中写明自己的来源和许可证，设置页在词典包旁显示这些信息。

## 离线翻译（Bergamot）

Bergamot 服务在本机翻译，使用 Firefox Translations 的引擎和翻译模型，由 Mozilla 以 MPL-2.0 许可证发布。引擎随扩展一起安装；每个翻译方向的模型从 Mozilla 下载一次，大小为 13 到 48 MB，保存在扩展的 IndexedDB 中。加载一个方向约占用 200 MB 内存，5 分钟不用后释放。每个模型的一侧都是英语，因此日语到中文要用“日语 → 英语”和“英语 → 中文”两个方向。

设置页的“离线翻译模型（Bergamot）”分组列出 58 种语言之间的 114 个方向，附大小和版本，可以按语言筛选。分组中写明当前源语言和目标语言需要哪些方向，并把它们排在最前。下载过程显示进度，可以取消；模型列表 30 秒内没有响应时加载失败，下载 30 秒内没有收到数据时停止并报错；Mozilla 提供了更新版本的已安装方向显示“更新”按钮。删除当前语言需要的方向前，会先请求确认。安装、翻译和删除都在后台脚本中执行，引擎也运行在那里。模型的选择、校验、存储和引擎细节见 [docs/bergamot.md](../docs/bergamot.md)。

## 界面语言

设置页“常规”分组中的“界面语言”有两类取值：

- 跟随 Thunderbird（默认）：扩展选用与 Thunderbird 界面语言最接近的受支持语言。选项文字会标出当前实际使用的语言，例如“跟随 Thunderbird（Deutsch）”。
- 12 种受支持语言之一：扩展固定使用这种语言，与 Thunderbird 的语言无关。

这一设置作用于弹出面板、设置页、邮件中的提示文字（“翻译中…”“翻译失败，点击重试”）、错误信息、测试连接的结果，以及工具栏按钮的悬停提示。已打开的设置页和弹出面板会立即换成新语言。已经翻译过的邮件里，提示文字在下一次绘制时换成新语言。

有两处文字由 Thunderbird 直接从扩展的 manifest 读取，始终跟随 Thunderbird 的界面语言：

- 附加组件管理器中的扩展名称和扩展说明；
- “管理扩展快捷键”中的快捷键说明。

设置页在“界面语言”选项下方注明了这一点。

选择“跟随 Thunderbird”时，Thunderbird 的语言按下表对应到受支持语言：

| Thunderbird 的语言 | 扩展使用的界面语言 |
| --- | --- |
| `zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant` | 繁体中文 |
| 其他 `zh-*` | 简体中文 |
| `pt-*` | 葡萄牙语（巴西） |
| `en-*`、`ja`、`ko`、`fr-*`、`de-*`、`es-*`、`ru`、`tr`、`vi` | 主语言标签相同的语言 |
| 其他语言 | 英语 |

目标语言下拉框中的语言名按当前界面语言显示，括号里附上该语言的自称，例如界面为中文时显示“日语（日本語）”。发给 AI 服务的提示词始终使用英文语言名，因为模型对英文指令的遵循最稳定。

首次安装时，目标语言按界面语言设定：日语界面的 Thunderbird 默认目标语言为日语，英语界面默认为英语。已经保存过的目标语言不会被覆盖。

## 批处理原理

一封邮件通常有十几到几十个段落。逐段请求时，每段都要单独发送一次系统提示词和翻译指令，并单独占用一次请求配额。批处理把短时间内到达的段落合并成一次请求，这两项开销随之改为每批计一次。

### 流程

1. 内容脚本把每个待翻译段落交给后台，一次请求涵盖所有在用的层级。
2. 后台对每个层级先查缓存，命中则直接返回。缓存键由五部分组成：服务商、模型、源语言与目标语言、一个“其他影响结果的设置”的哈希、段落文本的哈希。这个哈希包含接口地址，微软翻译还包含免费或密钥模式；AI 服务还包含提示词的种类和内容、思考开关和温度；词典和 Bergamot 还包含已安装的词典包或模型及其版本；精翻时再加上邮件。改动其中任何一项，都不会命中按旧设置得到的译文。相同文本正在翻译时，后来的请求共用同一个结果；请求失败或超时后，这个共用条目随即移除，下一次请求重新发出。
3. 未命中的段落进入批处理队列，按“服务商 + 模型 + 接口地址 + 源语言 + 目标语言”分组，AI 服务再按提示词、思考开关和温度分组，微软翻译再按免费或密钥模式分组，精翻时再按邮件分组。同一组的段落在 50 毫秒窗口内累积；窗口结束、段落数达到上限或字符数将超过上限时，这一组立即发出。单段超过字符上限时，先切成不超过上限的若干片。每片按整行收入，连同换行符，放得下就继续收入下一行；下一行放不下时，这一片在它的最后一个换行处结束。单行超过上限时，用 `Intl.Segmenter` 在句子之间切开；单句仍超过上限时按长度切开。段首的空白不发送，翻译后放回译文前面。各片像普通段落一样翻译，再按原顺序拼接：在换行处切开的位置用这个换行连接，其他位置加一个空格（目标为中文或日语时不加空格）。例如，一段 60 行、3900 字符的引用回复，在默认上限 3000 字符下分成两片发出，切口在换行处，不会拆成 60 个单行请求。缓存以整段为单位。
4. 每个服务有自己的请求队列，慢的 AI 服务不会挡住词典和机器翻译。请求队列限制本服务的并发数，遇到 408、429、5xx 或网络错误时按指数退避重试，最多重试设置中的次数；服务端给出 `Retry-After` 时按它等待，最长等待 30 秒。401、400 这类错误直接报告，不重试。请求超时到达时仍未收到完整响应（包括响应正文）的请求被取消。之后的处理因服务而异：

   | 服务 | 超时时间 | 超时之后 |
   | --- | --- | --- |
   | 谷歌翻译、微软翻译、DeepLX | 设置中的请求超时（默认 60 秒） | 再试一次；错误信息写明两次尝试合计的时间，例如“120 秒内没有响应” |
   | AI 服务，包括精翻的分析请求和“测试连接” | 请求超时；Ollama、LM Studio 和开启思考模式的模型为三倍 | 不再尝试：一次太慢的模型再试仍然太慢，而且每次尝试都要计费；错误信息写明等待的时间，例如“180 秒内没有响应” |

   每条超时错误都附带调大超时的提示。离线 Bergamot 引擎的一次翻译 2 分钟内没有响应，或加载模型 5 分钟内没有响应时，引擎终止它的 Worker，下一次请求启动新的 Worker。连续两次超时后，离线翻译在一分钟内直接失败，错误信息说明这一情况，不再逐个等待各自的超时。
5. 结果写入内存缓存，并在 1 秒后合并写入 `storage.local`。缓存按最近最少使用（LRU）淘汰。

### 各类服务的合并方式

- 词典和 Bergamot：整批在本机一次翻译，每段各有自己的结果，缺少词典包或模型的段落单独失败，不影响其他段落。自动检测源语言时，Bergamot 逐段检测语言，同一语言的段落合在一起翻译；太短、检测器无法判断的段落取本批中出现最多的语言，本批都无法判断时按英语处理。
- Google：一次 POST 带多个 `q` 参数，返回数组与输入一一对应。返回格式异常时，这一批改为逐段请求；逐段请求同样经过本服务的请求队列，受并发上限和重试约束，某一段失败只影响这一段。
- 微软：请求体本身就是数组。
- DeepLX：接口一次只接受一段，批内各段并发请求。
- AI 服务商：各段编号后放入一条消息，要求模型返回长度相同的 JSON 数组。解析器依次尝试 JSON 数组（可带代码块或前后说明文字，会修复字符串中的裸换行和多余逗号）、带编号的 `<seg>` 块、编号行、`%%` 分隔符。全部失败、条数不符，或某段原文含字母或数字而译文为空时，这一批改为逐段请求，用户看到的结果不受影响。认证失败等非解析错误不做逐段回退，避免同样的错误重复 N 次。

### 开销估算

设系统提示词和指令共 $s$ 个 token，每段平均 $t$ 个 token，共 $N$ 段，批大小为 $B$，每段编号与 JSON 引号的额外开销为 $c$ 个 token。

逐段请求的输入 token 总量为

$$
I_{\text{逐段}} = N(s + t).
$$

批处理时共有 $\lceil N/B \rceil$ 次请求，输入 token 总量为

$$
I_{\text{批}} = \left\lceil \frac{N}{B} \right\rceil s + N(t + c).
$$

两者之差为

$$
I_{\text{逐段}} - I_{\text{批}} = \left(N - \left\lceil \frac{N}{B} \right\rceil\right) s - Nc.
$$

只要 $s$ 明显大于 $c$，批越大节省越多。以 $s = 150$、$t = 60$、$c = 10$、$N = 20$、$B = 30$ 为例：

$$
I_{\text{逐段}} = 20 \times 210 = 4200, \qquad I_{\text{批}} = 150 + 20 \times 70 = 1550.
$$

输入 token 减少约 63%，请求次数从 20 次降为 1 次。输出 token 两种方式基本相同，因为译文本身的长度不变。请求次数的减少对免费接口同样重要：谷歌和微软的免费接口按请求频率限流，一封 20 段的邮件只占一次请求。

## 隐私

- API 密钥只保存在当前 Thunderbird 配置文件的 `storage.local` 中，只随请求发送到对应服务商的接口地址。
- 内容脚本运行在邮件页面里，它从后台拿到的设置既不包含密钥，也不包含接口地址，因为接口地址里可能带有令牌。
- 错误信息会遮盖可能是机密的内容，遮盖处显示为 `***`。遮盖的范围如下：
  - 本服务的 API 密钥或令牌，无论出现在错误信息的哪个位置；
  - URL 路径中形似令牌的段落，即 20 个及以上同时含字母和数字的字符；
  - URL 中的用户名和密码；
  - 名称含 key、token、auth、secret、sig、pass、credential 或 session 的 URL 参数。
- 邮件正文只发送给在用层级的服务。词典和 Bergamot 在本机翻译，不向外发送任何文字。设置页和新手引导页从本仓库的 GitHub Release 读取词典包列表，从 Mozilla 读取 Bergamot 模型列表；词典包和模型本身只在点击“下载”时下载。这些请求都不携带邮件正文。扩展不收集统计数据，不访问其他网络地址。
- 译文缓存保存在本地，可以在设置页关闭或清除。
- 使用谷歌、微软、DeepLX 或在线 AI 服务时，邮件内容会离开本机。处理敏感邮件时，只使用词典、Bergamot 和 Ollama、LM Studio 这类本地模型，请求只到达本机。

## 已知限制

- 译文以纯文本呈现。原文中的链接、加粗等行内格式在译文里不保留；双语模式下原文仍完整可用，仅译文模式下可悬停查看原文或切回双语。
- 谷歌和微软的免费接口没有公开文档，接口可能变化或限流。微软的令牌接口 `edge.microsoft.com/translate/auth` 已于 2026 年 7 月下线，扩展只使用直连接口。
- 判断段落是否已是目标语言时，中日韩等文字按字符类别判断，拉丁字母和西里尔字母语言优先调用扩展 API 的 i18n.detectLanguage；该接口不可用或结果不可靠时，只对英文有可靠的判断，其他拉丁字母语言的段落会照常发送翻译。
- 内容脚本通过 `messageDisplayScripts` 注册，只作用于注册之后打开的邮件。扩展启动时会尝试为已打开的邮件补充注入；补充注入失败时，重新点选一次邮件即可。
- 扩展自身产生的错误信息已翻译。翻译服务或 AI SDK 返回的错误文字（例如 HTTP 401 响应的正文）按原样显示，通常是英文。
- 扩展名称、附加组件管理器中的扩展说明和快捷键说明跟随 Thunderbird 的界面语言，不受“界面语言”选项控制。
- 精翻用正文文本的哈希标识邮件，因为内容脚本拿不到邮件 ID。正文完全相同的两封邮件共用译文和分析结果。
- 前缀缓存由服务商决定是否生效。Anthropic 只缓存长度达到模型下限的前缀，较短的前缀按普通输入计费。
- 思考模式开关按模型名匹配。名称不符合任何规则的新模型不会收到思考参数，需要在 `src/background/providers/thinking.ts` 的表中补充规则。
- 每个在用的层级各自发送请求。AI 层级和机器翻译层级同时在用时，每封邮件都会向机器翻译服务发送请求，占用谷歌和微软免费接口的频率限额。
- 词典翻译是逐词对照，保持原文词序，不做屈折变化。词典包里没有的词保持原样。
- 新手引导的示例邮件是英文，目标语言为英语时改为德文。源语言固定为其他语言时，试译仍会以该源语言发送这封邮件。
- 新手引导是当前标签页时按 Alt+A，会翻译或还原示例邮件，此时试译按钮上的文字不会随之变化。
- 预设是写给模型的指令，方言和语体的遵循程度取决于模型；小模型更容易混用不同地区的用语。
- 自动检测源语言时，Bergamot 把少于 12 个字母、检测器无法判断的短段落归入本批中出现最多的语言。与前后文语言不同的短段落因此会按前后文的语言翻译。
- 简繁中文靠一张 83 个常用字的对照表区分。段落中没有表内的字时，对简体和繁体两种目标都视为已是目标语言。
- 词典和 Bergamot 不做简体中文与繁体中文之间的转换。其中之一是唯一在用的层级时，另一种书写体系的中文段落保持未翻译。

```bash
npm run test:coverage  # 带覆盖率的单元测试，低于 vitest.config.ts 中的门槛即失败
npm run e2e            # 无界面 Thunderbird（THUNDERBIRD_BIN）对接本地模拟服务：三层翻译、模式切换、恢复原文；新手引导的离线下载
npm run typecheck      # TypeScript 类型检查
npm run locales:check  # 以 locales/en.json 为基准检查各语言文件
npm run live-test      # 用扩展自身的翻译模块调用真实的谷歌和微软接口，含指定源语言的情况
```

单元测试覆盖以下内容：

- 批处理分组与队列；
- AI 输出解析与回退；
- 段落识别，以及双语/仅译文的渲染与恢复（jsdom 环境）；
- 谷歌、微软、DeepLX 的请求构造与响应解析（模拟 fetch）；
- 每个 AI 预设的请求地址与认证头，每个服务商的思考参数；
- 设置迁移：迁移到“已添加”状态，迁移到三个层级和三套提示词；
- 弹出面板和设置页的层级下拉框，阻止三个层级全部为空，移除保护；
- 翻译层级：低层级先到后被替换、高层级先到后忽略低层级、最高层级失败时保留次高层级、所有层级失败、某层级不使用、最高层级命中缓存时不请求低层级；
- 提示词的选择与缓存键；切换显示方式时 AI 层级重新请求，其他层级只重新渲染；
- 源语言：各服务在自动检测和指定语言两种情况下的请求参数，改动源语言后不命中旧缓存；
- 词典：词典包解析、分词与短语匹配、变形还原、经英语中转、缺少词典包的错误、带校验的下载（使用内存中的 IndexedDB）；
- Bergamot 服务及其模型管理（模拟引擎模块），设置页的离线模型分组；
- 精翻：单次请求路径、分析加分批路径、分析失败降级、缓存键包含邮件哈希、不同邮件不混批、同一邮件的提示词前缀逐字相同及 Anthropic 缓存标记；
- 新手引导：只在首次安装时打开，步骤导航、跳过不需要的步骤、从上次的步骤继续，每一步的保存，推荐的词典包和 Bergamot 方向及其下载，服务配置和测试连接，提示词预设，经内容脚本模块的试译；
- 提示词预设：按目标语言筛选变体，与三套提示词的组合，同一预设的替换，四个预设同时生效时的批量解析；
- 本地化：各语言的键集合与占位符和英文一致，manifest 引用的 `__MSG_*__` 都存在，Thunderbird 语言到受支持语言的映射，缺失键回退到英文，HTML 页面和源码中没有硬编码的界面文字；
- 翻译流程走生产路径 `translateForPage()`：各层级使用独立的请求队列并行、请求超时、单段失败不影响同批其他段、同一批中混有多种语言、超过单批上限的长段落。

`npm run e2e` 运行三个场景，每个场景各启动一个使用临时配置文件的无界面 Thunderbird，结束时只关闭本次启动的进程：

| 场景 | 检查内容 |
| --- | --- |
| HTML 邮件 | 段落识别，每段按词典 → 谷歌 → AI 的顺序到达，临时译文与最终译文，切换到仅译文时只重新请求 AI 层级，恢复后的 DOM 与原文一致 |
| 纯文本邮件 | 同上，邮件中含引用块 |
| 新手引导的离线下载 | Thunderbird 不打开邮件，直接打开新手引导；测试进入离线下载这一步，从模拟服务下载词典包和 Bergamot 模型并检查进度，确认两者已存入后再删除 |

`npm run build:debug` 生成调试版 xpi，打开邮件即开始翻译并把进度写入控制台，用于在真实的 Thunderbird 中检查整条流程。

## 翻译界面文字

界面文字保存在 `locales/<语言>.json` 中，每个文件是一个“键 → 文字”的扁平对象。`locales/en.json` 是基准，其他文件的键必须与它完全相同。文件内容有三条约定：

- `$1` 到 `$9` 是替换参数，译文中出现的编号必须与英文一致，位置可以按语序调整。
- `{{apiKey}}` 和 `{{to}}` 是字面标记，原样保留。
- Google 翻译、OpenAI、DeepLX 等产品名不翻译。

`npm run build` 把这些文件转换成 Thunderbird 读取的 `dist/_locales/<语言>/messages.json`。扩展自带的 i18n 运行时在运行时加载同一批文件，所以切换界面语言不需要重启 Thunderbird。某个键在当前语言中缺失时，回退到英文。

新增一种语言的步骤：

1. 按 `locales/en.json` 的全部键新建 `locales/<代码>.json`。
2. 在 `src/shared/locales.ts` 的 `SUPPORTED_LOCALES` 中加入该代码，并补上它的自称。
3. 运行 `npm run locales:check` 和 `npm test`。
