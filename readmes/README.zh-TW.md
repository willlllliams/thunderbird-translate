# Thunderbird 郵件翻譯

[English](../README.md) | [简体中文](README.zh-CN.md) | 繁體中文 | [日本語](README.ja.md) | [한국어](README.ko.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Español](README.es.md) | [Português (Brasil)](README.pt-BR.md) | [Русский](README.ru.md) | [Türkçe](README.tr.md) | [Tiếng Việt](README.vi.md)

Thunderbird 郵件翻譯（Thunderbird Translate）是一個 Thunderbird 擴充套件，在閱讀窗格中直接翻譯郵件內文。譯文可以放在每段原文下方（雙語對照），也可以取代原文（僅譯文）；取消翻譯後，郵件會恢復原狀。翻譯分三個層級同時進行：離線辭典、機器翻譯（Google 翻譯、Microsoft 翻譯、DeepLX 或離線的 Bergamot 模型）和 AI 服務（OpenAI、Claude、Gemini、DeepSeek、通義千問等 22 個服務商）。先送達的結果先顯示，最高層級的結果送達後取代它。預設使用免費的 Google 翻譯，安裝後即可使用。

本文寫給第一次接觸 Thunderbird 擴充套件的讀者，依「安裝、開始使用、依需求設定、了解原理」的順序說明。

## 功能

- 翻譯內文：辨識郵件內文中段落層級的內容，包括段落、清單項目、表格儲存格、標題、引言區塊、只含文字的 div，以及純文字郵件中以空行分隔的段落。程式碼、已是目標語言的段落、純數字、純連結和空白內容會被略過。
- 兩種顯示方式：雙語對照會在原文下方插入帶淡色左框線的譯文區塊，在深色佈景主題下同樣清楚可讀；僅譯文以譯文取代原文，原文保留在記憶體中，取消翻譯時原樣放回。
- 翻譯過程中切換顯示方式或目標語言，頁面會自動重新繪製，不需要重新開啟郵件。切換顯示方式會用已收到的辭典與機器翻譯譯文重繪；AI 層級會依新顯示方式的提示詞重新請求，快取中已有該譯文時由快取直接回傳。
- 入口：郵件標頭工具列上的「翻譯郵件」按鈕與彈出面板，以及快速鍵 Alt+A（翻譯 / 顯示原文）、Alt+S（切換雙語對照 / 僅譯文）和 Alt+R（忽略快取重新翻譯）。
- 開啟即翻譯（可選）：開啟非目標語言的郵件時自動開始翻譯。
- 請求批次處理：背景程式在 50 毫秒的時間窗內收集段落，合併成一次請求；各服務分別限制同時請求數，並提供失敗重試、指數退避、請求逾時與本機快取。超過單次請求上限的長段落切成若干片，每片由完整的行組成；只有單獨一行就超過單次請求上限時，才在句子之間切開。
- 三個翻譯層級：辭典、機器翻譯、AI 翻譯。每個層級選擇一個服務或「不使用」，每個段落同時送給所有使用中的層級。較低層級的結果作為暫時譯文顯示，最高層級的結果送達後取代它；最高層級失敗時，保留較低層級的結果。
- 服務：1 個離線辭典，4 個機器翻譯服務（Google 翻譯、Microsoft 翻譯、DeepLX、離線 Bergamot 模型），22 個 AI 服務商預設組態，其中一個是「自訂 OpenAI 相容服務」。各層級的下拉選單只列出已新增的服務。
- 來源語言：自動偵測或指定一種語言，傳給每個服務。
- AI 層級有三套提示詞：雙語對照、僅譯文、精翻各一套。
- 提示詞預設：方言或地區用語、難詞保留原文、難詞解釋、四種語言風格，可以附加到三套提示詞中的任何一套。
- 新手導覽：安裝後自動開啟，分步設定語言、顯示方式、翻譯層級、離線下載、服務和提示詞，最後以一封範例郵件試譯。
- 精翻（AI 層級）：每次請求都以整封郵件為上下文，人名、術語和稱謂在各段之間保持一致。
- 每個 AI 服務商各有一個思考模式開關，預設關閉。
- 介面支援 12 種語言。介面語言預設跟隨 Thunderbird，也可以在設定頁面中指定。

## 安裝

### 從 Releases 安裝

1. 在本儲存庫的 Releases 頁面下載最新的 `thunderbird-translate-<版本號>.xpi`。
2. 開啟 Thunderbird，進入「工具 → 附加元件與佈景主題」（也可以從右上角的 ≡ 選單進入）。
3. 點擊擴充套件清單上方的齒輪圖示，選擇「從檔案安裝附加元件…」，選取下載的 xpi 檔案，確認安裝。

本擴充套件需要 Thunderbird 128 或更新版本。

### 從原始碼建置

需要 Node.js 22 或更新版本（開發時使用 Node 24、npm 11）。

```bash
npm ci
npm test
npm run build
```

`npm run build` 以 esbuild 將背景指令碼、內容指令碼、彈出面板、設定頁面、新手導覽頁面和 Bergamot Worker 分別打包到 `dist/`，由 `locales/` 中的檔案產生 `dist/_locales/<語言>/messages.json`，再將 `dist/` 壓縮成 `web-ext-artifacts/thunderbird-translate-<版本號>.xpi`。壓縮使用純 JavaScript 的 fflate 函式庫，不依賴系統中的 zip 指令。背景指令碼是 ES 模組，AI SDK 獨立成區塊，放在 `dist/chunks/` 下，用到 AI 層級時才載入，所以 Thunderbird 啟動擴充套件時不需要它。首次建置會從 Mozilla 下載固定版本的 Bergamot 引擎（wasm）到 `.cache/`，詳見 [docs/bergamot.md](../docs/bergamot.md)。

開發除錯時可以不打包直接安裝：在 Thunderbird 中開啟「工具 → 開發者工具 → 除錯附加元件」，點擊「載入暫時附加元件…」，選擇 `dist/manifest.json`。

## 新手導覽

首次安裝後，Thunderbird 會在新分頁中開啟新手導覽。擴充套件更新或 Thunderbird 更新時不會開啟。之後可以從彈出面板的「新手導覽」連結或設定頁面頂端的「新手導覽」按鈕再次開啟。

每一步只做一個決定，選擇後立即儲存。「上一步」「下一步」「略過此步」在步驟之間移動，進度列下方的步驟清單可以直接跳到任何一步，「結束導覽」隨時關閉分頁。下次開啟時從上次離開的那一步繼續；點擊「完成」之後，下次從第一步重新開始。

| 步驟 | 內容 | 何時顯示 |
| --- | --- | --- |
| 1 語言 | 介面語言、來源語言（預設「自動偵測」）、目標語言 | 一律顯示 |
| 2 顯示方式 | 雙語對照或僅譯文，附一段範例郵件依目前譯文樣式繪製的預覽 | 一律顯示 |
| 3 翻譯層級 | 辭典、機器翻譯、AI 翻譯三個層級的速度、品質、隱私和費用比較；為每個層級選擇服務或「不使用」，至少一個層級使用服務 | 一律顯示 |
| 4 離線翻譯 | 全部辭典包和 Bergamot 方向，附大小、授權條款和姓名標示，所選語言的排在最前並已勾選；勾選後點擊「下載所選項目」，顯示下載進度，或點擊「下載常用語言」 | 辭典層級使用中，或機器翻譯層級使用 Bergamot |
| 5 線上機器翻譯 | 機器翻譯服務的設定：Google 翻譯不需要填寫，Microsoft 翻譯可選免費模式或金鑰模式（Azure Translator），DeepLX 填寫端點和存取權杖；「測試連線」 | 機器翻譯層級使用 Google 翻譯、Microsoft 翻譯或 DeepLX |
| 6 AI 翻譯 | AI 服務商、API 金鑰、模型、溫度、思考模式、「測試連線」和精翻開關；說明思考模式和精翻會讓翻譯變慢、費用變高 | AI 層級使用中 |
| 7 提示詞 | 三套提示詞和預設庫（見「提示詞預設」） | AI 層級使用中 |
| 8 完成 | 使用方法（工具列按鈕、Alt+A、Alt+S）、「自動翻譯非目標語言的郵件」開關、「翻譯範例郵件」按鈕 | 一律顯示 |

前面的選擇用不到的步驟仍留在步驟清單中，以刪除線顯示，「上一步」「下一步」會直接越過它。例如在第 3 步為 AI 層級選擇服務後，第 6、7 步會重新出現。

第 4 步列出辭典和 Bergamot 的全部方向，排列順序和標籤見[離線清單](#離線清單)。哪些方向已被勾選，取決於來源語言：

- 來源語言固定：勾選這組語言需要的方向。以日語 → 簡體中文為例，辭典勾選發布版本中的「日語 → 中文」辭典包，沒有這個辭典包時勾選「日語 → 英語」和「英語 → 中文」兩個辭典包；Bergamot 勾選 ja → en 和 en → zh-Hans 兩個方向，因為每個 Bergamot 模型的一側都是英語。
- 「自動偵測」：勾選推薦語言到英語和英語到推薦語言的方向。頁面另有一則提示說明中轉方式：其他語言的郵件先經「語言 → 英語」譯成英語，再經「英語 → 目標語言」譯成目標語言。

沒有勾選任何項目時，「下載所選項目」無法點擊，旁邊的一行寫著「請先勾選要下載的項目。」。下載過程中顯示「正在下載 N 項…」，結束時顯示「下載完成。」；有下載失敗的項目時，顯示失敗的項數（「N 項下載失敗，原因見清單。」），每個失敗的列各自顯示原因。

第 8 步的「翻譯範例郵件」在頁面中繪製一封簡短的郵件（來源語言為英語或德語時用來源語言，否則用英語；目標語言為英語時用德語），並以目前的設定翻譯。導覽頁面使用內容指令碼的段落辨識和繪製模組，經由與真實郵件相同的連線把請求傳給背景程式，因此結果與真實郵件一致，各層級的暫時譯文和最終譯文都會出現。

導覽頁面與設定頁面使用同一套元件：服務設定欄位與測試連線、辭典清單、Bergamot 模型清單、附預設的提示詞編輯器。

## 使用方式

開啟一封郵件，郵件標頭工具列上會出現「翻譯郵件」按鈕。點擊後會彈出面板，面板中有以下控制項：

- 「翻譯此郵件」按鈕：開始翻譯；翻譯進行中或完成後，按鈕會變成「顯示原文」，點擊即可恢復原文。
- 「重新翻譯」按鈕：郵件處於翻譯狀態時顯示在「顯示原文」旁邊。點擊後依目前的顯示方式重新翻譯這封郵件，三個層級全部重新請求：快取和仍在進行的同一請求都不參與，新結果覆蓋快取中的舊譯文；精翻也會重新分析整封郵件。低層級的暫時譯文照常顯示，其他郵件的快取不受影響。
- 顯示方式：在雙語對照與僅譯文之間切換，對目前的郵件立即生效。
- 來源語言與目標語言：來源語言預設為「自動偵測」。變更其中任何一項後，正在翻譯的郵件會重新翻譯。兩者相同時，下方會出現提示。
- 翻譯層級：每個層級一個下拉選單（層級 1：辭典、層級 2：機器翻譯、層級 3：AI 翻譯），選項為「不使用」、該層級中已新增的服務，最後一項是「＋ 新增翻譯服務…」。選擇最後一項會開啟設定頁面並定位到該層級的翻譯服務，下拉選單保持原值。至少要有一個層級設定服務；把最後一個使用中的層級改成「不使用」時，下拉選單會恢復原值並顯示提示。選中的辭典或 Bergamot 缺少目前語言所需的資料時會帶標記，見[缺少離線資料](#缺少離線資料)。
- 精翻：AI 層級設定了服務時才會顯示。
- 自動翻譯非目標語言的郵件：勾選後，開啟郵件時若內文不是目標語言，會自動開始翻譯。
- 新手導覽：在新分頁中開啟新手導覽。

面板下方顯示翻譯進度，例如「已翻譯 8 / 12」。仍顯示較低層級暫時譯文的段落會另外計數，例如「已翻譯 7 / 9（2 段為暫時譯文）」。某一段在所有層級都失敗時，原文後方會出現紅色的「翻譯失敗，點擊重試」；滑鼠游標停在上面可以看到錯誤原因，點擊即重試這一段。

快速鍵 Alt+A 翻譯目前的郵件或恢復原文，Alt+S 在雙語對照與僅譯文之間切換，Alt+R 與彈出面板中的「重新翻譯」作用相同，郵件未翻譯時不做任何動作。三個快速鍵都可以在附加元件管理員齒輪選單中的「管理擴充套件快速鍵」修改。

在僅譯文模式下，將滑鼠游標停在譯文上，提示框會顯示對應的原文。

## 設定

在附加元件管理員中點擊本擴充套件的「選項」即可開啟設定頁面。設定會自動儲存，右上角出現「已儲存」即表示已經寫入。儲存失敗時，該位置改為顯示錯誤，這次變更隨下一次儲存寫入。新手導覽在離開或完成時無法儲存設定的話，會保持開啟並顯示錯誤。旁邊的「新手導覽」按鈕會開啟新手導覽。

| 分組 | 內容 |
| --- | --- |
| 一般 | 介面語言、來源語言、目標語言、預設顯示方式、「自動翻譯非目標語言的郵件」開關 |
| 翻譯層級 | 每個層級的服務或「不使用」，缺少資料的離線服務帶標記；精翻；已關閉的「缺少離線資料時的提醒」，附「恢復提醒」按鈕 |
| 翻譯服務 | 服務分為「已新增」和「可新增」兩組，可依層級篩選；每個服務商的 API 端點、API 金鑰、模型、溫度、思考模式；「測試連線」「新增」「使用此服務」「移除」按鈕 |
| 辭典 | 發布版本中的全部辭典包，附大小、授權條款和姓名標示，推薦語言的排在最前；篩選；「下載常用語言」；下載、刪除；辭典包的發布標籤（進階） |
| 離線翻譯模型（Bergamot） | Bergamot 模型的全部方向，附大小和版本，推薦語言的排在最前；篩選；「下載常用語言」；下載、更新、取消、刪除；目前語言需要的方向 |
| 提示詞（AI 層級） | 提示詞預設庫；雙語對照、僅譯文、精翻三套提示詞，各附「還原內建提示詞」按鈕 |
| 請求批次處理 | 收集時間窗、每次請求的字元數上限與段落數上限、同時請求數、重試次數、請求逾時（預設 60 秒；Ollama、LM Studio 和思考模式為其三倍）、是否合併 AI 請求 |
| 譯文樣式 | 左側直線、左側虛線、底色醒目提示或無裝飾；強調色、文字不透明度、字型大小比例；附即時預覽 |
| 快取 | 是否快取、快取段落數上限、目前快取筆數、清除快取 |

「測試連線」會以輸入欄位中目前的值傳送一句測試文字；成功時顯示譯文，失敗時顯示服務商傳回的錯誤，例如金鑰無效或模型名稱不存在。

## 新增與移除服務

「翻譯服務」分組左側的清單分為兩組。「已新增」組中的服務會出現在彈出面板和設定頁面的服務清單中，其餘服務在「可新增」組中。選取一個服務後，右側會顯示它的設定和按鈕：

- 尚未新增的服務有「新增」按鈕。填入 API 金鑰（DeepLX 為 API 端點）也會自動新增該服務。
- 已新增的服務有「使用此服務」和「移除」按鈕。「使用此服務」會把它設為所屬層級的服務。移除只會把服務移出清單，已填寫的設定會保留，再次新增時金鑰和模型仍在。
- 某個層級正在使用的服務不能移除。此時「移除」按鈕無法點擊，按鈕下方會寫明是哪個層級在使用。左側清單中，使用中的服務帶有「使用中」標籤。

全新安裝時，Google 翻譯和 Microsoft 翻譯處於已新增狀態。辭典和 Bergamot 需要先下載資料，因此要手動新增。讀取 1.1 及更早版本儲存的設定時，依下表判斷一個服務是否已新增：

| 服務 | 視為已新增的條件 |
| --- | --- |
| Google 翻譯、Microsoft 翻譯 | 一律視為已新增 |
| DeepLX | 已填寫 API 端點 |
| 需要金鑰的 AI 服務 | 已儲存 API 金鑰 |
| Ollama、LM Studio、自訂 OpenAI 相容服務 | API 端點、模型或溫度被修改過 |
| 各層級正在使用的服務 | 一律視為已新增 |

## 翻譯層級

| 層級 | 可選服務 | 提供的結果 |
| --- | --- | --- |
| 1 辭典 | 辭典（離線） | 以已安裝的辭典包逐詞對照，立即可用，不需要網路 |
| 2 機器翻譯 | Google 翻譯、Microsoft 翻譯、DeepLX、Bergamot（離線） | 完整譯文，通常一兩秒內傳回 |
| 3 AI 翻譯 | 22 個 AI 服務商 | 品質最高的譯文，依目前顯示方式的提示詞翻譯 |

每個層級選擇一個服務或「不使用」，至少要有一個層級設定服務。預設只有層級 2 使用 Google 翻譯。

每個段落同時送給所有使用中的層級，各層級分別經過原有的批次處理和快取。郵件中顯示的內容遵循一條規則：顯示已傳回結果的最高層級。

| 情況 | 郵件中顯示的內容 |
| --- | --- |
| 較低層級先傳回 | 該層級的譯文，以斜體顯示並帶有註明層級的標籤（「辭典」「機器翻譯」）；滑鼠游標停在上面會顯示仍在等待的層級。較高層級的結果送達後取代它 |
| 使用中的最高層級傳回 | 最高層級的譯文，不帶標籤，即最終譯文；之後送達的較低層級結果會被忽略 |
| 最高層級失敗 | 保留現有最好的較低層級譯文，標記「AI 翻譯失敗」（或最高層級的名稱）；滑鼠游標停在上面可以看到原因，點擊只重試失敗的層級 |
| 所有層級都失敗 | 紅色的「翻譯失敗，點擊重試」 |
| 最高層級的譯文已在快取中 | 直接顯示該譯文，不請求較低層級 |

切換顯示方式時，辭典和機器翻譯的結果直接重新繪製。AI 層級的每種顯示方式各有一套提示詞，因此切換後會依新提示詞重新請求；該提示詞下已有快取時不發出請求。彈出面板把最終譯文計為已翻譯，把較低層級的譯文計為暫時譯文。

讀取 1.3 及更早版本儲存的設定時，轉換規則如下：

- 目前服務是 AI 服務時，它成為層級 3；當時開啟了競速翻譯的，競速翻譯的快速服務成為層級 2。
- 目前服務是其他服務時，它成為層級 2。
- 辭典層級為「不使用」。

## 來源語言

來源語言預設為「自動偵測」，也可以指定目標語言清單中 20 種語言的任何一種。各服務依下表接收來源語言：

| 服務 | 自動偵測 | 指定語言 |
| --- | --- | --- |
| Google 翻譯 | `sl=auto` | `sl=<代碼>` |
| Microsoft 翻譯（免費與金鑰模式） | 不帶 `from` 參數 | `from=<代碼>` |
| DeepLX | `source_lang: "auto"` | `source_lang: "<代碼>"`（中文變體一律為 `ZH`） |
| AI 服務 | 提示「Detect the source language of … and translate it into …」 | 提示「Translate … from <語言> into …」 |
| 辭典 | 逐段偵測 | 直接使用指定語言 |
| Bergamot | 逐段偵測，同一語言的段落合在一起翻譯 | 直接使用指定語言 |

略過段落的規則不變：偵測為目標語言的段落不翻譯。目標語言是中文時，段落還要與目標使用同一種書寫體系：目標為繁體中文時，簡體段落照常翻譯，反過來也一樣。判斷依據是只在一種書寫體系中出現的字，例如 们/們、这/這、说/說；段落裡沒有這類字時，簡繁讀者都能直接閱讀，視為已是目標語言。指定了來源語言時，偵測結果不可靠的段落依指定的來源語言處理。快取鍵和批次鍵都包含來源語言，變更來源語言後不會命中依舊設定得到的譯文。

辭典和 Bergamot 不在簡體中文與繁體中文之間翻譯。若由它們翻譯，兩者都要經英語中轉，傳回依中文詞序排列的英語詞義轉譯，例如把「我们明天开会」譯成「我們明天持有一個會議」。因此，另一種中文書寫體系的段落在這兩個層級中會失敗，錯誤訊息為「此服務不支援簡體中文與繁體中文之間的翻譯。」。這兩個層級不為它顯示暫時譯文，段落由機器翻譯和 AI 層級翻譯。新手導覽不為這一組語言推薦辭典包。

## 提示詞

AI 層級有三套系統提示詞，都可以在設定頁面編輯，並以「還原內建提示詞」還原。設定中只儲存改動過的提示詞：沒有改動的提示詞儲存為空字串，代表內建提示詞，編輯框中顯示內建文字。因此擴充套件升級後，沒有改過提示詞的使用者會自動用上新版的內建提示詞。點擊「還原內建提示詞」，或把編輯框的內容改回與內建文字相同，儲存的都是空字串。舊版本存入的內建提示詞副本會在讀取設定時被辨識出來並改為空字串，設定隨即以這種形式寫回；使用者自己寫的提示詞原樣保留。`{{to}}` 會替換為目標語言的英文名稱。來源語言和批次處理格式由擴充套件自動加入每次請求。

| 提示詞 | 使用場合 | 內建提示詞的要求 |
| --- | --- | --- |
| 雙語對照 | 雙語對照模式下的 AI 層級 | 讀者會對照原文閱讀，因此貼近原文，逐句對應，順序不變，不增不刪 |
| 僅譯文 | 僅譯文模式下的 AI 層級 | 讀者只看譯文，因此要求通順、可獨立閱讀、符合目標語言的郵件慣例，可以調整語序、拆分或合併句子，完整保留原意 |
| 精翻 | 開啟精翻時的 AI 層級，兩種顯示方式都使用 | 利用術語表、摘要和相鄰段落，使術語、人名和稱謂在整封郵件中保持一致 |

快取鍵和批次鍵包含提示詞的種類和內容雜湊值，修改提示詞後不會命中舊譯文。1.3 及更早版本儲存的自訂系統提示詞會同時成為雙語對照和僅譯文兩套提示詞，精翻提示詞使用內建內容。

### 提示詞預設

預設庫位於設定頁面三套提示詞的上方，新手導覽第 7 步中也有同一個預設庫。使用步驟：

1. 選擇預設；預設帶有變體時，再選擇變體。
2. 在「附加到」中選擇一套提示詞。
3. 點擊「套用預設」。

「範例」一行列出一句原文和套用該預設後的預期譯文。

| 預設 | 變體 | 附加到提示詞的規則 |
| --- | --- | --- |
| 一般（不附加規則），清單中的第一項 | 無 | 不附加規則：套用後移除所有由預設附加到提示詞的規則區塊，保留手寫的文字；移除後提示詞與內建提示詞相同的，重新存為空字串 |
| 方言／地區用語 | 依目標語言列出：簡體中文為粵語（香港）、四川話；繁體中文為粵語（香港）、臺灣用語；英語為英式英語、美式英語；葡萄牙語為巴西葡萄牙語、歐洲葡萄牙語；西班牙語為墨西哥西班牙語、西班牙本土西班牙語；法語為加拿大法語（魁北克）；德語為瑞士標準德語 | 以該變體書寫，採用它的拼寫、詞彙和稱呼方式 |
| 難詞保留原文 | 無 | 正常翻譯，在難詞和專業術語的譯文後以括號保留原文，同一個詞每段只標註一次，例如「盡職調查（due diligence）」 |
| 難詞解釋 | 無 | 翻譯段落後，在同一段末尾以一個括號用目標語言解釋該段的難詞：〔註：術語：解釋；……〕 |
| 語言風格 | 正式商務、口語隨意、淺白易懂（適合語言學習者）、文學化 | 採用該語體，完整保留原意 |

變體清單隨目標語言變化。目標語言沒有地區變體時（例如日語），預設清單中不出現「方言／地區用語」。

預設以英文規則區塊的形式附加在提示詞末尾，與前文隔一個空行。規則區塊以標題行開頭，例如 `Style (this rule takes precedence over the rules above):`，表示它優先於內建提示詞中的一般規則，例如「不要加入解釋」。

再次套用同一個預設會取代它原本的規則區塊，不同預設的規則區塊會疊加。提示詞編輯框顯示組合後的文字，可以繼續手動修改；「還原內建提示詞」會移除所有附加內容。

預設不改變「每段一個譯文」的約定。難詞解釋留在所屬段落的譯文之內，規則區塊明確禁止把解釋輸出為單獨的段落或陣列元素，因此批次請求的回答仍是每段恰好一項的 JSON 陣列（或編號分段）。測試把四個預設同時附加到一套提示詞上，以模擬模型分別傳回 JSON 陣列和編號分段，兩種格式都能正確剖析。

## 精翻

精翻只作用於 AI 層級，讓每次 AI 請求都帶上整封郵件作為上下文，可以在彈出面板或設定頁面的「翻譯層級」分組中開關。開始翻譯時，內容指令碼依序串接已辨識的段落，得到郵件內文的純文字（超過 20000 字元時截斷，並註明後文未列出），向背景程式登記一次。郵件以完整內文的雜湊值識別，截斷只作用於作為上下文傳送的文字。

翻譯流程取決於待翻譯段落的總量：

1. 待翻譯段落能放進一次請求（不超過「每次請求的字元數上限」和「每次請求的段落數上限」）時，一次請求翻譯全部段落，這次請求本身就包含整封郵件。
2. 放不下時，先多送一次請求分析全文，要求傳回三項內容：2 到 3 句話的摘要；人名、產品名等專有名詞及其統一譯法組成的術語表；語氣和稱謂建議。傳回內容無法剖析時，不使用分析結果，翻譯照常進行，這封郵件也不再重新分析。請求失敗時（網路錯誤、逾時、HTTP 錯誤），同樣不使用分析結果，翻譯照常進行，下一次翻譯這封郵件時會重新請求分析。
3. 之後每次請求都以同一段前綴開頭：系統提示詞、分析結果，以及全文（全文不超過約 8000 字元時）。前綴之後是本批段落，每段前後各附上一個相鄰段落作為參考，並註明參考段落不翻譯。

同一封郵件的所有請求，前綴逐字相同，支援前綴快取的服務商可以直接命中快取。Anthropic 需要明確標記，擴充套件會為前綴加上 `cacheControl: { type: "ephemeral" }`。分析結果與譯文存放在同一個快取中，快取鍵由服務商、模型、來源語言與目標語言、請求設定的雜湊值（API 端點、提示詞、思考開關、溫度）和全文雜湊值組成；同一封郵件的多個批次共用一次分析請求。

精翻得到的譯文，快取鍵中包含郵件雜湊值；批次處理也依郵件分組，不同郵件的段落不會進入同一次請求。因此同一句話出現在另一封郵件中時，會結合那封郵件重新翻譯。分析請求和較長的提示詞使精翻的費用高於一般翻譯。

## 辭典翻譯

辭典服務使用儲存在 Thunderbird 設定檔中的辭典包逐詞翻譯。辭典包安裝後不需要網路，幾毫秒內就能傳回，用來填補機器翻譯和 AI 翻譯傳回之前的空檔。得到的是逐詞對照：詞序與原文相同，不做文法變換。

### 辭典包

辭典包作為本儲存庫 GitHub Release 的附件發布，預設使用 `dicts-v1` 這個發布版本。設定頁面「辭典」分組中的「辭典包的發布標籤（進階）」可以改用其他發布版本。每個翻譯方向一個檔案 `dict-<來源>-<目標>.tsv.gz`，內容是以 gzip 壓縮的 UTF-8 文字：

```text
#dict	<src>	<tgt>	<packVersion>	<sourceName>	<license>
w	<key>	<translation>
f	<key>	<lemmaKey>
```

各行的意義如下：

- 第一行說明辭典包本身：來源語言、目標語言、版本、資料來源、授權條款。
- 以 `w` 開頭的行是詞條。
- 以 `f` 開頭的行把屈折變化形式對應到原形的鍵，例如把 `went` 對應到 `go`。

鍵經過 NFC 正規化，依來源語言的規則轉為小寫，並去除前後空白；鍵可以是含空格的多詞片語。索引檔 `dict-index.json` 列出每個辭典包的大小、詞條數、變化形式數、SHA-256 總和檢查碼、來源、授權條款和姓名標示。辭典包涵蓋英語、簡體中文、繁體中文、日語、韓語、法語、德語、西班牙語、葡萄牙語、俄語、土耳其語和越南語。建置方法見 [docs/dictionary-packs.md](../docs/dictionary-packs.md)。

設定頁面的「辭典」分組讀取索引，列出每個辭典包的大小、授權條款和姓名標示。「下載」按鈕會下載檔案，並顯示進度和「取消」按鈕，驗證 SHA-256 和檔頭，然後存入擴充套件的 IndexedDB 資料庫 `tt-dictionary`；「刪除」按鈕會刪除它。索引無法載入時，分組中會寫明原因，已安裝的辭典包仍可刪除。索引在 30 秒內沒有回應時載入失敗。下載連續 30 秒沒有收到資料時停止並回報錯誤；速度慢但持續收到資料的下載沒有時間限制。

### 翻譯過程

1. 決定來源語言：使用指定的來源語言；自動偵測時，逐段偵測（文字類別、瀏覽器的語言偵測、英文常用詞）。
2. 以 `Intl.Segmenter` 把段落切分成詞。在每個詞的位置，先找最長的、有詞條的片語（最多 3 個詞），再找單詞。單詞查不到時，經由變化形式表找到原形再查；仍查不到則保留原詞。標點和數字原樣保留。
3. 目標語言為中文或日語時，詞與詞之間不加空格，其他語言以空格分隔。
4. 兩種語言都不是英語時，經英語中轉：法語到德語使用「法語 → 英語」和「英語 → 德語」兩個辭典包。
5. 缺少需要的辭典包時，錯誤訊息會寫明缺少的語言組合，並提示到「辭典」分組下載。

背景程式第一次用到某個辭典包時，將它從 IndexedDB 讀入記憶體；連續 5 分鐘沒有辭典翻譯後釋放記憶體。

## 離線翻譯（Bergamot）

Bergamot 服務在本機翻譯，使用 Firefox Translations 的引擎和翻譯模型，由 Mozilla 以 MPL-2.0 授權條款發布。引擎隨擴充套件一起安裝；每個翻譯方向的模型從 Mozilla 下載一次，大小為 13 到 48 MB，儲存在擴充套件的 IndexedDB 中。載入一個方向約佔用 200 MB 記憶體，5 分鐘未使用後釋放。每個模型的一側都是英語，因此日語到中文要使用「日語 → 英語」和「英語 → 中文」兩個方向。

設定頁面的「離線翻譯模型（Bergamot）」分組列出 58 種語言之間的 114 個方向，附大小和版本，排列順序見[離線清單](#離線清單)。分組中會寫明目前來源語言和目標語言需要哪些方向。下載過程會顯示進度，可以取消；模型清單在 30 秒內沒有回應時載入失敗，下載連續 30 秒沒有收到資料時停止並回報錯誤；Mozilla 提供了較新版本的已安裝方向會顯示「更新」按鈕。刪除目前語言需要的方向之前，會先要求確認。安裝、翻譯和刪除都在背景指令碼中執行，引擎也在那裡執行。模型的選擇、驗證、儲存和引擎細節見 [docs/bergamot.md](../docs/bergamot.md)。

## 離線清單

設定頁面和新手導覽第 4 步中的辭典清單與 Bergamot 清單，顯示各自目錄的全部方向和已安裝的方向。篩選欄位接受語言名稱或 `ja>en` 這樣的方向，多個詞以逗號分隔。

推薦語言的方向排在最前。推薦語言來自下列一個或多個來源，依重要性由高到低：

1. 目標語言；
2. 來源語言（固定時）；
3. 擴充套件的介面語言（「跟隨 Thunderbird」時取 Thunderbird 的語言）；
4. Thunderbird 的介面語言；
5. 系統語言（`i18n.getPreferredSystemLanguages()`；沒有該介面的 Thunderbird 版本使用 `Intl` 格式的地區設定）。

對英語以外的每個推薦語言 X，推薦 X → 英語和英語 → X 兩個方向；辭典還推薦 X 與目標語言之間的直接辭典包，前提是發布版本中有。推薦的每一列以標籤標明來源（「目標語言」「來源語言」「附加元件語言」「Thunderbird 語言」「系統語言」），進入目標語言的方向另帶「直接方向」，進入英語、用於經英語中轉的方向另帶「經英語中轉」。其餘方向依名稱排在後面。

「下載常用語言」會下載八種固定語言與英語之間兩個方向的模型：簡體中文、西班牙語、法語、德語、日語、葡萄牙語、俄語和韓語，目錄中有的才下載。下載前先列出這些方向和總大小，已安裝的方向不再列入。全部已安裝時，按鈕無法點擊，並顯示「常用語言均已安裝。」。

## 缺少離線資料

各處對一組語言需要什麼資料，規則相同：

| 服務 | 一側是英語的語言組合 | 兩側都不是英語的語言組合 |
| --- | --- | --- |
| 辭典 | 直接辭典包 | 發布版本中有直接辭典包時用它，否則用來源語言 → 英語和英語 → 目標語言 |
| Bergamot | 直接方向 | 來源語言 → 英語和英語 → 目標語言 |

簡體中文與繁體中文之間，以及目錄中沒有提供方向的語言組合，不受支援：沒有可下載的內容，段落交給其他層級。

辭典層級，或機器翻譯層級中的 Bergamot，因缺少辭典包或模型而使一封郵件的段落翻譯失敗時，第一輪翻譯結束後，郵件上方會出現一則提示。每封郵件只提示一次，只針對使用中的離線層級。提示依服務和語言組合各列一行，例如「辭典：日語 → 簡體中文，缺少 日語 → 英語、英語 → 簡體中文」，並帶三個控制項：

- 「前往設定下載」會開啟設定頁面，兩個離線清單都篩選到缺少的方向。
- 「這些語言不再提醒我」會關閉所列項目的提醒，依服務和語言組合分別記錄。關閉的項目列在設定頁面的「翻譯層級」下，「恢復提醒」會讓它們重新出現。
- 「關閉」會移除這則提示。

語言只靠推測判斷的段落、網路錯誤和不受支援的語言組合不計入。這些段落仍會得到其他層級的譯文；只有離線層級使用中時，它們會保持失敗。

在彈出面板和設定頁面中，選中的辭典或 Bergamot 缺少目前語言所需的資料時，會以紅色顯示「辭典（本機模型未下載）」或「Bergamot（本機模型未下載）」，層級清單下方有一行寫明缺少的方向，並附指向已篩選清單的「前往下載」連結。自動偵測時，以英語到目標語言的方向計算；目標語言為英語時，至少需要一個進入英語的方向。不受支援的語言組合會在這一行中寫明，但不標紅。這些標記會隨在其他頁面完成的安裝和刪除而更新。

## 介面語言

設定頁面「一般」分組中的「介面語言」有兩類選項：

- 跟隨 Thunderbird（預設）：擴充套件選用與 Thunderbird 介面語言最接近的受支援語言。選項文字會標出目前實際使用的語言，例如「跟隨 Thunderbird（Deutsch）」。
- 12 種受支援語言之一：擴充套件固定使用該語言，與 Thunderbird 的語言無關。

這項設定套用於彈出面板、設定頁面、郵件中的提示文字（「翻譯中…」「翻譯失敗，點擊重試」）、錯誤訊息、測試連線的結果，以及工具列按鈕的滑鼠懸停提示。已開啟的設定頁面和彈出面板會立即換成新語言。已翻譯過的郵件中，提示文字會在下一次繪製時換成新語言。

有兩處文字由 Thunderbird 直接從擴充套件的 manifest 讀取，一律跟隨 Thunderbird 的介面語言：

- 附加元件管理員中的擴充套件名稱與擴充套件說明；
- 「管理擴充套件快速鍵」中的快速鍵說明。

設定頁面在「介面語言」選項下方註明了這一點。

選擇「跟隨 Thunderbird」時，Thunderbird 的語言依下表對應到受支援語言：

| Thunderbird 的語言 | 擴充套件使用的介面語言 |
| --- | --- |
| `zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant` | 繁體中文 |
| 其他 `zh-*` | 簡體中文 |
| `pt-*` | 葡萄牙語（巴西） |
| `en-*`、`ja`、`ko`、`fr-*`、`de-*`、`es-*`、`ru`、`tr`、`vi` | 主要語言標籤相同的語言 |
| 其他語言 | 英語 |

目標語言下拉選單中的語言名稱依目前的介面語言顯示，括號內附上該語言的自稱，例如介面為中文時顯示「日語（日本語）」。傳給 AI 服務的提示詞一律使用英文語言名稱，因為模型對英文指令的遵循最穩定。

初次安裝時，目標語言依介面語言設定：日語介面的 Thunderbird 預設目標語言為日語，英語介面預設為英語。已儲存過的目標語言不會被覆蓋。

## 批次處理原理

一封郵件通常有十幾到幾十個段落。逐段請求時，每一段都要單獨傳送一次系統提示詞和翻譯指示，並各自佔用一次請求配額。批次處理把短時間內到達的段落合併成一次請求，這兩項開銷隨之改為每批計一次。

### 流程

1. 內容指令碼將每個待翻譯段落交給背景程式，一次請求涵蓋所有使用中的層級。
2. 背景程式對每個層級先查詢快取，命中則直接傳回。快取鍵由五部分組成：服務商、模型、來源語言與目標語言、一個「其他影響結果的設定」的雜湊值、段落文字的雜湊值。這個雜湊值包含 API 端點，Microsoft 翻譯還包含免費或金鑰模式；AI 服務還包含提示詞的種類和內容、思考開關和溫度；辭典和 Bergamot 還包含已安裝的辭典包或模型及其版本；精翻時再加上郵件。變更其中任何一項，都不會命中依舊設定得到的譯文。相同文字正在翻譯時，後到的請求共用同一個結果；請求失敗或逾時後，這個共用項目隨即移除，下一次請求重新送出。
3. 未命中的段落進入批次處理佇列，依「服務商 + 模型 + API 端點 + 來源語言 + 目標語言」分組，AI 服務再依提示詞、思考開關和溫度分組，Microsoft 翻譯再依免費或金鑰模式分組，精翻時再依郵件分組。同一組的段落在 50 毫秒的時間窗內累積；時間窗結束、段落數達到上限或字元數即將超過上限時，該組立即送出。單一段落超過字元上限時，先切成不超過上限的若干片。每片盡量容納完整的行，包括換行字元；下一行放不下時，這一片在它的最後一個換行處結束。單獨一行超過上限時，用 `Intl.Segmenter` 在句子之間切開；單句超過上限時依長度切開。段落開頭的空白不送出，之後補回譯文前面。各片像一般段落一樣翻譯，再依原順序接合：在換行處切開的片之間放回換行，其他片之間加一個空格（目標為中文或日語時不加）。例如一段 60 行、3900 字元的引用回覆，在預設 3000 字元的上限下，於換行處切成兩片送出，免去 60 次單行請求。快取以整個段落為單位。
4. 每個服務有自己的請求佇列，慢速的 AI 服務不會擋住辭典和機器翻譯。請求佇列限制本服務的同時請求數，遇到 408、429、5xx 或網路錯誤時以指數退避重試，最多重試設定中的次數；伺服器提供 `Retry-After` 時依其指定時間等待，最長等待 30 秒。401、400 這類錯誤直接回報，不重試。到了請求逾時仍未收到完整回應（包括回應本文）的請求會被取消。之後的處理依服務而定：

   | 服務 | 逾時時間 | 逾時之後 |
   | --- | --- | --- |
   | Google、Microsoft、DeepLX | 設定中的請求逾時（預設 60 秒） | 再嘗試一次；錯誤訊息寫出兩次嘗試合計的時間，例如「120 秒內沒有回應」 |
   | AI 服務，包括精翻的分析請求和「測試連線」 | 請求逾時；Ollama、LM Studio 以及任何開啟思考模式的模型為其三倍 | 不再嘗試：一次太慢的模型，再試一次同樣太慢，而且每次嘗試都要計費；錯誤訊息寫出實際等待的時間，例如「180 秒內沒有回應」 |

   每個逾時錯誤都附有調高逾時的提示。離線 Bergamot 引擎的翻譯在 2 分鐘內沒有回應，或載入模型在 5 分鐘內沒有完成時，引擎會終止 Worker；下一次請求啟動新的 Worker。連續兩次逾時後，離線翻譯在接下來的 1 分鐘內立即失敗，並以訊息說明原因，不再各自等到自己的逾時。
5. 結果寫入記憶體快取，並在 1 秒後合併寫入 `storage.local`。快取以最近最少使用（Least Recently Used，LRU）策略淘汰。

### 各類服務的合併方式

- 辭典和 Bergamot：整批在本機一次翻譯，每段各有自己的結果，缺少辭典包或模型的段落單獨失敗，不影響其他段落。自動偵測來源語言時，Bergamot 逐段偵測語言，同一語言的段落合在一起翻譯；太短、偵測器無法判斷的段落取本批中出現最多的語言，本批都無法判斷時以英語處理。
- Google：一次 POST 攜帶多個 `q` 參數，傳回的陣列與輸入一一對應。傳回格式異常時，這一批改為逐段請求；逐段請求同樣經過本服務的請求佇列，受同時請求數上限和重試約束，某一段失敗只影響這一段。
- Microsoft：請求本文本身就是陣列。
- DeepLX：端點一次只接受一段，批次內各段同時發出請求。
- AI 服務商：各段編號後放入同一則訊息，要求模型傳回長度相同的 JSON 陣列。剖析器依序嘗試 JSON 陣列（可包在程式碼區塊中或帶有前後說明文字，並會修正字串中未跳脫的換行與多餘的逗號）、帶編號的 `<seg>` 區塊、編號行、`%%` 分隔符號。全部失敗、筆數不符，或某段原文含字母或數字而譯文為空時，這一批改為逐段請求，使用者看到的結果不受影響。驗證失敗等非剖析錯誤不做逐段退回，以免同樣的錯誤重複 N 次。

### 開銷估算

設系統提示詞與指示共 $s$ 個 token，每段平均 $t$ 個 token，共 $N$ 段，批次大小為 $B$，每段編號與 JSON 引號的額外開銷為 $c$ 個 token。

逐段請求的輸入 token 總量為

$$
I_{\text{逐段}} = N(s + t).
$$

批次處理時共有 $\lceil N/B \rceil$ 次請求，輸入 token 總量為

$$
I_{\text{批次}} = \left\lceil \frac{N}{B} \right\rceil s + N(t + c).
$$

兩者之差為

$$
I_{\text{逐段}} - I_{\text{批次}} = \left(N - \left\lceil \frac{N}{B} \right\rceil\right) s - Nc.
$$

只要 $s$ 明顯大於 $c$，批次越大，節省越多。以 $s = 150$、$t = 60$、$c = 10$、$N = 20$、$B = 30$ 為例：

$$
I_{\text{逐段}} = 20 \times 210 = 4200, \qquad I_{\text{批次}} = 150 + 20 \times 70 = 1550.
$$

輸入 token 減少約 63%，請求次數從 20 次降為 1 次。兩種方式的輸出 token 大致相同，因為譯文本身的長度不變。請求次數的減少對免費端點同樣重要：Google 和 Microsoft 的免費端點依請求頻率限流，一封 20 段的郵件只佔用一次請求。

## 隱私

- API 金鑰只儲存在目前 Thunderbird 設定檔的 `storage.local` 中，只隨請求傳送到對應服務商的 API 端點。
- 內容指令碼在郵件頁面中執行，它從背景程式取得的設定既不包含金鑰，也不包含 API 端點，因為端點中可能帶有權杖。
- 錯誤訊息會遮蓋可能屬於機密的內容，遮蓋處顯示為 `***`。遮蓋的範圍如下：
  - 本服務的 API 金鑰或權杖，無論出現在錯誤訊息的哪個位置；
  - URL 路徑中形似權杖的段落，即 20 個以上同時含字母和數字的字元；
  - URL 中的使用者名稱和密碼；
  - 名稱含 key、token、auth、secret、sig、pass、credential 或 session 的 URL 參數。
- 郵件內文只傳送給使用中層級的服務。辭典和 Bergamot 在本機翻譯，不向外傳送任何文字。設定頁面和新手導覽頁面從本儲存庫的 GitHub Release 讀取辭典包列表，從 Mozilla 讀取 Bergamot 模型列表；辭典包和模型本身只在點擊「下載」時下載。這些請求都不攜帶郵件內文。擴充套件不收集統計資料，也不連線到其他網路位址。
- 譯文快取儲存在本機，可以在設定頁面中關閉或清除。
- 使用 Google、Microsoft、DeepLX 或線上 AI 服務時，郵件內容會離開本機。處理敏感郵件時，只使用辭典、Bergamot 以及 Ollama、LM Studio 這類本機模型，請求只會到達本機。

## 已知限制

- 譯文以純文字呈現。原文中的連結、粗體等行內格式在譯文中不會保留；雙語對照模式下原文仍完整可用，僅譯文模式下可以將滑鼠游標停在譯文上查看原文，或切回雙語對照。
- Google 和 Microsoft 的免費端點沒有公開文件，端點可能變動或遭到限流。微軟的權杖端點 `edge.microsoft.com/translate/auth` 已於 2026 年 7 月停用，擴充套件只使用直接連線的端點。
- 判斷段落是否已是目標語言時，中日韓等文字依字元類別判斷，拉丁字母與西里爾字母語言優先呼叫擴充套件 API 的 i18n.detectLanguage；該介面無法使用或結果不可靠時，只有英文能可靠判斷，其他拉丁字母語言的段落會照常送出翻譯。
- 內容指令碼透過 `messageDisplayScripts` 註冊，只對註冊之後開啟的郵件生效。擴充套件啟動時會嘗試為已開啟的郵件補充注入；補充注入失敗時，重新點選一次該郵件即可。
- 擴充套件本身產生的錯誤訊息已經翻譯。翻譯服務或 AI SDK 傳回的錯誤文字（例如 HTTP 401 回應的本文）會原樣顯示，通常是英文。
- 擴充套件名稱、附加元件管理員中的擴充套件說明和快速鍵說明跟隨 Thunderbird 的介面語言，不受「介面語言」選項控制。
- 精翻以內文文字的雜湊值識別郵件，因為內容指令碼取不到郵件 ID。內文完全相同的兩封郵件會共用譯文和分析結果。
- 前綴快取是否生效由服務商決定。Anthropic 只快取長度達到模型下限的前綴，較短的前綴按一般輸入計費。
- 思考模式開關依模型名稱比對。名稱不符合任何規則的新模型不會收到思考參數，需要在 `src/background/providers/thinking.ts` 的表中補充規則。
- 每個使用中的層級各自傳送請求。AI 層級和機器翻譯層級同時使用時，每封郵件都會向機器翻譯服務傳送請求，佔用 Google 和 Microsoft 免費端點的頻率限額。
- 辭典翻譯是逐詞對照，保持原文詞序，不做屈折變化。辭典包中沒有的詞保持原樣。
- 新手導覽的範例郵件是英文，目標語言為英語時改為德文。來源語言固定為這兩種以外的語言時，試譯仍會以該來源語言傳送這段英文。
- 新手導覽是目前分頁時按 Alt+A，會翻譯或還原範例郵件，此時試譯按鈕上的文字不會隨之改變。
- 預設是寫給模型的指令，方言和語體的遵循程度取決於模型；小模型較容易混用不同地區的用語。
- 自動偵測來源語言時，Bergamot 把少於 12 個字母、偵測器無法判斷的短段落歸入本批中出現最多的語言。與前後文語言不同的短段落因此會依前後文的語言翻譯。
- 簡繁中文靠一張 83 個常用字的對照表區分。段落中沒有表內的字時，對簡體和繁體兩種目標都視為已是目標語言。
- 辭典和 Bergamot 不做簡體中文與繁體中文之間的轉換。只使用其中一個層級時，另一種書寫體系的段落保持原文，沒有譯文。

- 批次處理分組與佇列；
- AI 輸出剖析與退回；
- 段落辨識，以及雙語對照 / 僅譯文的繪製與還原（jsdom 環境）；
- Google、Microsoft、DeepLX 的請求建構與回應剖析（模擬 fetch）；
- 每個 AI 預設組態的請求位址與驗證標頭，每個服務商的思考參數；
- 設定遷移：遷移到「已新增」狀態，遷移到三個層級和三套提示詞；
- 彈出面板和設定頁面的層級下拉選單，防止三個層級全部為空，移除保護；
- 翻譯層級：較低層級先送達後被取代、較高層級先送達後忽略較低層級、最高層級失敗時保留次高層級、所有層級都失敗、某層級不使用、最高層級命中快取時不請求較低層級；
- 提示詞的選擇與快取鍵；切換顯示方式時 AI 層級重新請求，其他層級只重新繪製；
- 來源語言：各服務在自動偵測和指定語言兩種情況下的請求參數，變更來源語言後不命中舊快取；
- 辭典：辭典包剖析、斷詞與片語比對、變化形式還原、經英語中轉、缺少辭典包的錯誤、附驗證的下載（使用記憶體中的 IndexedDB）；
- Bergamot 服務及其模型管理（模擬引擎模組），設定頁面的離線模型分組；
- 精翻：單次請求路徑、分析加分批路徑、分析失敗時降級、快取鍵包含郵件雜湊值、不同郵件不混批、同一封郵件的提示詞前綴逐字相同，以及 Anthropic 的快取標記；
- 新手導覽：只在首次安裝時開啟，步驟導覽、略過不需要的步驟、從上次的步驟繼續，每一步的儲存，推薦的辭典包和 Bergamot 方向及其下載，服務設定和測試連線，提示詞預設，經由內容指令碼模組的試譯；
- 提示詞預設：依目標語言篩選變體，與三套提示詞的組合，同一預設的取代，四個預設同時生效時的批次剖析；
- 在地化：各語言的鍵集合與替換參數和英文一致，manifest 引用的 `__MSG_*__` 都存在，Thunderbird 語言到受支援語言的對應，缺少的鍵退回英文，HTML 頁面和原始碼中沒有寫死的介面文字；
- 翻譯流程走正式路徑 `translateForPage()`：各層級使用獨立的請求佇列並行、請求逾時、單一段落失敗不影響同批其他段落、同一批中混有多種語言、超過單批上限的長段落。

`npm run e2e` 執行三個情境，每個情境各啟動一個使用暫時設定檔的無介面 Thunderbird，結束時只關閉本次啟動的程序：

| 情境 | 檢查內容 |
| --- | --- |
| HTML 郵件 | 段落辨識，每段依辭典 → Google → AI 的順序送達，暫時譯文與最終譯文，切換到僅譯文時只重新請求 AI 層級，還原後的 DOM 與原文一致，再次翻譯時直接使用已記住的譯文、不發請求，按 Alt+R 後即使全部已快取也重新請求三個層級並顯示新的 AI 譯文 |
| 純文字郵件 | 同上，郵件中含引用區塊 |
| 新手導覽的離線下載 | Thunderbird 不開啟郵件，直接開啟新手導覽；測試進入離線下載這一步，從模擬服務下載辭典包和 Bergamot 模型並檢查進度，確認兩者已儲存後再刪除 |

`npm run build:debug` 會產生除錯版 xpi：開啟郵件即開始翻譯，並將進度寫入主控台，用於在真實的 Thunderbird 中檢查整個流程。

## 翻譯介面文字

介面文字儲存在 `locales/<語言>.json` 中，每個檔案是一個「鍵 → 文字」的扁平物件。`locales/en.json` 是基準，其他檔案的鍵必須與它完全相同。檔案內容有三項約定：

- `$1` 到 `$9` 是替換參數，譯文中出現的編號必須與英文一致，位置可以依語序調整。
- `{{apiKey}}` 和 `{{to}}` 是字面標記，原樣保留。
- Google 翻譯、OpenAI、DeepLX 等產品名稱不翻譯。

`npm run build` 會將這些檔案轉換成 Thunderbird 讀取的 `dist/_locales/<語言>/messages.json`。擴充套件內建的 i18n 執行階段會在執行時載入同一批檔案，因此切換介面語言不需要重新啟動 Thunderbird。某個鍵在目前語言中缺少時，會退回英文。

新增一種語言的步驟：

1. 依 `locales/en.json` 的全部鍵新建 `locales/<代碼>.json`。
2. 在 `src/shared/locales.ts` 的 `SUPPORTED_LOCALES` 中加入該代碼，並補上它的自稱。
3. 執行 `npm run locales:check` 和 `npm test`。
