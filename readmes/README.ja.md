# Thunderbird Translate

[English](../README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | 日本語 | [한국어](README.ko.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Español](README.es.md) | [Português (Brasil)](README.pt-BR.md) | [Русский](README.ru.md) | [Türkçe](README.tr.md) | [Tiếng Việt](README.vi.md)

Thunderbird Translate は、閲覧中のメッセージ本文をメッセージペイン内でそのまま翻訳する Thunderbird 拡張機能です。訳文は原文の各段落の下に表示する（対訳表示）ことも、原文と置き換える（訳文のみ）こともできます。翻訳をオフにすると、メッセージは元の状態に正確に戻ります。翻訳は 3 つの段階で同時に行われます。オフラインの辞書、機械翻訳（Google 翻訳、Microsoft Translator、DeepLX、オフラインの Bergamot モデル）、AI サービス（OpenAI、Claude、Gemini、DeepSeek、Qwen など 22 のプロバイダー）です。最も早く届いた訳文が先に表示され、最も上位の段階の訳文がそれを置き換えます。既定の翻訳サービスは Google 翻訳（無料）で、インストール直後から使えます。

この文書は、Thunderbird 拡張機能を使ったことがない読者を想定しています。インストール、使い方、設定、仕組みの順に説明します。

![デモ：メールの翻訳、対訳と訳文のみの切り替え、翻訳先言語の変更](../docs/demo.gif)

## 機能

- 本文の翻訳: メッセージ本文から段落単位のコンテンツを検出します。対象は段落、リスト項目、表のセル、見出し、引用ブロック、テキストだけを含む div、プレーンテキストメールの空行で区切られた段落です。コード、すでに翻訳先の言語で書かれた段落、数値、URL だけのリンク、空白は翻訳しません。
- 2 つの表示方法: 対訳表示では、原文の下に左側へ薄い罫線を付けた訳文ブロックを挿入します。ダークテーマでも読めます。訳文のみの表示では、原文を訳文で置き換えます。原文はメモリーに保持され、翻訳をオフにすると元に戻ります。
- 即時反映: メッセージの翻訳中や翻訳後に表示方法や翻訳先の言語を変更すると、メッセージを開き直さずにページを再描画します。表示方法を変更すると、受信済みの辞書と機械翻訳の訳文を描画し直します。AI の段階には新しい表示方法のプロンプトで改めてリクエストし、同じ翻訳がキャッシュにあればキャッシュが応答します。
- 操作方法: メッセージヘッダーのツールバーにある「メッセージを翻訳」ボタンとそのポップアップ、ショートカットキー Alt+A（翻訳 / 原文を表示）と Alt+S（対訳表示 / 訳文のみを切り替え）を使います。
- メッセージを開いたときの翻訳（任意）: 翻訳先の言語以外のメッセージを、開いた時点で翻訳します。
- リクエストのバッチ処理: バックグラウンドスクリプトが段落を 50 ミリ秒間集め、1 回のリクエストにまとめます。サービスごとの同時実行数の制限、指数バックオフによる再試行、リクエストのタイムアウト、ローカルキャッシュも備えています。1 回のリクエストで送れる量より長い段落は、行単位の断片に分割します。1 回のリクエストより長い 1 行だけは、文の間で切ります。
- 3 つの翻訳の段階: 辞書、機械翻訳、AI 翻訳です。各段階にはそれぞれ 1 つのサービスを設定するか、未使用にします。各段落は、使用中のすべての段階に同時に送られます。下位の段階の訳文は、最上位の段階の訳文に置き換わるまで暫定訳として表示され、最上位の段階が失敗した場合はそのまま残ります。
- 翻訳サービス: オフラインの辞書、機械翻訳 4 種（Google 翻訳、Microsoft Translator、DeepLX、オフラインの Bergamot モデル）、AI プロバイダーのプリセット 22 種を利用できます。プリセットの 1 つは「カスタム OpenAI 互換」です。各段階の一覧には、追加したサービスだけが表示されます。
- 翻訳元の言語: 自動検出または固定の言語を選べます。選んだ言語はすべてのサービスに渡されます。
- AI の段階用の 3 つのプロンプト: 対訳表示用、訳文のみの表示用、精密翻訳用です。
- プロンプトのプリセット: 方言・地域の言葉づかい、難しい語に原語を併記、難しい語の解説、4 種類の文体を、3 つのプロンプトのどれにも追加できます。
- セットアップガイド: インストール後に開き、言語、表示方法、翻訳の段階、オフライン用のダウンロード、サービス、プロンプトを手順ごとに設定します。最後にサンプルメッセージを試しに翻訳します。
- 精密翻訳（AI の段階）: すべてのリクエストにメッセージ全体を文脈として付けるため、人名、用語、呼称が段落をまたいで統一されます。
- AI プロバイダーごとの思考モードのスイッチ。既定ではオフです。
- 12 言語のインターフェース: 表示言語は既定で Thunderbird に合わせ、設定ページで選択することもできます。

## インストール

### Releases からインストールする

1. このリポジトリの Releases ページから最新の `thunderbird-translate-<version>.xpi` をダウンロードします。
2. Thunderbird で ツール → アドオンとテーマ を開きます（右上の ≡ メニューからも開けます）。
3. 拡張機能一覧の上にある歯車アイコンをクリックし、「ファイルからアドオンをインストール...」を選んで、ダウンロードした xpi ファイルを選択し、確認します。

Thunderbird 128 以降が必要です。

### ソースからビルドする

Node.js 22 以降が必要です（開発には Node 24 と npm 11 を使用しています）。

```bash
npm ci
npm test
npm run build
```

`npm run build` は、esbuild でバックグラウンドスクリプト、コンテンツスクリプト、ポップアップ、設定ページ、セットアップガイド、Bergamot ワーカーを `dist/` にバンドルし、`locales/` のファイルから `dist/_locales/<language>/messages.json` を生成して、`dist/` を `web-ext-artifacts/thunderbird-translate-<version>.xpi` にパッケージ化します。パッケージ化には純粋な JavaScript で書かれた fflate ライブラリを使うため、システムの zip コマンドは不要です。バックグラウンドスクリプトは ES モジュールです。AI SDK は `dist/chunks/` の別チャンクに分かれ、AI の段階を使うときに読み込まれるため、Thunderbird は AI SDK なしで拡張機能を起動します。最初のビルドでは、固定バージョンの Bergamot エンジン（wasm）を Mozilla から `.cache/` にダウンロードします。詳しくは [docs/bergamot.md](../docs/bergamot.md) を参照してください。

開発中はパッケージ化せずに拡張機能を読み込めます。Thunderbird で ツール → 開発ツール → アドオンをデバッグ を開き、「一時的なアドオンを読み込む...」をクリックして `dist/manifest.json` を選択します。

## セットアップガイド

新規インストールの後、Thunderbird はセットアップガイドをタブで開きます。拡張機能や Thunderbird を更新したときには開きません。あとからポップアップの「セットアップガイド」リンクや、設定ページ上部の「セットアップガイド」ボタンで開くこともできます。

各手順では 1 つのことだけを決め、選んだ内容はすぐに保存されます。「戻る」「次へ」「この手順をスキップ」で手順を移動し、進行状況バーの下にある番号付きの一覧から任意の手順へ移動できます。「ガイドを終了」はいつでもタブを閉じます。次に開いたときは前回離れた手順から再開し、「完了」を押した後は最初の手順から始まります。

| 手順 | 内容 | 表示される条件 |
| --- | --- | --- |
| 1 言語 | 表示言語、翻訳元の言語（既定は「自動検出」）、翻訳先の言語 | 常に表示 |
| 2 表示方法 | 対訳表示または訳文のみ。サンプルメッセージを現在の訳文のスタイルで描画したプレビュー付き | 常に表示 |
| 3 翻訳の段階 | 辞書、機械翻訳、AI 翻訳の各段階の速度、品質、プライバシー、費用の比較。各段階のサービスまたは「未使用」。少なくとも 1 つの段階にサービスが必要 | 常に表示 |
| 4 オフライン翻訳 | 手順 1 の言語に必要な辞書パックと Bergamot の方向。サイズ、ライセンス、帰属表示付き。ダウンロードするものにチェックを入れ、「選択したものをダウンロード」で進行状況を表示しながらダウンロード | 辞書の段階を使用する場合、または機械翻訳の段階で Bergamot を使用する場合 |
| 5 オンライン機械翻訳 | 機械翻訳サービスの設定項目。Google 翻訳は入力不要、Microsoft Translator は「標準（無料）」と「自分のキーを使う（Azure Translator）」から選択、DeepLX はエンドポイントとアクセストークン。「接続テスト」 | 機械翻訳の段階で Google 翻訳、Microsoft Translator、DeepLX のいずれかを使用する場合 |
| 6 AI 翻訳 | AI プロバイダー、API キー、モデル、温度、思考モード、「接続テスト」、精密翻訳のスイッチ。思考モードと精密翻訳は翻訳を遅く、高くするという注意書き | AI の段階を使用する場合 |
| 7 プロンプト | 3 つのプロンプトとプリセット集（「プロンプトのプリセット」を参照） | AI の段階を使用する場合 |
| 8 完了 | 翻訳のしかた（ツールバーボタン、Alt+A、Alt+S）、「翻訳先の言語以外のメッセージを自動的に翻訳する」スイッチ、「サンプルメッセージを翻訳」ボタン | 常に表示 |

それまでの選択で不要になった手順は、取り消し線付きで一覧に残ります。「戻る」と「次へ」はその手順を飛ばします。たとえば手順 3 で AI の段階にサービスを選ぶと、手順 6 と 7 が再び有効になります。

翻訳元の言語が日本語、翻訳先の言語が簡体字中国語の場合、手順 4 は次のものを勧めます。

- 辞書: リリースに日本語 → 中国語の辞書パックがあればそのパックを、なければ日本語 → 英語と英語 → 中国語の 2 つのパックを勧めます。
- Bergamot: ja → en と en → zh-Hans の 2 つの方向を勧めます。すべての Bergamot モデルは片側が英語だからです。

翻訳元の言語が「自動検出」の場合、手順 4 は英語から翻訳する辞書パックと方向を勧めます。あわせて、受信する他の言語それぞれについて、その言語から英語への方向をインストールするよう注意書きを表示します。

手順 8 の「サンプルメッセージを翻訳」は、短いメール（翻訳元の言語が英語またはドイツ語ならその言語で、それ以外は英語で、翻訳先の言語が英語の場合はドイツ語で書かれたもの）をページ内に描画し、現在の設定で翻訳します。ページはコンテンツスクリプトの段落検出と描画のモジュールを使い、表示中のメッセージと同じ接続でバックグラウンドスクリプトにリクエストを送ります。そのため結果は実際のメッセージでの表示と同じになり、使用中の段階の暫定訳と最終訳も表示されます。

ガイドは設定ページと同じ部品を使います。対象は、サービスの設定項目と接続テスト、辞書と Bergamot の一覧、プリセット付きのプロンプト編集欄です。

## 使い方

メッセージを開くと、メッセージヘッダーのツールバーに「メッセージを翻訳」ボタンが表示されます。クリックすると、次の項目を含むポップアップが開きます。

- 「このメッセージを翻訳」: 翻訳を開始します。翻訳の実行中または訳文の表示中は、ボタンの表示が「原文を表示」に変わり、クリックすると原文に戻ります。
- 表示方法: 対訳表示と訳文のみを切り替えます。変更は表示中のメッセージにすぐ反映されます。
- 翻訳元の言語と翻訳先の言語: 翻訳元の言語の既定は「自動検出」です。どちらかを変更すると、翻訳中のメッセージは翻訳し直されます。2 つが同じ言語のときは注意書きが表示されます。
- 翻訳の段階: 段階ごとに 1 つの一覧があり（段階 1: 辞書、段階 2: 機械翻訳、段階 3: AI 翻訳）、それぞれ「未使用」とその段階に属する追加済みのサービスを含みます。少なくとも 1 つの段階にサービスが必要で、最後に残ったサービスを「未使用」にしようとすると、注意書きが表示されて変更は受け付けられません。一覧の下にある「+ 翻訳サービスを追加」は、設定ページの「翻訳サービス」セクションを開きます。
- 精密翻訳: AI の段階にサービスが設定されているときに表示されます。
- 翻訳先の言語以外のメッセージを自動的に翻訳する: オンにすると、本文が翻訳先の言語以外で書かれたメッセージを、開いた時点で翻訳します。
- セットアップガイド: セットアップガイドを新しいタブで開きます。

ポップアップには「翻訳済み: 8 / 12」のように進行状況が表示されます。まだ下位の段階の暫定訳のままの段落は別に数え、「翻訳済み: 7 / 9（うち暫定訳 2 段落）」のように表示します。ある段落ですべての段階が失敗すると、その段落の後ろに赤い「翻訳に失敗しました。クリックして再試行」が表示されます。マウスポインターを重ねるとエラー内容が表示され、クリックするとその段落を再試行します。

Alt+A は表示中のメッセージを翻訳するか、原文に戻します。Alt+S は対訳表示と訳文のみを切り替えます。どちらのショートカットキーも、アドオンマネージャーの歯車メニューにある「拡張機能のショートカットキーを管理」で変更できます。

訳文のみの表示では、訳文にマウスポインターを重ねると原文がツールチップに表示されます。

## 設定

アドオンマネージャーでこの拡張機能の「設定」ボタンをクリックすると、設定ページが開きます。設定は自動的に保存され、書き込みが終わると右上に「保存しました」と表示されます。保存に失敗した場合は、その位置にエラーが表示され、変更は次の保存で書き込まれます。セットアップガイドでは、手順を離れるときや完了するときに設定を保存できない場合、ガイドは閉じずにエラーを表示します。その横の「セットアップガイド」ボタンはセットアップガイドを開きます。

| セクション | 内容 |
| --- | --- |
| 一般 | 表示言語、翻訳元の言語、翻訳先の言語、既定の表示方法、「翻訳先の言語以外のメッセージを自動的に翻訳する」スイッチ |
| 翻訳の段階 | 各段階のサービスまたは「未使用」、精密翻訳 |
| 翻訳サービス | サービスは「追加済み」と「追加できるサービス」の 2 グループに分かれます。各サービスのエンドポイント、API キー、モデル、温度、思考モード。「接続テスト」「追加」「このサービスを使用」「削除」ボタン |
| 辞書 | 辞書の段階で使う言語ペアと、そのサイズ、ライセンス、帰属表示。ダウンロードと削除。辞書パックのリリースタグ（詳細設定） |
| オフライン翻訳モデル（Bergamot） | Bergamot モデルの各方向のペアと、そのサイズとバージョン。言語での絞り込み。ダウンロード、更新、キャンセル、削除。現在の言語に必要な方向 |
| プロンプト（AI の段階） | プリセット集。対訳表示用、訳文のみの表示用、精密翻訳用のプロンプト。それぞれに「組み込みのプロンプトに戻す」ボタン |
| リクエストのバッチ処理 | 収集時間、1 リクエストあたりの最大文字数と最大段落数、同時リクエスト数、再試行回数、リクエストのタイムアウト（既定は 60 秒。Ollama、LM Studio、思考モードではその 3 倍）、AI リクエストをまとめるかどうか |
| 訳文のスタイル | 左罫線、左破線、背景ハイライト、装飾なし。アクセントカラー、文字の不透明度、文字サイズの比率。リアルタイムのプレビュー |
| キャッシュ | キャッシュのオン / オフ、キャッシュする最大段落数、現在のエントリー数、キャッシュの消去 |

「接続テスト」は、入力欄に現在入っている値でテスト用の文を 1 つ送信します。成功すると訳文を表示し、失敗するとサービスが返したエラーを表示します。たとえば無効なキーや存在しないモデル名がエラーになります。

## サービスの追加と削除

翻訳サービスのセクションの左側にある一覧は、2 つのグループに分かれています。「追加済み」には、ポップアップと設定ページのサービス一覧に表示されるサービスが入り、それ以外のサービスは「追加できるサービス」に入ります。サービスを選ぶと、設定とボタンが表示されます。

- 追加していないサービスには「追加」ボタンがあります。API キー（DeepLX ではエンドポイント）を入力した場合も、そのサービスが追加されます。
- 追加済みのサービスには「このサービスを使用」と「削除」ボタンがあります。「このサービスを使用」を押すと、そのサービスが属する段階に設定されます。削除すると一覧からは外れますが、入力済みの設定は残るため、再び追加するとキーとモデルが元のままになります。
- いずれかの段階で使用しているサービスは削除できません。この場合は「削除」ボタンが無効になり、ボタンの下にそのサービスを使っている段階が表示されます。左側の一覧では、使用中のサービスに「使用中」のタグが付きます。

新規インストールでは、Google 翻訳と Microsoft Translator が追加済みの状態で始まります。辞書と Bergamot はデータのダウンロードが必要なため、手動で追加します。バージョン 1.1 以前の設定を読み込むときは、次の場合にサービスを追加済みとして扱います。

| サービス | 追加済みとして扱う条件 |
| --- | --- |
| Google 翻訳、Microsoft Translator | 常に追加済み |
| DeepLX | エンドポイントが入力されている |
| キーが必要な AI サービス | API キーが保存されている |
| Ollama、LM Studio、カスタム OpenAI 互換 | エンドポイント、モデル、温度のいずれかが変更されている |
| 各段階で使用しているサービス | 常に追加済み |

## 翻訳の段階

| 段階 | サービス | 得られる結果 |
| --- | --- | --- |
| 1 辞書 | 辞書（オフライン） | インストール済みの辞書パックによる単語ごとの対訳。すぐに得られ、ネットワークを使いません |
| 2 機械翻訳 | Google 翻訳、Microsoft Translator、DeepLX、Bergamot（オフライン） | 完全な訳文。1 から 2 秒以内に届きます |
| 3 AI 翻訳 | 22 の AI プロバイダー | 最も質の高い訳文。表示方法に対応するプロンプトに従います |

各段階には 1 つのサービスを設定するか「未使用」にし、少なくとも 1 つの段階にサービスを設定します。既定では段階 2 に Google 翻訳だけが設定されています。

各段落は、使用中のすべての段階に同時に送られます。各段階は通常のバッチ処理とキャッシュを通ります。メッセージに表示される内容は、応答があった段階のうち最も上位のものを表示する、という 1 つの規則で決まります。

| 状況 | メッセージに表示される内容 |
| --- | --- |
| 下位の段階が先に返した | その段階の訳文を、斜体で段階名のタグ（「辞書」「機械翻訳」）付きで表示します。ポインターを重ねると、応答を待っている段階が表示されます。上位の段階の訳文が届くと置き換わります |
| 使用中の最上位の段階が返した | その訳文をタグなしで最終訳として表示します。後から届いた下位の段階の結果は無視します |
| 最上位の段階が失敗した | 得られている最も良い下位の訳文を残し、「AI 翻訳に失敗しました」（または最上位の段階の名前）と表示します。ポインターを重ねると理由が表示され、クリックすると失敗した段階だけを再試行します |
| すべての段階が失敗した | 赤い「翻訳に失敗しました。クリックして再試行」を表示します |
| 最上位の段階の訳文がすでにキャッシュにある | その訳文をすぐに表示し、下位の段階にはリクエストしません |

表示方法を切り替えると、辞書と機械翻訳の訳文は手元の結果からそのまま描画し直します。AI の段階は表示方法ごとに別のプロンプトを使うため、新しい表示方法のプロンプトで改めてリクエストします。そのプロンプトでの訳文がキャッシュにあれば、リクエストは送りません。ポップアップは、最終訳を翻訳済みとして、下位の段階の訳文を暫定訳として数えます。

バージョン 1.3 以前で保存された設定は、1 回だけ次のように変換されます。

- 現在のサービスが AI サービスの場合は、段階 3 になります。競争翻訳がオンだった場合は、その高速サービスが段階 2 になります。
- 現在のサービスがそれ以外のサービスの場合は、段階 2 になります。
- 辞書の段階は「未使用」で始まります。

## 翻訳元の言語

翻訳元の言語は、既定では「自動検出」です。翻訳先の言語の一覧にある 20 言語のいずれかを指定することもできます。翻訳元の言語は、すべてのサービスに次のように渡されます。

| サービス | 自動検出 | 言語を指定 |
| --- | --- | --- |
| Google 翻訳 | `sl=auto` | `sl=<code>` |
| Microsoft Translator（無料とキー使用の両方） | `from` パラメーターなし | `from=<code>` |
| DeepLX | `source_lang: "auto"` | `source_lang: "<code>"`（中国語の各変種は `ZH`） |
| AI サービス | 「Detect the source language of … and translate it into …」 | 「Translate … from <language> into …」 |
| 辞書 | 段落ごとに検出 | 指定した言語 |
| Bergamot | 段落ごとに検出し、同じ言語の段落をまとめて翻訳します | 指定した言語 |

翻訳先の言語と判定された段落は、これまでどおり翻訳しません。翻訳先の言語が中国語の場合は、段落が翻訳先と同じ字体で書かれていることも条件です。翻訳先が繁体字中国語なら簡体字の段落は翻訳し、その逆も同様です。判定には、一方の字体にしかない文字（们/們、这/這、说/說 など）を使います。そうした文字を含まない段落はどちらの字体でも同じように読めるため、翻訳先の言語であるものとして翻訳しません。翻訳元の言語を指定している場合、言語を確実に判定できない段落はその言語として扱います。キャッシュキーとバッチには翻訳元の言語が含まれるため、翻訳元の言語を変更した後に古い設定での訳文が返ることはありません。

辞書と Bergamot は、簡体字中国語と繁体字中国語の間では翻訳しません。どちらも英語を経由するため、中国語の語順に英語の訳語を並べた結果になります。たとえば「我们明天开会」は「我們明天持有一個會議」になります。そのため、もう一方の字体で書かれた段落は、この 2 つの段階では「このサービスは簡体字中国語と繁体字中国語の間の翻訳には対応していません。」というエラーで失敗し、これらの段階の暫定訳は表示されません。この段落は機械翻訳と AI の段階が翻訳します。セットアップガイドは、この言語ペアには辞書パックを勧めません。

## プロンプト

AI の段階には 3 つのシステムプロンプトがあります。それぞれ設定ページで編集でき、「組み込みのプロンプトに戻す」で元に戻せます。設定には、変更したプロンプトだけが保存されます。変更していないプロンプトは空で保存され、組み込みのプロンプトを表します。入力欄には組み込みの本文が表示されます。そのため、拡張機能を更新すると、プロンプトを変更していない場合は改良された新しい組み込みのプロンプトが使われます。「組み込みのプロンプトに戻す」を押したときも、入力欄の本文を組み込みの本文と同じにしたときも、保存されるのは空です。以前のバージョンが保存した組み込みのプロンプトのコピーは、設定を読み込むときに識別して空に戻し、その形の設定をすぐに書き戻します。ユーザー自身が書いたプロンプトはそのまま残ります。`{{to}}` は翻訳先の言語の英語名に置き換えられます。翻訳元の言語とバッチの形式は、拡張機能がすべてのリクエストに自動的に追加します。

| プロンプト | 使われる場面 | 組み込みのプロンプトが求める内容 |
| --- | --- | --- |
| 対訳表示 | 対訳表示での AI の段階 | 読者は原文と見比べるため、原文に近い訳文を、文ごとに同じ順序で、何も加えず何も省かずに出力すること |
| 訳文のみの表示 | 訳文のみの表示での AI の段階 | 翻訳先の言語で書かれたメールとして読める自然な文章にすること。意味をすべて保ったまま、節の順序を入れ替えたり、文を分けたりまとめたりしてかまいません |
| 精密翻訳 | 精密翻訳がオンのときの AI の段階（両方の表示方法） | 用語集、要約、前後の段落を使い、用語、人名、呼称をメッセージ全体で統一すること |

キャッシュキーとバッチのキーには、プロンプトの種類とその本文のハッシュが含まれます。そのため、プロンプトを編集した後に古い本文で作られた訳文が返ることはありません。バージョン 1.3 以前で保存されたカスタムシステムプロンプトは、対訳表示と訳文のみの表示の両方のプロンプトになり、精密翻訳のプロンプトは組み込みの本文で始まります。

### プロンプトのプリセット

プリセット集は、設定ページの 3 つのプロンプトの上と、セットアップガイドの手順 7 にあります。使い方は次のとおりです。

1. プリセットを選びます。バリエーションがあるプリセットでは、バリエーションも選びます。
2. 「追加先のプロンプト」でプロンプトを 1 つ選びます。
3. 「プリセットを適用」をクリックします。

「例」の行には、原文の 1 文と、選んだプリセットで期待される訳文が表示されます。

| プリセット | バリエーション | プロンプトに追加される規則 |
| --- | --- | --- |
| 方言・地域の言葉づかい | 翻訳先の言語ごとに異なります。簡体字中国語では広東語（香港）と四川語、繁体字中国語では広東語（香港）と台湾の言葉づかい、英語ではイギリス英語とアメリカ英語、ポルトガル語ではブラジルポルトガル語とヨーロッパポルトガル語、スペイン語ではメキシコのスペイン語とスペインのスペイン語、フランス語ではカナダフランス語（ケベック）、ドイツ語ではスイス標準ドイツ語 | その変種の綴り、語彙、呼びかけ方を使って書く |
| 難しい語に原語を併記 | なし | 通常どおり翻訳し、難しい語や専門用語の訳語の後に原語を括弧で付ける。同じ語に付けるのは段落ごとに 1 回で、例は「デューデリジェンス（due diligence）」 |
| 難しい語の解説 | なし | 段落を翻訳した後、その段落の難しい語の解説を、翻訳先の言語で同じ段落の末尾に 1 つの括弧にまとめて付ける: 〔注: 用語: 解説; …〕 |
| 文体 | フォーマルなビジネス文、くだけた話し言葉、やさしい言葉（学習者向け）、文学的 | その文体を使い、意味をすべて保つ |

バリエーションの一覧は翻訳先の言語に従います。日本語のように地域変種のない翻訳先の言語では、「方言・地域の言葉づかい」のプリセットは表示されません。

プリセットは、プロンプトの末尾に空行を挟んで、英語で書かれた規則のまとまりを追加します。このまとまりは `Style (this rule takes precedence over the rules above):` のような見出しで始まります。そのため、「説明を加えない」のような組み込みのプロンプトの一般的な規則より、このまとまりが優先されます。

同じプリセットをもう一度適用すると、そのまとまりが置き換わります。異なるプリセットは重ねて追加されます。プロンプト欄には組み合わせたテキストが表示され、そのまま編集できます。「組み込みのプロンプトに戻す」で追加分はすべて消えます。

プリセットを使っても、1 段落につき 1 つの訳文という形は変わりません。難しい語の解説はその段落の訳文の中に入り、規則のまとまりは解説を別の段落や配列要素として返すことを禁じています。そのため、バッチの応答は引き続き、段落ごとにちょうど 1 要素の JSON 配列（または番号付きの区切り）になります。テストでは 4 つのプリセットすべてを 1 つのプロンプトに適用し、モックのモデルが返す両方の形式の応答を解析します。

## 精密翻訳

精密翻訳は AI の段階に適用され、すべての AI リクエストにメッセージ全体を文脈として付けます。ポップアップまたは設定ページの「翻訳の段階」セクションでオンにします。翻訳を開始すると、コンテンツスクリプトは検出した段落を順に連結してメッセージ本文のプレーンテキストを作り（20,000 文字を超える分は切り捨て、続きがあることを注記します）、バックグラウンドスクリプトに 1 回だけ登録します。メッセージは、本文全体のハッシュで識別します。切り捨ては、文脈として送るテキストにだけ適用されます。

処理の流れは、翻訳する段落の量によって変わります。

1. 1 回のリクエストに収まる場合（「1 リクエストあたりの最大文字数」と「1 リクエストあたりの最大段落数」の範囲内）は、1 回のリクエストですべての段落を翻訳します。このリクエスト自体がメッセージ全体を含んでいます。
2. 収まらない場合は、先に 1 回追加のリクエストでメッセージ全体を分析します。返される内容は、2 から 3 文の要約、人名、製品名などの固有名詞とその統一訳語をまとめた用語集、文体と呼称の指針です。この応答を解析できない場合は、分析結果なしで翻訳を続け、そのメッセージを再び分析することはありません。リクエストが失敗した場合（ネットワークエラー、タイムアウト、HTTP エラー）も分析結果なしで翻訳を続けますが、そのメッセージを次に翻訳するときに改めて分析をリクエストします。
3. 以降のリクエストは、すべて同じ接頭辞で始まります。システムプロンプト、分析結果、そして（約 8,000 文字以下のメッセージでは）全文です。接頭辞の後にバッチの段落が続き、各段落には前後 1 つずつの段落が、翻訳しない参考として付きます。

1 通のメッセージのすべてのリクエストで、接頭辞は 1 文字も違わず同一です。繰り返されるプロンプトの接頭辞をキャッシュするプロバイダーでは、この部分をキャッシュから処理できます。Anthropic では、接頭辞に `cacheControl: { type: "ephemeral" }` を付けます。分析結果も訳文と同様にキャッシュされ、キーはプロバイダー、モデル、翻訳元と翻訳先の言語、リクエスト設定（エンドポイント、プロンプト、思考モードのスイッチ、温度）のハッシュ、メッセージ本文のハッシュで決まります。同じメッセージの複数のバッチは、同じ分析リクエストの完了を待ちます。

精密翻訳の訳文は、メッセージのハッシュを含むキーでキャッシュされ、バッチは異なるメッセージの段落を混ぜません。そのため、同じ文が別のメッセージに現れたときは、そのメッセージを文脈として翻訳し直します。分析リクエストと長いプロンプトのため、精密翻訳は通常の翻訳よりコストがかかります。

## 辞書翻訳

辞書サービスは、Thunderbird プロファイルに保存した辞書パックを使って単語ごとに翻訳します。パックをインストールした後はネットワークを使わず、数ミリ秒で応答するため、機械翻訳と AI の段階が応答するまでの間を埋めます。結果は単語ごとの対訳で、語順は原文のままで、文法上の変形は行いません。

### 辞書パック

辞書パックは、このリポジトリの GitHub リリースのアセットとして公開されています。既定ではリリース `dicts-v1` を使います。リリースタグは、「辞書」セクションの「辞書パックのリリースタグ（詳細設定）」で変更できます。翻訳の方向ごとに 1 つのファイル `dict-<src>-<tgt>.tsv.gz` があり、中身は gzip で圧縮した UTF-8 のテキストです。

```text
#dict	<src>	<tgt>	<packVersion>	<sourceName>	<license>
w	<key>	<translation>
f	<key>	<lemmaKey>
```

各行の意味は次のとおりです。

- 1 行目はパック自体を説明します。翻訳元の言語、翻訳先の言語、バージョン、出典、ライセンスです。
- `w` で始まる行は見出し語です。
- `f` で始まる行は、活用形をその原形のキーに対応付けます。たとえば `went` を `go` に対応付けます。

キーは NFC で正規化し、翻訳元の言語の規則で小文字に変換し、前後の空白を取り除いたものです。複数の単語からなる句もキーにできます。インデックス `dict-index.json` には、各パックのサイズ、見出し語と活用形の数、SHA-256 チェックサム、出典、ライセンス、帰属表示が記載されています。辞書パックは、英語、簡体字中国語、繁体字中国語、日本語、韓国語、フランス語、ドイツ語、スペイン語、ポルトガル語、ロシア語、トルコ語、ベトナム語に対応しています。パックの作り方は [docs/dictionary-packs.md](../docs/dictionary-packs.md) で説明しています。

設定ページの「辞書」セクションはインデックスを読み込み、各パックをサイズ、ライセンス、帰属表示とともに一覧表示します。「ダウンロード」はファイルを進行状況と「キャンセル」ボタンを表示しながら取得し、SHA-256 チェックサムとヘッダーを検証してから、拡張機能の IndexedDB データベース `tt-dictionary` に保存します。「削除」はパックを削除します。インデックスを読み込めない場合は、セクションにその理由が表示されます。その場合も、インストール済みのパックは削除できます。インデックスの読み込みは、30 秒間応答がなければ失敗します。ダウンロードは、30 秒間データを受信しなければエラーで停止します。データを受信し続けている遅いダウンロードには時間制限がありません。

### 翻訳の手順

1. 翻訳元の言語を決めます。指定した言語を使い、自動検出の場合は段落の言語（文字種、ブラウザーの言語検出、英語のストップワード）を使います。
2. `Intl.Segmenter` で段落を単語に分割します。各単語の位置で、見出し語がある最長の句（最大 3 単語）を優先し、なければ単語 1 つを引きます。見出し語がない単語は原形から引き直し、それでも見つからなければそのまま残します。句読点と数字はそのまま残します。
3. 翻訳先の言語が中国語または日本語の場合は単語を空白なしでつなぎ、それ以外の言語では空白で区切ります。
4. 英語以外の 2 つの言語の間では、英語を経由します。フランス語からドイツ語へは、フランス語 → 英語と英語 → ドイツ語の 2 つのパックを使います。
5. 必要なパックがない場合、エラーメッセージに言語ペアを示し、「辞書」セクションを案内します。

バックグラウンドスクリプトは、パックを初めて使うときに IndexedDB からメモリーに読み込み、辞書による翻訳が 5 分間行われなければメモリーを解放します。

### データの出典

辞書パックは次の 2 つのデータから作られています。

- Wiktionary。wiktextract で抽出され、kaikki.org が公開しています（CC BY-SA 4.0、© Wiktionary の貢献者）。
- skywind3000 による ECDICT（MIT ライセンス）。

各パックはインデックスに自身の出典とライセンスを記載し、設定ページはそれをパックの横に表示します。

## オフライン翻訳（Bergamot）

Bergamot サービスは、Firefox Translations のエンジンと翻訳モデルを使ってこのコンピューター上で翻訳します。エンジンとモデルは Mozilla が MPL-2.0 で公開しています。エンジンは拡張機能に同梱されています。翻訳の方向ごとのモデルは Mozilla から 1 回だけダウンロードされ（13 から 48 MB）、拡張機能の IndexedDB に保存されます。読み込んだ方向は約 200 MB のメモリーを使い、5 分間使われなければ解放されます。すべてのモデルは片側が英語のため、日本語から中国語への翻訳には日本語 → 英語と英語 → 中国語を使います。

設定ページの「オフライン翻訳モデル（Bergamot）」セクションには、58 言語の間の 114 の方向のペアが、サイズとバージョンとともに一覧表示され、言語で絞り込めます。このセクションは、現在の翻訳元と翻訳先の言語に必要な方向を示し、それらを先頭に並べます。ダウンロード中は進行状況が表示され、キャンセルできます。モデルの一覧の読み込みは、30 秒間応答がなければ失敗します。ダウンロードは、30 秒間データを受信しなければエラーで停止します。インストール済みのペアに Mozilla が新しいバージョンを提供している場合は「更新」が表示されます。現在の言語に必要なペアを削除するときは、確認を求めます。インストール、翻訳、削除は、エンジンが動作するバックグラウンドスクリプトで実行されます。モデルの選択、検証、保存、エンジンについては [docs/bergamot.md](../docs/bergamot.md) で説明しています。

## 表示言語

「一般」セクションの「表示言語」には 2 種類の値があります。

- 「Thunderbird に合わせる」（既定）: Thunderbird 自体の表示言語に最も近い対応言語を使います。選択肢のラベルには、現在選ばれている言語が「Thunderbird に合わせる（Deutsch）」のように表示されます。
- 12 の対応言語のいずれか: Thunderbird の言語にかかわらず、その言語を使います。

この設定は、ポップアップ、設定ページ、メッセージ内のラベル（「翻訳中…」「翻訳に失敗しました。クリックして再試行」）、エラーメッセージ、接続テストの結果、ツールバーボタンのツールチップに適用されます。開いている設定ページやポップアップの文字列はすぐに切り替わります。すでに翻訳済みのメッセージ内のラベルは、次に描画されるときに切り替わります。

一部の文字列は Thunderbird 自体が拡張機能のマニフェストから読み込むため、常に Thunderbird の表示言語に従います。対象は、アドオンマネージャーに表示される拡張機能の名前と説明、「拡張機能のショートカットキーを管理」に表示されるショートカットの説明です。設定ページでは、この選択肢の下にこのことを記載しています。

「Thunderbird に合わせる」は、Thunderbird の言語を次のように対応付けます。

| Thunderbird の言語 | 使用される表示言語 |
| --- | --- |
| `zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant` | 繁体字中国語 |
| その他の `zh-*` | 簡体字中国語 |
| `pt-*` | ポルトガル語（ブラジル） |
| `en-*`、`ja`、`ko`、`fr-*`、`de-*`、`es-*`、`ru`、`tr`、`vi` | 主言語サブタグが同じ言語 |
| その他の言語 | 英語 |

翻訳先の言語の一覧では、各言語の名前を表示言語で示し、その後にその言語自身での名前を続けます。たとえば「ドイツ語（Deutsch）」のように表示されます。AI サービスに送るプロンプトでは、常に英語の言語名を使います。モデルは英語の指示に最も確実に従うためです。

初回インストール時には、表示言語に基づいて翻訳先の言語を設定します。日本語の Thunderbird では翻訳先の言語が日本語に、英語の Thunderbird では英語になります。すでに設定されている翻訳先の言語は上書きしません。

### 思考モード

## バッチ処理の仕組み

1 通のメッセージには、通常 10 から数十の段落があります。段落ごとに 1 回のリクエストを送ると、各段落がシステムプロンプトと指示のコピーをそれぞれ持ち、各段落がレート制限のリクエスト 1 回分を消費します。バッチ処理では、近いタイミングで届いた段落を 1 回のリクエストにまとめます。これにより、この 2 つのコストは段落ごとではなくバッチごとにかかるようになります。

### 処理の流れ

1. コンテンツスクリプトが、翻訳対象のすべての段落をバックグラウンドスクリプトに渡します。使用中のすべての段階に対して 1 回で渡します。
2. バックグラウンドスクリプトは段階ごとにまずキャッシュを検索し、ヒットした場合はそのまま応答します。キャッシュキーは、プロバイダー、モデル、翻訳元と翻訳先の言語、結果を左右するその他の設定をまとめた 1 つのハッシュ、段落テキストのハッシュで構成されます。その他の設定のハッシュには、エンドポイント、Microsoft Translator では無料モードかキー使用モードか、AI サービスではプロンプトの種類とその本文・思考モードのスイッチ・温度、辞書と Bergamot ではインストール済みのパックまたはモデルとそのバージョン、精密翻訳ではメッセージが含まれます。これらのどれを変更しても、古い設定で得た訳文が返ることはありません。同じテキストがすでに翻訳中の場合、後続のリクエストは同じ結果を共有します。リクエストが失敗またはタイムアウトした場合、この共有は破棄され、次のリクエストが新たに開始されます。
3. キャッシュにない段落はバッチキューに入り、プロバイダー + モデル + エンドポイント + 翻訳元の言語 + 翻訳先の言語の組み合わせごとに、AI サービスではさらにプロンプト・思考モードのスイッチ・温度ごとに、Microsoft Translator ではさらに無料モードかキー使用モードかごとに、精密翻訳ではさらにメッセージごとにグループ化されます。1 つのグループの段落は 50 ミリ秒間蓄積されます。グループが送信されるのは、収集時間が終わったとき、段落数の上限に達したとき、または次の段落を加えると文字数の上限を超えるときです。文字数の上限より長い段落は、収まる大きさの断片に分割されます。1 つの断片には、収まる限り、行を改行も含めて丸ごと入れます。次の行が収まらないときは、断片の最後の改行でその断片を終えます。上限より長い 1 行は文の間で切り（`Intl.Segmenter`）、上限より長い文は長さで切ります。段落の先頭の空白は送信せず、訳文の前に戻します。断片は段落と同じように翻訳され、元の順序で連結されます。改行で切った箇所は改行で、それ以外の箇所は空白でつなぎます（中国語と日本語では空白を入れません）。たとえば 60 行、3,900 文字の引用返信は、既定の上限 3,000 文字では改行で切った 2 つの断片として送信されます。1 行ずつ 60 回リクエストすることはありません。キャッシュには段落全体が保存されます。
4. サービスごとに専用のリクエストキューがあるため、遅い AI サービスが辞書や機械翻訳を止めることはありません。キューはそのサービスの同時実行数を制限し、408、429、5xx、ネットワークエラーを、設定の再試行回数まで指数バックオフで再試行します。サーバーが `Retry-After` を返した場合は、その時間だけ待機します（上限は 30 秒）。401 や 400 などのエラーは再試行せずに報告します。リクエストのタイムアウトが過ぎても、本文を含む応答が届いていないリクエストは取り消されます。その後の動作はサービスによって異なります。

   | サービス | タイムアウト | タイムアウトの後 |
   | --- | --- | --- |
   | Google、Microsoft、DeepLX | 設定のリクエストのタイムアウト（既定は 60 秒） | もう 1 回試行します。エラーには 2 回の試行を合わせた時間が示されます。例は「120 秒以内に応答がありません」 |
   | AI サービス（精密翻訳の分析と「接続テスト」を含む） | リクエストのタイムアウト。Ollama、LM Studio、思考モードをオンにしたモデルではその 3 倍 | 再試行しません。一度遅すぎたモデルは次も遅すぎ、試行のたびに課金されるためです。エラーには待った時間が示されます。例は「180 秒以内に応答がありません」 |

   タイムアウトのエラーには、どれもタイムアウトを延ばすよう案内が付きます。オフラインの Bergamot エンジンは、翻訳が 2 分以内に、またはモデルの読み込みが 5 分以内に応答しない場合にワーカーを終了し、次のリクエストで新しいワーカーを起動します。タイムアウトが 2 回続くと、その後 1 分間、オフライン翻訳はそれぞれのタイムアウトを待たずにすぐ失敗し、その旨をメッセージで示します。
5. 結果はメモリー上のキャッシュに入り、1 秒後にまとめて 1 回で `storage.local` に書き込まれます。キャッシュは最も長く使われていない（LRU）エントリーから削除します。

### 各サービスでの段落のまとめ方

- 辞書と Bergamot: バッチ全体をこのコンピューター上で 1 回の呼び出しで翻訳し、段落ごとに結果を返します。辞書パックやモデルがない言語の段落は、その段落だけが失敗します。自動検出では、Bergamot は段落ごとに言語を検出し、同じ言語の段落をまとめて翻訳します。検出器が判定するには短すぎる段落は、バッチ内で最も多い言語を使い、判定できなければ英語として扱います。
- Google: 複数の `q` パラメーターを含む 1 回の POST を送ります。返される配列は入力と 1 対 1 で対応します。応答の形式が想定と異なる場合は、そのバッチを 1 段落ずつのリクエストで送り直します。送り直しも同じリクエストキューを通るため、同時実行数の制限と再試行が適用され、失敗した場合は該当の段落だけに影響します。
- Microsoft: リクエスト本文そのものが配列です。
- DeepLX: エンドポイントは 1 回のリクエストで 1 段落しか受け付けないため、バッチ内の段落を並行してリクエストします。
- AI プロバイダー: 段落に番号を付けて 1 つのメッセージにまとめ、同じ長さの JSON 配列を返すようモデルに指示します。パーサーは次の順に解析を試みます。JSON 配列（コードブロック内にある場合や説明文に囲まれている場合も含みます。文字列内の改行や末尾のカンマは修復します）、番号付きの `<seg>` ブロック、番号付きの行、`%%` 区切り文字です。すべて失敗した場合、件数が一致しない場合、または原文に文字か数字があるのに訳文が空の場合は、そのバッチを 1 段落ずつのリクエストで送り直します。ユーザーから見た結果は同じです。認証エラーなど解析エラー以外のエラーではこのフォールバックを行わないため、同じエラーが N 回繰り返されることはありません。

### コストの見積もり

システムプロンプトと指示のトークン数を $s$、1 段落あたりの平均トークン数を $t$、段落の総数を $N$、バッチサイズを $B$、番号付けと JSON の引用符のために段落ごとに増えるトークン数を $c$ とします。

段落ごとに 1 回のリクエストを送る場合、入力トークンの合計は次のとおりです。

$$
I_{\text{single}} = N(s + t).
$$

バッチ処理ではリクエスト数が $\lceil N/B \rceil$ 回になり、入力トークンの合計は次のとおりです。

$$
I_{\text{batch}} = \left\lceil \frac{N}{B} \right\rceil s + N(t + c).
$$

両者の差は次のとおりです。

$$
I_{\text{single}} - I_{\text{batch}} = \left(N - \left\lceil \frac{N}{B} \right\rceil\right) s - Nc.
$$

$s$ が $c$ より十分に大きい限り、バッチが大きいほど節約量が増えます。$s = 150$、$t = 60$、$c = 10$、$N = 20$、$B = 30$ の場合は次のようになります。

$$
I_{\text{single}} = 20 \times 210 = 4200, \qquad I_{\text{batch}} = 150 + 20 \times 70 = 1550.
$$

入力トークンは約 63% 減り、リクエスト数は 20 回から 1 回に減ります。訳文の長さは変わらないため、出力トークンはどちらの場合もほぼ同じです。リクエスト数の削減は無料エンドポイントでも効果があります。Google と Microsoft は無料エンドポイントをリクエストの頻度で制限しており、20 段落のメッセージが 1 回のリクエストで済みます。

## プライバシー

- API キーは現在の Thunderbird プロファイルの `storage.local` にのみ保存され、対応するプロバイダーのエンドポイントへのリクエストでのみ送信されます。
- コンテンツスクリプトはメッセージページ内で動作します。コンテンツスクリプトがバックグラウンドスクリプトから受け取る設定には、キーもエンドポイントも含まれません。エンドポイントにトークンが含まれていることがあるためです。
- エラーメッセージでは、機密情報の可能性があるものを伏せます。伏せた部分は `***` と表示されます。対象は次のとおりです。
  - サービスの API キーまたはトークン（エラーメッセージのどこに現れても）
  - URL のパスのうち、トークンに見える部分（英字と数字を含む 20 文字以上）
  - URL 内のユーザー名とパスワード
  - 名前に key、token、auth、secret、sig、pass、credential、session のいずれかを含む URL パラメーター
- メッセージのテキストは、使用中の段階のサービスにのみ送信されます。辞書と Bergamot はこのコンピューター上で翻訳し、テキストをどこにも送信しません。設定ページとセットアップガイドは、辞書パックの一覧をこのリポジトリの GitHub リリースから、Bergamot のモデルの一覧を Mozilla から読み込みます。パックとモデルの本体は、「ダウンロード」をクリックしたときにだけダウンロードされます。これらのリクエストにメッセージのテキストは含まれません。拡張機能は統計情報を収集せず、それ以外のネットワークアドレスには接続しません。
- 翻訳キャッシュはローカルに保存され、設定ページでオフにしたり消去したりできます。
- Google、Microsoft、DeepLX、オンラインの AI サービスを使うと、メッセージのテキストはコンピューターの外に出ます。機密性の高いメールには、辞書、Bergamot、Ollama や LM Studio などのローカルの AI モデルだけを使うと、すべてのリクエストが自分のマシン内で完結します。

## 既知の制限事項

- 訳文はプレーンテキストです。原文のリンク、太字などのインライン書式は訳文に引き継がれません。対訳表示では原文をそのまま操作できます。訳文のみの表示では、マウスポインターを重ねて原文を確認するか、対訳表示に切り替えてください。
- Google と Microsoft の無料エンドポイントは公式に文書化されておらず、仕様変更やレート制限の対象になることがあります。Microsoft は 2026 年 7 月にトークンエンドポイント `edge.microsoft.com/translate/auth` を廃止しました。拡張機能は直接エンドポイントだけを使います。
- 段落がすでに翻訳先の言語で書かれているかを判定する際、中国語、日本語、韓国語などの文字体系は文字種で判定し、ラテン文字・キリル文字の言語はまず拡張機能 API の `i18n.detectLanguage` を使います。この API が使えない場合や結果の信頼性が低い場合、確実に判定できるのは英語だけです。その他のラテン文字の言語の段落は、通常どおり翻訳に送られます。
- コンテンツスクリプトは `messageDisplayScripts` で登録され、登録後に開いたメッセージにのみ適用されます。拡張機能は起動時に、すでに開いているメッセージへの挿入を試みます。失敗した場合は、メッセージを選択し直せば適用されます。
- 拡張機能自身が生成するエラーメッセージは翻訳されます。翻訳サービスや AI SDK が返すエラー文（HTTP 401 応答の本文など）は受け取ったまま表示され、通常は英語です。
- 拡張機能の名前、アドオンマネージャーに表示される説明、ショートカットの説明は、表示言語の設定ではなく Thunderbird の表示言語に従います。
- 精密翻訳は、コンテンツスクリプトがメッセージ ID を取得できないため、本文テキストのハッシュでメッセージを識別します。本文が同一の 2 通のメッセージは、訳文と分析結果を共有します。
- プロンプトのキャッシュが効くかどうかはプロバイダー次第です。Anthropic がキャッシュするのは、モデルごとに決まる最小の長さを超える接頭辞だけで、それより短い接頭辞は通常どおり送信され、課金されます。
- 思考のスイッチはモデル名の照合で動作します。どのパターンにも一致しない新しいモデルには、`src/background/providers/thinking.ts` の表に規則を追加するまで、思考パラメーターを送りません。
- 使用中の各段階は、それぞれ独自にリクエストを送ります。AI の段階と機械翻訳の段階を両方使う場合、各メッセージで機械翻訳サービスへのリクエストも発生し、無料の Google と Microsoft のエンドポイントのレート制限を消費します。
- 辞書翻訳は単語ごとの対訳です。原文の語順を保ち、語形を変化させません。パックにない単語は翻訳されずに残ります。
- セットアップガイドのサンプルメッセージは英語で、翻訳先の言語が英語の場合はドイツ語です。翻訳元の言語をこの 2 つ以外の言語に固定している場合も、試しの翻訳はその翻訳元の言語を指定して英語の本文を送ります。
- セットアップガイドがアクティブなタブのときに Alt+A を押すと、サンプルメッセージが翻訳されるか原文に戻ります。このとき試しの翻訳のボタンの表示は切り替わりません。
- プリセットはモデルへの指示です。方言や文体がどこまで守られるかはモデルによって決まり、小さなモデルほど地域変種を混ぜやすくなります。
- 自動検出では、Bergamot は検出器が判定できない短い段落（12 文字未満）を、そのバッチで最も多い言語として扱います。そのため、前後の段落と言語が違う短い段落は、前後の言語として翻訳されます。
- 簡体字中国語と繁体字中国語は、よく使われる 83 文字の対応表で区別します。表の文字を 1 つも含まない段落は、どちらの中国語の翻訳先でも、すでに翻訳先の言語であるものとして扱います。
- 辞書と Bergamot は、簡体字中国語と繁体字中国語の間の変換を行いません。使用中の段階がこのどちらか 1 つだけの場合、もう一方の字体で書かれた段落は翻訳されずに残ります。

## インターフェースの翻訳

インターフェースの文字列は `locales/<language>.json` にあり、言語ごとにキー → 文字列のフラットなオブジェクトを 1 つ持ちます。`locales/en.json` が基準で、他のすべてのファイルはまったく同じキーを持ちます。`$1` から `$9` は置換文字列で、各訳文に英語と同じ番号で含める必要があります。`{{apiKey}}` と `{{to}}` はそのまま残すリテラルのトークンです。Google 翻訳、OpenAI、DeepLX などの製品名は翻訳しません。

`npm run build` は、これらのファイルを Thunderbird が読み込む形式の `dist/_locales/<language>/messages.json` に変換します。拡張機能独自の i18n ランタイムが実行時に同じファイルを読み込むため、Thunderbird を再起動せずに表示言語を変更できます。欠けているキーは英語にフォールバックします。

言語を追加するには、すべてのキーを含む `locales/<code>.json` を作成し、`src/shared/locales.ts` の `SUPPORTED_LOCALES` にそのコードと言語自身での名前を追加して、`npm run locales:check` と `npm test` を実行します。
